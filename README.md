# DealerDesk 4S · 0.2.0 多门店版

中文前端 + FastAPI后端 + SQLite数据库。面向门店销售、新车库存、维修工单、保单与收支流水；提供部门权限、审核留痕、经营看板、规则复核和可选DeepSeek日报。

本次新增：**多门店隔离与汇总、员工账号门店授权、改进意见收集、DeepSeek受限改码、Git候选分支、飞书应用机器人审批、本地发布与代码回滚。**

这是需要业务验收的试运行系统，不是完整ERP、法定会计账簿或零维护的自主开发平台。数据库迁移、核心后端/账务/权限开发与故障处理仍需有人负责。

## 先运行，不必先接飞书

Windows安装Python 3.11–3.13，解压后在目录终端运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Demo
```

macOS/Linux：

```bash
bash start.sh --demo
```

首次自己设置管理员密码，账号admin。浏览器打开 `http://127.0.0.1:8000`。以后启动去掉Demo参数。正式数据使用独立空数据库，不与演示数据混用。只装基础依赖即可使用多门店、账号、人工录入和意见收集；不需要Node.js或Docker。

启动脚本现在运行可信Supervisor，它管理业务子进程。关闭窗口就停止服务。依赖固定版本，不自动升级第三方包。无自动维护配置时照常提供业务服务。

**已有0.1数据先阅读 [迁移说明](docs/UPGRADE_0_2.md)，不要直接覆盖旧目录或数据库。**

## 你需要操作的页面

管理员：门店管理→新建各店；账号与权限→新增员工→选择角色与门店。员工：右上角选门店后录入。老板：已授权门店汇总查看合计与分店对照。店长、财务、审计的汇总只包含已授权门店；全店汇总为只读。

改进意见：文本或导入UTF-8 TXT/Markdown→授权AI处理→等待测试→负责人在飞书看diff并批准。反馈本身属于所选门店，但代码发布是整套系统级操作。

「账户录入」在这版指员工登录账号，可创建/停用/改角色/改授权店/重置密码。财务流水中的现金或银行账户仍是手工填写字段，未连接银行接口，也不是财务账户主数据系统。

## 自动维护是可选的一次性接线

需要自己的专用Git仓库、DeepSeek API Key、飞书企业自建应用机器人（App ID/Secret/负责人open_id）和Docker隔离测试环境。运行 `setup-maintenance.ps1` / `setup-maintenance.sh` 后按 [接线说明](docs/MAINTENANCE.md) 配置.env。

不是飞书自定义Webhook群机器人；使用官方SDK长连接接收卡片回调，不要求本机有公网地址。没有配置不会外发，不会伪装成已连接。飞书默认私聊负责人，也可发专用审批群。

AI默认仅改前端与用户说明。后端、权限、金额算法、数据库迁移、依赖、测试和发布器全部受保护。候选代码先在无网络容器中测试；通过才推送候选分支。未批准不改Git主分支、不切换业务代码。批准绑定确切SHA；发布前备份，失败恢复旧代码并按情况暂停维护。回滚保留当前业务数据库。

## 必须明确的限制

一套服务连接一个数据库管理多家门店，不是各店各建SQLite后自动同步。默认只监听本机，外部员工接入和服务器HTTPS部署另行配置，不要直接把开发服务暴露公网。客户级隔离、不同店不同角色、审批金额限额、跨店车辆调拨、集团内部交易抵销、配件库存和复式会计尚未实现。

日报按店分别生成；汇总看板不是集团合并会计报表。本版飞书推送的是代码审批与发布结果，尚未额外推送经营日报。默认没有自动清理备份/旧版本，也没有跨机器灾备。

真实DeepSeek与飞书租户、远程Git托管、Docker和Windows/macOS操作系统需在用户环境完成接线验收。测试数据全部虚构，压缩包不附真实数据库或凭据。
