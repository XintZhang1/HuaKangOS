# 普通搜索、AI搜索与表单入口

2026-09-24 搜索功能维持原样；业务助手已增加思考开关和流式输出。原需求范围、流程权限及业务账本不变；助手消息新增thinking标记。

## 搜索和跳转

默认普通搜索，实时匹配111条指引及其入口。普通搜索没有结果也不会自动调用模型。点击AI搜索标签会提交已有查询；AI模式后续输入只更新文字，Enter或按钮才提交。切回普通搜索会取消等待并立即恢复关键词结果。搜索结果与图文说明中的页面和表单入口相同。

40个快捷表单映射位于 `web/workflowactions.js`，由开发者逐条核对原按钮，只打开现有表单。入口校验门店和岗位；表单未完成时不会跳走，切店、导航变化或迟到页面结果不会自动点击旧入口。退款、退货等选原单的流程没有跨过原单选择；用户仍在原业务界面办理。系统内及离线手册的 `#workflow-form/<指引ID>` 链接经过同样校验，不能传任意URL、选择器或执行动作。

## DeepSeek当前接入

业务助手由Python后端使用 `httpx` 调用官方 `https://api.deepseek.com/chat/completions`，采用Chat Completions兼容协议。API凭据在源码外服务端配置，前端不持有密钥。目前配置为 `deepseek-flash`。业务助手使用流式接口，思考默认关闭，可在发送前开启；开启时请求 `thinking: {type: "enabled"}`、`reasoning_effort: "low"`。正文逐步显示，查询期间显示状态。指引AI搜索继续显式关闭思考、非流式返回，不受助手开关影响。

模型通过固定工具查询和准备表单，缺信息可以继续多轮询问；员工核对后确认提交。工具没有执行代码或修改源码权限。指引AI搜索使用单独只读接口，仅发送静态指引目录和搜索文字，不读取员工业务资料。

不开思考仍支持多轮问答和工具调用，适合找入口、补字段及常规填表。复杂条件推导可能受益于思考，但效果须实测；思考会产生额外推理内容，一般增加响应等待和token消耗。助手一轮可能多次请求模型，耗时可累积。

思考工具链已保留当前轮次需要的完整 `reasoning_content`，仅在服务端内存传回模型，不存入业务记录或展示给员工。已分别设置输出预算、总超时、中断与重试核对。流式工具参数必须接收完整才准备表单，正文显示不代表已提交业务。官方说明：https://api-docs.deepseek.com/guides/thinking_mode/
