# huakangos 集团会员卡、续会与消费积分

本轮把集团会员办理从接待／销售／维修的附属入口扩展为独立业务单。员工从本店客户进入“会员卡与续会”，办理本次申请、上传实际凭据，再由相应岗位确认。会员身份、本金、赠金、积分、券和套餐继续使用各自原账，不自动合并旧本店会员或迁移历史余额。

原始功能表中直接相关的是 HK-117 会员信息管理、HK-118 换补卡、HK-119/120 积分兑换／调整、HK-121 等级调整、HK-122 续会、HK-124 储值充值、HK-128 卡生成、HK-168 积分统计及 HK-187/188 会员字典／级别。挂失和消费积分追回是这些能力的流程补充；原表没有提供收费金额、积分比例或退款算法。本模块要求管理员明确配置，初始规则及自动消费积分均关闭。

## 独立办理与岗位

`membership` 使用流程版本2。每单冻结会员、本店客户、用途、申请人及具体规则／金额／原批次。前台不能通过修改状态或填写任意账目直接改变余额。

| 分支 | 岗位及前置事实 | 原子结果、下一责任人、异常出口 |
|---|---|---|
| 本金充值 | 本店接待／销售／服务／客服／财务或管理人员建立具体金额申请；当前接手财务核对本单凭据、真实账户、流水号 | 一次记录实际现金、本金及中心／门店往来，结束本次宿主。未收款可撤销；完成后由原本金退款请求、主管批准占额、财务实际退款处理 |
| 券包购买／权益赠送 | 冻结权益规则版本、单位数及购买或赠送用途；购买交财务，赠送交主管 | 调用既有独立权益账；购买现金仅在本店一次记录。不能把购买改成赠送或更换规则。退款沿原批次既有批准流程 |
| 积分调整／兑换 | 明确原积分批次、单位数、兑换目标；主管扣减，财务兑换 | 使用原积分单位账与冻结兑换率，保留原扣减及目标发行。不得超过可用或已占用额度 |
| 卡发行／挂失／换补 | 本店已明确关联客户和会员；接手办理人上传本人核对客户申请的凭据 | 发卡只生成识别卡，不充值、不扣款。完成后不可取消抹除，后续挂失／换补追加办理记录 |
| 续会／等级调整 | 选择当前已启用且适用本店的规则；另一位主管复核 | 申请人与批准人不同，管理员也不能自批。续会转财务，等级调整转服务岗位；未办理可撤销或退回 |
| 收费续会 | 按申请时冻结费用、实际账户和本单收款凭据，由财务确认 | 现金、本次期间、事件、待办和幂等回执一次提交；不得在未到账时提前生成生效期间 |
| 未生效续会退款 | 原冻结规则允许、尚未到开始日、原店原款、有独立批准且没有后续期间 | 财务整笔退回原账户并追加期间撤销记录；原收费、期间、审批和原业务单保持可查。开始日已到、已有后继期间或已经退过均拒绝 |

财务、主管、服务／客服可按本店权限办理；销售和接待仍只能访问自己负责的客户和业务，审计员只读。集团汇总界面不能办理。创建待办不等于完成发卡、到账或生效；到期与转交复用现有待办能力，系统不代替员工确认，也不向客户自动发送消息。

## 卡片与等级期间

集团会员号保留原身份。识别卡另有随机卡号、连续代次、原卡和发行来源。一个会员最多一张有效识别卡；数据库唯一约束和集团会员版本共同防止同时发出两张有效卡。挂失停用该卡；换补在同一事务使原卡作废并发行下一代，旧卡再次扫描或精确查号返回无有效卡。乙店可在已明确关联本店客户后换补甲店发行的卡，但不能读取甲店原办理单或附件。

**识别卡不是付款授权凭证。** 知道卡号不能扣款、退款、查看未关联本店的客户信息，或获得他店经营历史。实际资金和权益操作始终校验员工、本店客户、原业务及本次实际凭据。挂失或等级到期不没收本金、不抹掉已发行券包，也不阻断合法原款退款。识别卡状态与等级有效期分别显示。

集团规则由集团管理员发布为不可变版本，明确适用门店、等级名称、自然月数、续会费用、收费归属、退款规则和消费积分配置。普通门店主管不能替其他门店发布集团规则。原逐店 `MemberTier` 主数据保持原样，不自动解释为集团统一规则。

续会从现有最后一个有效期间结束后接续；已经过期则从办理日开始，以自然月计算截止日。等级调整从办理日生效，保持当前期间结束日；没有当前期间时按所选规则建立明确期限。原有期间不覆盖，更高代次记录表达当前等级。已预约的未来续会仍保持其冻结规则，不暗中改写。

收费主体目前只支持配置为收款门店实际经营主体，费用独立记为 `group_member_fee`，退款为 `group_member_fee_refund`；不将续会费充入储值本金，也不捏造会员中心银行账户或收入。规则可选择“不提供退款”或“未生效期间整笔原款退款”；已生效的按天退费、转会退费、换补卡收费和集团中心统一收费归属尚未开放。

本轮等级通过有效期和消费积分规则实际联动。没有自动重写维修／精品价格，没有把等级字典中的折扣率强加到已授权报价；等级折扣、组合促销、自动升降级和成长值尚需独立规则及价格授权验收。

## 实际消费积分与原单追回

消费积分支持维修明细版本3／4及精品版本2。原业务首次客户授权时冻结会员和当时有效等级对应的当前规则版本；当时没有会员、没有生效等级、规则未启用或积分未启用，就冻结为本单不赠分。后续入会、续会或启用规则不会追赠该历史单。规则修改只影响后续新授权业务，既有消费按原版本核算。

计算基数为已实际履约的客户净消费：

- 维修必须已由服务岗位确认客户接车；只取客户承担中的实际现金与集团本金抵扣净额，不含保险、厂家、内部承担和赠金／积分／券包抵扣。
- 精品必须由原销售岗位确认客户已接收；取实际净收款与验收退货后的净收费两者较小值。退货减少履约收费后即追回积分，不等到现金退款才处理。
- 充值、预收、续会费用、购买券包和未交付业务不计消费积分；纯内部责任返修没有客户消费，不发积分。

系统使用整数分和整数积分计算：

`原单应得积分 = floor(原单累计净基数分 × 已冻结积分分子 ÷ 已冻结消费分母分)`

每次事实变化只追加新应得与原应得之差。分两笔收款不会比一次收款多赠分；部分退货、分次退货也按同一原单累计口径取整，不逐笔向上舍入。原发放保留来源业务、冻结规则、积分批次、履约／收退款凭据和操作人。

原消费减少时先扣回原发放批次尚未占用的积分。积分已经被消费、兑换、另行扣减或占用而不足的部分，记录关联本次原单追回的积分债务，**不阻断真实现金退款，也不将积分钱包改成负数**。债务存在时不能新增积分兑换、占额或核销；已有占额仍可在原店释放，其他本金、赠金和券包不自动扣押。

随后发放或退回的积分先抵这笔原欠额。客户也可明确选择已有且适用、未过期的积分，建立独立“使用现有积分抵扣原欠额”办理单，由财务按已冻结数量扣减并关联原债务，数量不能超过可用积分或尚欠额度。不存在通过伪造新赠分才能清债的要求。自动抵扣及人工确认抵扣都追加真实积分扣减与债务抵扣记录；其他店只能看到共同会员的待追回总额，本店之外的原消费历史仍不暴露。

## 接口、核对与恢复

- `/api/membership/rules`：读取适用规则；管理员发布新版本。
- `/api/membership/members?customer_id=...`：本店客户的卡片、期间、有效等级及待追回积分；`/cards/lookup` 仅识别本店已关联的有效卡。
- `/api/membership/orders`、`/orders/{case_id}`、`/orders/{case_id}/actions/{action}`：明确用途的办理。动作要求请求号、会员业务版本、Case版本、集团会员版本及专属字段。
- `freeze_points_rule(db,user,row)`、`sync_consumption_points(db,user,row,evidence_id=None)`：原业务内部调用，不自行提交事务。同步现金／实物事实、积分、任务、版本和回执后一起提交。
- `analytics_rows(db,user)`：本店或已授权门店的续会费、带符号积分变化、原债务与剩余单位；不把金额和积分相加。每类最多25,000条，超过上限明确拒绝而不截断金额；债务抵扣批量汇总。
- `validate_membership_sqlite(connection)`：只读检查业务宿主、客户关系、独立复核、卡代次、期间与实际收费、退款原款、积分原发放／扣回／待追回／抵扣守恒；并从原履约、客户承担与实际收退记录重算消费基数。与既有附件和权益余额恢复校验一起执行。
- `s319_membership` 在 `r218_warehouse` 后追加12张冻结表，旧集团本金和权益账不改写，不自动补卡或补积分。
