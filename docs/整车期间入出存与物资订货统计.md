# huakangos · 整车期间入出存与物资订货统计

对应原需求 HK-143 整车入库统计、HK-144 整车出库统计、HK-145 整车入出存统计、HK-153 物资采购订货统计。以下是已明确并落地的报表定义，不把菜单数量当作公司业务验收。

## 员工使用

在具体门店打开“整车期间入出存”或“物资采购订货统计”，选择首末日期。库存、主管、财务、审计及管理员可查询；库管只看到数量。销售、接待及维修等岗位不因此取得采购成本或库存财务信息。集团汇总只包含已授权的管理岗位门店，原单办理入口隐藏，不扩大其他门店原业务或附件访问权。

日期不能倒置、晚于今天或超过一年。所有金额按整数分保存，数量为台或整数千分位；展示时才换为元或物资原单位。每张表和图的原始行均可导出 CSV，导出不改变库存、付款、状态或责任人。CSV 中以公式字符起始的文本作文本转义。

查看结果时分别核对“库内库存来源”和“在途来源”。两者完整性分别标示，不以一个“已核对”遮住另一项未知事实。来源差异保留逐车/逐行说明；已验证原始明细仍可查询，但完整性不足时不出完整期末或履约合计图。

## 整车期间口径

按门店、车辆库存编号、VIN、库存代次归集。开始日前原始实物流水合计是期初，期间包含首末日，期末＝期初＋期间入库－期间出库。不同代次保留各自原行门店归属；不能把同 VIN 的历史行当作一行覆盖。

| 业务事实 | 唯一统计来源 | 日期和处理 |
|---|---|---|
| 已确认期初车辆 | OpeningVehicleEntry，关联已确认 OpeningImport | 原期初日期，关联原确认业务单；其位置记录不再计一次入库 |
| 整车采购实际验收/退回 | VehiclePurchaseMovement | 原业务日期；验收必须与 VehiclePurchaseReceipt 一致，未到货退回不产生库存 |
| 跨店发出、实际接收、拒收后的原退接收 | VehicleMovement | 各自实际业务日；原发出负数，新代次接收正数 |
| 其他出库、其他原单退回、客户退车验收入库 | VehiclePositionEntry.inventory_delta | 仅实际改变库存的已追加事实；申请、批准、隔离检查均不计入库 |
| 销售实车出库 | 唯一 sale_dispatch 位置记录与 dispatch、allocate FlowEvent 核对 | 实际出库日；若旧版本缺该位置记录，只有唯一配车事件、出库事件及原代次唯一入库成本均具备时，才按原事件日期/原入库成本取数 |
| 店内移库和定位 | 位置流水，不额外改变门店库存 | 店内在途仍属本店库内库存，不能将移出某库位再作为一次门店出库 |

销售出库后的待客户交车车辆已退出本表库内，原经营收入仍按客户交车日期另表。本表不是会计结转成本、利润、当前可售库存或收入报表。车型和库存编号用于定位来源，数量及价值只来自上述不可变事实。

每个库存代次只允许一笔原入库、最多一笔退出，原退出成本应等于原入库成本。按业务日核对数量次序及同 VIN 各代次期末不重叠，并与当前明确保管位置核对。当前状态和成本只能用来检查差异，不能反推或补造历史期初。没有原始入库来源的旧库存、无实际出库来源的旧销售记录逐车标缺口。

### 调拨和供应商在途

供应商已发运未实际验收另列，尚不计本店库存或入库价值。跨店在途从实际发出到实际接收/原退接收，按发出店列一次。双方都在本次授权范围内的原流水标为“授权范围内双边调拨”，它们的原值变动抵销；跨授权边界单列。库内入出库数量表示实际收发量，不能把调拨收货再解释为集团对外采购。

若只有发出店权限而原对店接收流水不可读，历史在途数量显示“—”，transit_complete=false，并明确授权缺口。不会使用今天的调拨状态推断过去某日，也不会临时扩大 ORM 门店范围。单店原入出库仍可独立 complete=true。拒收原退事实在发出店可核对时可以确定其在途结束。

## 物资订货批次口径

期间按原 procurement_create 事件转换至配置时区后的申请日期选择采购批次。所选批次的实际到货、关闭未到余量和退货，是截至本次查询快照的累计事实；期间末日不是历史履约时点。页面明确展示查询时间。后来到货不因为发生在期间外而被丢弃，期间内其他老批次到货也不混入此批次。

按每个不可变 PurchaseLine 原单位和原分金额核对：

```
原订货 = 累计实际到货 + 仍待到货 + 已关闭未到货 + 待批准
累计实际留存 = 累计实际到货 - 实际原单退货
```

待批准与被拒绝/已取消分别列示。批准并不代表已收到实物。已关闭剩余采购不会被退货自动重开。实际到货和退货同时核对 PurchaseReceipt/PurchaseReturnPosting 与原 StockMove 的原单、物资、数量、价值和日期；申请退货或批准退货不算实际退货，付款也不重复算采购数量或库存。

每种计量单位有自己的图和对应明细集合，图的导出只包含该单位，不把件、升等相加。逐行金额来自冻结总额和实际批次价值的余数，不用显示单价重新乘算，保留分摊尾差。旧 purchase 简表只有登记日期和缺少不可变逐行订货来源时，列在历史差异表，不冒充新版详细订货账。

## 技术接口及一致性

- `GET /api/inventory-reports/vehicles?date_from=…&date_to=…&vin=…`（VIN 可选）。
- `GET /api/inventory-reports/procurement?date_from=…&date_to=…`。
- `GET /api/inventory-reports/{vehicles|procurement}/export/{table_key}` 使用相同筛选和 builder 的同一张表。无写入业务动作。
- 独立 builder 为 `build_vehicle_period`、`build_procurement_cohort`，综合经营报表复用其 tables/charts/metrics/definitions，不重复实现口径。指标使用独立前缀，不覆盖原“当前库存”指标。
- 所有 StoreScoped 来源保留当前授权门店 SQL 条件。中央调拨仅查询与当前 scope 参与方匹配的头记录，不读取对店未授权原业务、客户或附件。
- 一次请求内使用数据库读事务快照；SQLite 显式读事务、PostgreSQL REPEATABLE READ。超过来源上限拒绝而不截断合计。导出追加审计记录，其余业务事实不变。

## 验证与本版边界

专项见 `tests/test_vehicle_period_analytics.py`、`tests/test_procurement_analytics.py`，覆盖期初/采购/原退/客户退/新代次/销售不重复、旧来源不足、局部授权与集团调拨在途、并发读快照、单位隔离、图表和 CSV 原行、原账差异拒绝、岗位和跨店限制以及上海午夜日期。

`tests/browser_inventory_reports.py` 创建独立合成空库和随机密码，使用真实 Chrome HTTP 的库管/主管账号在 390px 下查询、下载 CSV、验证成本权限、期间错误及其他门店隔离。过程截图和 JSON 放系统临时目录，不包含公司资料。测试结果不替代公司期初确认、正式数据逐笔核对或生产设备验收。

2026-09-21 本轮验证：新报表专项 17 项通过；与既有物资期间及整车位置统计组合共 26 项通过。综合报表与独立入口的原始表对象相同，CSV 仅保留既有通用导出对负数字符串的 Excel 文本前缀差异，解读后的有符号金额一致。真实 Chrome 两个员工账号四条验证链通过、无 JavaScript 错误；日期错误后可直接在原页修改并重新查询。最终四张 390px 截图已逐页目检，前端及 Python 语法检查通过。

本版不推断旧裸录车辆的原始入出库、不改未结旧单、不导入缺失历史、不提供任意过去日期的采购状态快照、不自动估计运输损失；未授权对店历史在途确认为明确限制。未新增迁移或改写任何历史账本。
