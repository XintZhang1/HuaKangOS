# 整车运输差异与原车找回 · r80e

## 原业务闭环

从原整车调拨页面登记失联、错VIN或损坏，不新造一笔调拨。原单、原VIN、原成本、原实物发出及两店岗位保持绑定。核对期间暂停原实物动作；双方分别登记本人观察。错VIN仅作为观察，不能把另一辆车当作原车入库。

原调出方提出继续交接或损失/承担方案，两店各由另一主管独立复核，排除原观察人、申请人和另一店已复核人，管理员无自批例外。解除差异只重新开放原动作，不自动验收入库。确实在手不可用的原车还需有据实际处置；失联不虚构处置。

财务在两店批准和实际事实齐全后确认原在途成本损失。原发出早已出库，核销不再次扣库存、不自动记现金。两店承担合计原成本，原调入方承担形成独立原往来。

失联原车后来找到：本人记录新的在场观察，原调出方财务提出明确实际接收店，两店独立批准，指定店库管逐位输入VIN、确认真实库位及原凭据，按原成本建立新的合法库存代次。批准本身不入库。原车接收前再失联或不可用则保留一次原损失，退回查找；不能制造第二笔损失或绕过新观察。

## 资金及原路调整

外部追偿明确引用本店启用承运供应商或保险公司。目标须另一主管独立复核，实际现金使用本店账户/凭据和银行流水，退款沿同一本原款和原账户。多个目标、待复核目标以及尚未退回的原现金共同占用本店承担上限，减少目标不等于已经退款。

找到原车后停止按旧损失新增收款；旧目标须另行独立确认减少，再沿原实际款退款。找回不会修改旧赔款；找到的车后来再次合法调拨，旧赔款退款仍沿旧原记录办理。

新增原往来类型vehicle_loss及vehicle_found；找到时承担反向及新的资产归属分开追溯。新清算/付款在找回复核在办时暂停，但已经真实支付的清算仍允许接收方核对到账；不阻断已发生事实，也不自动净额结算。

## 期间来源、权限及恢复

原损失、实际找回、两店承担/恢复、原赔付目标及实际收退款分别提供同源图表、表和CSV。集团汇总隐藏VIN及外部单位，不开放单店原文件；库管不读取成本、赔款和财务协议。原发出保管、损失从在途移除和找回新增本店代次接入整车期间入出存。

月结定义12冻结十六类来源；旧1—11保持原范围，不把后来事实倒塞入已封存旧批次。显式重算生成新后继批次。恢复校验核对原单/原VIN、独立观察批准、原成本、财务原款、两店成对往来、库存代次、月结原来源和请求关系；摘要是内部一致性约束，不是抵抗全库管理员重写的外部签名。

## 证据和边界

`vehicle-final08`在同一冻结运行源码上102项通过、0失败、0跳过，含非空q79d升级、原请求重放、并发、后续再次调拨、原退款、原数据篡改及旧月结保护。旧q79d整轮1242通过/2失败/1跳过仅是原检查点；两项写死旧head的测试已经修正并在102项内重跑。所有扩大迭代失败记录保留，不与其他专项重复相加。

`tests/browser_vehicle_transport.py`为实际员工移动端原交接→损失→找回页面脚本，起始车辆是隔离合成夹具；`tests/postgres_vehicle_transport.py --pg-bin <可信安装目录>`只创建自己的临时本机服务器，验原数据迁移、真实PG并发原接口、原退款、dump/restore及业务图回验。**本阶段均未运行真实浏览器/真实PG**。`--prepare-only`仅准备并校验合成SQLite来源，已成功，绝非PG验收。

迁移`r80e_vehicle_transport`追加在q79d后；所有历史迁移保持不变。用非空副本演练备份和升级，不能覆盖现用数据库，也不能对旧库执行init --demo。默认规则仍待公司确认和实际两店周期验收。采购供应商发运短缺不冒充已入库整车的原调拨差异；原采购退回按其专用入口。
