# 跨店原单与逐件附件授权

检查点 `t02g-dossier-masters`；权限域迁移 `s91f_dossier_grants`。本功能是指定范围的只读历史交接，不是把原单转到另一门店，不是开放跨店办理权限。门店均为平级直营，不增加合作关系审批模块。

## 员工办理

原店能正常读取该业务的员工，从原业务“档案授权”入口选择接收门店和**具体员工**。可选择提供原单历史快照，并逐件勾选原文件；文件默认全不勾选。电话/联系许可和金额分别选择，财务内容仅可提供给允许财务读取的岗位。填写用途、截止时间并明确确认后提交。

原店另一位有权主管/管理员从“待我复核”核对原单版本、接收人、用途、期限及逐件文件。发起人不能批准自己的请求，管理员也不例外。原单或文件在批准前变化时拒绝批准，须重新核对范围；不得在旧请求里偷偷替换文件。

批准后，指定接收员工从“收到的授权”读取专用入口。普通原单和附件地址仍然执行原跨店限制；同店同岗位的其他员工、接收店管理员也不会因此自动获得授权。没有批准的文件，即使与批准文件字节完全相同，也不可读取。

原店可以撤销未来读取；待审申请可取消/拒绝。每个动作保留原请求回执，重复请求不会创建第二份批准、恢复已经撤销的权限或改变批准内容。

## 冻结内容与明确边界

原单快照采用定义1的字段白名单：原单头、当时状态/版本、允许的客户/车辆信息，以及最近最多200条必要事件标签；总事件数和省略数明确显示。金额及联系字段须单独批准。它**不是原单所有嵌套明细、原始JSON、私密备注、任务、全部历史或后续子单的复制**；需要完整原文时，由原店逐件选择合适的既有文档。行政配置、期初、月结、业务财务等系统类单据不从这个客户档案入口共享。

批准后新增的业务、事件和文件不会自动出现在快照里。原单继续合法办理不倒改已批准的历史版本；再次交接新版本须另建申请。每份授权至多100件文件、有效期最长366日，是本版人工复核与响应规模的工程预算，不是额外业务事实或安全正确性的证明。

每次查看、列文件和下载都会重新核对实际账号、门店、岗位及账号授权版本、原店来源权限、截止时间、撤销状态。原单负责人变更与读取加锁协调；帐号停用、改岗、权限版本变化等会使旧授权暂停，不会因浏览器缓存而继续开放。

文件读取还核对明确原文件编号、元数据、查毒可用状态及实际私有存储字节。只批准文件摘要并不自动信任另一份同内容文件。读取回执先提交成功才返回内容，回执写入失败时不向客户端发送原文。响应保持不缓存策略。

页面在退出、切换账号/门店、离开授权页、到期和重新核验失败时清除旧显示，异步过时响应不覆盖当前页面。**已实际下载到员工设备的副本无法通过撤销远程删除**；公司仍应限定用途和员工保存方式。

## 恢复与数据一致性

五张新增表记录授权范围、逐件文件、独立决策、读取回执及幂等回执。运行时禁止覆写冻结依据；独立SQLite恢复校验复核门店/原业务/原文件、原范围摘要、决策时序、人员、有效期和读取来源。旧库没有这个领域时兼容，只有部分表的破损状态拒绝恢复。合法的后续原业务或账号变化不倒改历史决策。

内部摘要用于检测记录不一致，不是能抵抗管理员同时改写所有原始数据与全部摘要的外部签名。本版不接外部身份/存储服务，不发送公司档案给AI。

## t02g-fix1 岗位子类型与原成本

显式授权替代原单个人归属限制，但不替代岗位对业务子类型的限制。车辆作业中服务和技师只允许客户退车；其他出库、采购退回、移库等不能通过跨店授权变为可读。修复前获批但不再符合此规则的记录保留，实时访问暂停；原快照和批准记录不覆盖。合法授权与财务附件限制继续有效。

`cost_cents=null` 表示原单未记录成本，展示“原单未记录成本”；整数 0 仍表示原成本为零。不读取别的业务域补值，不制造费用或现金。原金额/已结金额仍严格为整数分，恢复验证与在线读取使用相同结构规则。
