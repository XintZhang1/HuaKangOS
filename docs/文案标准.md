# 当前界面文案标准

依据是用户本轮明确要求及当前会话中“操作简单、文案简洁、没有多余介绍”的偏好。Writing Style两次检索返回无可用参考，因此本文件不是已取得的个人风格档案。原需求名、业务规则及服务器拒绝优先于风格调整。

按钮直接说明动作，如“保存客户”“分派接待”“查看原单”；一处一个主要动作。标题采用员工熟悉的原业务名称，少用抽象术语。输入提示只说明该项需要填什么，单位和必要格式放在相关字段旁。

先说当前结果，再说需要员工做什么。准备、待确认、已提交、等待真实事实分别写清，不能用“已完成”替代到账、交车、签字或核销。失败引用真实原因，能够继续时给一个明确下一步，权限拒绝和业务规则拒绝保持区别。

省去不影响当前操作的产品介绍、能力宣传、重复状态和实现解释。需要作决定时保留客户/原单/门店、金额或数量、不可逆后果和确认范围。精简不省略原法定/业务说明，不隐藏错误、来源不足、未知结果或版本冲突。

相同动作使用相同名称，中文标点和金额/数量单位一致。普通员工无需猜内部ID或版本；显示已有真实名称、编号和可选择候选，提交仍使用原生值。管理员或审计页面确需技术信息时沿原用途保留。

验收时按实际页面记录：员工是否能识别对象、当前结果和下一步，是否有重复或无帮助的介绍，字段/按钮是否准确，错误是否易于恢复。自动长度阈值只是辅助，不能用词表或短句数量代替业务和人工判断。
