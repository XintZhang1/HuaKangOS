# 销售零价赠送加装 · w35j

本专项补齐 HK-012、HK-065 的购车零价赠送加装分支。既有收费加装及 addon/v3 入口保留；新报价使用核价合同第 2 版，按原销售、本店原 VIN、原物资和实际安装办理。所有验证使用新建合成数据库，不使用公司数据。

## 员工办理与例外

1. 销售/服务人员在原销售加装单逐项选择真实物资与安装作业，填写数量与收费。新零价行（包括全额优惠后为零）必须说明赠送原因并选择“本销售门店承担商品及安装成本”。收费行不能误填赠送条款；单独一个收费组成部分为零不等于整行赠送。
2. 原核价经理待办保持独立：报价人或申请人不能自批，管理员也不例外。主管核对原件、最低价和赠送条款，并明确确认本销售门店承担。低于本次最低额仍需原低价例外授权。主管确认不生成库存或现金。
3. 客户授权必须引用当前已获批报价。后台一次事务建立原行物资占用；旧版本授权、重复领用、跨门店引用和竞争占用均拒绝。重新报价产生独立报价、批准、客户授权，不覆盖旧版本。
4. 库管核对原销售配车 VIN 后实际领料，记录原移动平均出库成本。技师确认实际安装，服务顾问实际检查；不合格必须有技师整改及重新检查。零价不跳过这些步骤，也不因没有应收而提前完成。
5. 销售/服务人员登记客户本版实际接收。此时记录零收入及真实原出库成本，交车前条件才可满足。系统不估计安装人工成本，不制造一分钱收款、预收抵用、退款或销售发票额度。
6. 未授权可按原取消动作取消。已授权未领项目须原处置申请、另一位主管批准、客户同意，之后释放数量占用；没有实物收发或虚构客户接收。已领/已安装赠品拆回沿原处置、实际可售检查、必要整改/拒收交回；入库恢复原批次数量与原成本，含分拆尾差，客户应退保持零。
7. 随原车无偿接回已装件仍沿已有的原 VIN 退车与附属物移交，不恢复物资库存或再次资本化。零价赠送的原客户接收也受父销售售后门槛核验。

待办责任人和原到期日由既有任务路由保留；没有到期自动收款、放行、验收或取消。交接、取消和原单处置沿现有明确动作。所有报价、核价、客户授权、施工、库存、接收、处置和请求回执同事务落地，版本冲突要求刷新核对并保留原请求编号。

赠送默认由本销售门店承担；没有借此引入总部付款或供应商赔付工作流。对应承担方若以后有实际业务约定，应按原业务规则单独定义，不能直接改原赠送门店。

## 接口与冻结数据

- `POST /api/addon-orders/{id}/actions/quote` 的每个新零价行增加 `gift_reason` 与 `gift_cost_bearer="selling_store"`。不接受客户端指定承担店 ID。
- 原 `approve` 动作增加 `confirm_gift=true`，只有本版存在明确赠送条款时才能确认。
- `addon_quotes.pricing_version`：历史默认 1，新报价明确 2。
- `addon_quotes.gift_terms`：历史默认 `{}`；新条款按原 `line_key` 冻结 `{reason,cost_bearer,burden_store_id}`。承担店来自原加装单本店。
- `addon_approvals.gift_confirmed`：历史默认 false，新赠送报价必须由独立核价人明确确认。
- 旧第 1 版报价摘要保持原 `lines` 列表算法。新第 2 版摘要包含 `pricing_version`、同一原行字段列表和 `gift_terms`。未知版本关闭办理及恢复验收。
- 已授权的商品、数量、价格和赠送条款不得改写。历史第 1 版已授权的零价原行仍可被原样带入后续报价，但不补记赠送理由或推定旧独立赠送批准；其原始摘要不变。
- 仅有金额读取权限的角色看到赠送价格与原因；库管、技师的原有精简视图和原件权限保持。通用案件接口同样隐藏赠送报价字段。

迁移 `w35j_addon_gifts` 紧接 `v24i_procurement_prepayments`，只扩展上述三列并更新新报价零金额约束。旧迁移不改；不自动降级删除业务事实。已向主任务交付旧月结 definition 1–12 序列化需排除这三列、新 definition 13 可包括的集成说明。本专项不修改公共月结、现金汇总或总恢复入口。
