# huakangos 华慷集团门店运营系统建设计划

目标为完整覆盖原始功能表193项的内部运营系统。按业务闭环建设，不能将菜单存在或正常路径通过等同于业务验收。原表及用户明确修订优先，具体边界见《原始需求范围复核》。当前实施证据见 `实施进度.md`，逐项追踪见 `需求验收台账.md` 与 `requirements.json`。

## 已确认的产品边界

- 门店独立办理、独立库存、独立业务账和结算；集团共享客户、车辆身份，历史按授权开放；供应商/保险公司基础资料保留，不增设直营店合作关系审批。
- 集团会员为独立权益与内部记账模块，实际付款沿用集团独立财务系统，不增设实际资金清算。门店调用统一会员身份和权益，实际现金归收付款门店，履约归服务门店，集团记录对应权益和内部往来。
- 电脑和手机浏览器为员工端；集团汇总只读。前台不承担权限边界，不增加员工绩效排名或AI业务决策。
- 财务包括应收应付、预收、收退款、月结和对账；不建设会计总账。
- 税务、银行、保险、厂家先通过外部办理结果和凭据衔接，不将登记结果称为已调用外部接口；新增接口不得因旧计划提到而自动列为本次必需。
- 尚无正式业务数据，正式启用使用新库及经核对的期初数据；不把虚构演示库迁入正式库。

## 六个交付阶段

| 阶段 | 建设范围 | 通过条件 |
|---|---|---|
| 一 需求与风险基线 | 稳定需求编号、实现与验收分层、huakangos品牌、环境基线、PDI与已有撤销出口 | 需求不遗漏；高风险关口有拒绝测试；既有回归通过 |
| 二 共享基础与经营账 | 逐店岗位、共享身份、集团会员基础、完整主数据、明细与版本化报价、应收应付、流程版本、附件存储及期初导入 | 两店共享身份但不能越权操作；车辆不重复占用；账目与附件可核对 |
| 三 采购仓储 | 整车采购计划和请款导入、发货到货、采购付款退回；多明细分批物资采购、耗材礼品、盘点移库；双方调拨及在途拒收；期间入出存报表 | 采购到退货、调拨到接收或退回均可完成；数量、成本及往来守恒 |
| 四 销售维修与财务 | 销售服务及核价、已履约退订和交付后退车、维修预约快捷开单、项目配件明细及增项授权、多方索赔结算、精品销售、预收退款月结和发票协同 | 实际岗位完成完整链路；钱、货、履约、开票各自有据 |
| 五 客户与会员 | 问卷咨询投诉救援、首保保养保修续保；卡发行换补续会等级、积分赠送、券套餐发行核销退款；跨店权益结算 | A店发行、B店履约、集团对账可完成；并发不能重复扣款或核销 |
| 六 可视化与正式启用 | 全部36项专项统计、单店与集团汇总和内部抵销、真实浏览器及备份恢复、两店演练、单店试点后推广、岗位运维手册 | 193项逐项有验收证据；完成至少一次实际月结与会员内部记账核对周期 |

报表随业务阶段同步建设，不能等到最后再补口径。所有新业务分支在实现前确定岗位、入口、事实来源、账目影响、下一责任人、文件、超时与撤销规则。

## 工程与验收约束

- 保留Python业务后端和网页基础，逐域拆分；目标正式环境为PostgreSQL、私有附件存储、独立任务进程。
- 业务写入限定门店；跨店协调使用专门服务并保留双方独立确认，不改原记录的门店归属。
- 业务类型与流程版本共同分派，未知版本拒绝办理；账本、凭据、收款关联追加纠错而不覆盖。
- 金额为整数分，数量为整数千分位；并发版本、幂等回执、现金与权益账在同一事务提交。
- 覆盖正常、拒绝、跨店、重复、过期版本、撤销和并发争用；报表对账到原行及CSV；员工网页和正式模板需实际检查。
- 保留自动改代码、Git推送、飞书代码审批及无人值守部署的禁用边界。可选AI摘要默认关闭。

## 当前阶段说明

这是一份持续建设计划，不是完成证明。真实门店业务验收、期初数据确认、公司合同模板确认和部署侧验证尚未发生；不将自动测试结果替代这些步骤。
