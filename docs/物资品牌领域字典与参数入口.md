# 物资品牌、领域字典与参数入口

这是原需求表基础数据与系统管理的补齐，不是新增门店关系或实际资金清算模块。当前迁移头 `t02g_master_completion`；`s91f_dossier_grants` 在它之前。

## 物资品牌（HK-181）

“经营主数据 → 物资品牌”沿原主数据岗位规则维护代码、名称及启停。物资归类增加可选品牌引用，与分类/仓库库位分别设置。品牌必须属于同店；启用物资不能引用停用品牌，仍被启用物资引用的品牌不能停用。引用保留版本及重复请求校验。

原物资目录及详情/选项显示**当前主数据品牌**。此标签不重算库存价值、历史交易成本或历史冻结报价，不冒充历史品牌归属分析。

迁移新增品牌表及原归类的可空引用；旧库数据不猜填品牌，不改变原物资或文件。旧版客户端编辑未携带 `brand_id` 时保留原值；显式空值才解除绑定。独立恢复校验拒绝跨店品牌引用、启用物资引用停用品牌以及残缺领域表。

## 七类领域字典（HK-170、173、176、180、185、186、187）

“领域字典”按公共、维修、整车、物资、财务、客户、会员七组分别维护名称、说明、启停。沿用 `flow_references` 原表，不复制已有资料和历史引用。支持版本、原请求回执、查询/分页及岗位控制。原通用编辑入口也不能将已归类条目偷偷换组。

字典是描述性资料。流程状态、权限、财务分摊、会员规则等仍由各自专用规则控制，不能通过新增自由字典值改变业务行为。未定义的业务下拉不会自动与任意同名字典混合。

## 参数与个人密码（HK-192）

“参数与个人密码”只展示当前岗位可以读取的原规则页面，包括提醒、问卷版本、工位/快捷组合、会员等级积分、券包/充值组合、精品套餐及混合记账、主数据和模板。是否可修改由原业务接口决定：例如集团规则原先仅管理员可发布，参数入口不会扩大为主管都可发布。测试逐角色访问每个列出的目标API，避免出现显示入口却无权读取的死链。

部署阈值仅向本店有权管理人员展示安全白名单，**仍由部署配置维护**。没有通用配置写入后台，不返回数据库连接串、密钥、外发设置或私有文件路径。业务可配置规则直接进入已有原编辑器，不新增第二套规则表。

本人改密沿已有接口验证当前密码，并按原机制撤销其它会话；它与员工授权版本管理分开。集团汇总页不办理门店参数，只保留本人改密和切换实际门店提示。

## 验证

`tests/test_master_completion.py`、`tests/test_master_completion_upgrade.py` 覆盖类型/岗位/跨店/幂等/版本、旧客户端、非空旧库、原文件字节、独立恢复和参数入口权限。`tests/js/master_completion.test.cjs` 是Node模拟DOM契约验证，不是真实浏览器。

真实手机宽度浏览器脚本 `tests/browser_master_completion.py` 已保留但本轮不运行。`tests/postgres_dossier_grants.py` 的合成源同时包含实际品牌/物资引用及维修字典；只有 `--pg-bin` 真正运行服务器并完成恢复才算PostgreSQL验证，`--prepare-only` 仅检查SQLite合成准备。
