# HuakangOS 需求范围纠正 · 2026-09-22

## 决策及依据

本记录纠正之前由助手自行扩张的开发与验收范围，不是新增需求，也不代表新功能完成或验收通过。

权威依据为压缩包根目录《全新搭建：功能需求表.docx》和用户明确确认的修订。需求表是一份包含十个模块的原始功能清单；源文件与 `docs/原始功能需求表.docx` 字节一致，本轮均未改动。源 SHA-256：`ddf297678e5d6d35e1dbfffc5c232c3d56748934eb22b58bbb9f9d5343689aae`。

需求表、用户修订与助手推导必须区分：对原表未展开的业务细节可以制定默认流程，但不能据此强加用户已明确排除的模块。旧计划、交接说明和台账中的助手推导不得反过来覆盖用户需求。

## 必须保留的原始功能

原表第（九）项“公共基础数据”明确列出“公共字典、供应商设置、保险公司”。稳定台账对应供应商设置 HK-171、保险公司 HK-172。取消关系扩展不等于删除这些基础资料，也不取消正常的数据引用与岗位控制。

原表第（七）项“会员服务模块”包括会员信息、换补卡、积分、等级、续会、充值套餐、储值充值、退款请求、套餐购买/退款、会员卡、消费券和套餐卡类型。第（五）项还包含会员储值卡充值收款和退款。这里的办理结果由既有财务流程提供，本系统维护会员余额、权益、占额、核销、原路退回及来源记录，不把内部记账当成银行划款。

例如：A店登记已确认的1000元充值，客户在B店消费200元，本系统应记录原充值、B店原消费、余额800元及内部归属；实际资金由集团既有财务流程处理。会员记账不需要等待新增“集团中心清算模块”才能算功能完整。

原表已有的业务收退款登记、应收、月结和统计不得因为这一纠正被整体删除；仅剔除助手新增且用户明确不需要的模块。既有生产运行代码、迁移、历史账本与审计数据本轮均不改动。

## 开发与验收口径

直接开发顺序收敛为：跨店原业务及逐件附件授权 → 按原始193项逐条核对真实功能缺口 → 同一份源码的回归、迁移/恢复及本机验收材料。

不得直接宣布“只差授权就全部完成”：其余原表条目仍按实际功能核对，但不增加自拟大模块。被排除的任务不进入未完成项、完成率分母或验收阻塞；本轮也不把任何原始条目从“部分”直接改成“已实现”。

真实浏览器和真实PostgreSQL测试保留脚本与说明，由用户本机统一运行并反馈，不作为这里功能开发的前置阻塞，也不虚报为已通过。
