# huakangos · 整车采购与付款

本模块把本店整车采购分为数量计划、核价批准、请款、实际付款、逐 VIN 发运、实际到货验收、退回与原款退款。审批或上传文件本身不会增加库存或生成实际现金。采购单使用独立 `Case.kind=vehicle_procurement, flow_version=2`，原有流程版本不改写。通用任意状态修改不可用。

## 使用入口与主档

员工在“整车采购与付款”办理。先由主管维护启用的供应商、车型参数、整车或混合仓、库位，以及资金账户。本店引用由后台逐次检查；原始供应商名称、付款期限、车型品牌/年款/动力、颜色与计划台数保存快照。供货方停用后不能新建或批准计划，已批准的真实交接依据原快照完成。

计划中的“实际采购经营主体”由员工按真实合同明确填写并冻结，产品名与华慷集团品牌不会被自动当成任一家法人主体。尚无经营主体主档、合同模板自动套用或工商资料核验。本模块不生成需签章的采购合同，上传外部采购合同与核价凭据供内部协同。

默认旧车辆裸录入、修改、提交、批准和作废由根模块封闭为历史只读；新的实车库存由本采购链产生。现有已确认库存仍可按现行销售、调拨流程办理。旧草稿和未结单不推断、不自动迁移，整车期初批量导入另需专门方案。

## 岗位、事实与异常分支

| 动作 | 经办岗位与前置条件 | 实际依据 | 同一事务及下一责任 |
|---|---|---|---|
| 建立计划 | 库管、店长；启用本店供应商与车型 | 实际采购主体、车型、颜色、整数台数、原因、计划到货日 | 建立主管核价待办；此时没有批准金额、实车或应付 |
| 批准核价 | 当前主管待办负责人；申请与批准分人，管理员保留管理例外 | 全部车型行逐行成本、建议售价、采购合同/核价凭据 | 冻结 `VehiclePurchasePrice`，安排发运待办；价格不覆盖修改 |
| 拒绝计划 | 当前主管待办负责人；尚未批准 | 原因 | 结束申请并保留原记录，不能有过账事实 |
| 请款 | 店长；已批准采购 | 金额、原因、采购合同或财务凭据 | 锁定未付请款余量并派财务；累计已付净额加待付请款不能超过有效约定 |
| 分笔实际付款 | 当前财务待办负责人 | 有效请款、实际账户、唯一流水号、收退款凭据 | 追加唯一 `CashEntry` 及 `VehiclePurchasePayment`；没有到货时列采购预付 |
| 取消请款余量 | 店长；请款尚未付完且版本一致 | 原因 | 只关闭未付额度，已付款不删除、不假定已退款 |
| 供应商发运 | 当前库管发运待办负责人；有未发运台数 | 逐台 VIN、实际发运日期、预计到货日期、物流或交接依据 | 中央 VIN 占用，同一 VIN 不重复发运；生成到货责任，尚不入可用库存 |
| 实车验收 | 当前库管验收待办负责人 | 重新核对现场 VIN、本店启用库位、实际验收凭据 | 一台一次入库，生成新 `Vehicle` 批次、集团 VIN 身份链接、原始 `Receipt` 和 `Movement(+1,+成本)`；形成该批实际应付 |
| 终止未发运余量 | 店长；已批准且仍有未发运数量 | 供货方取消依据及原因 | 追加不可覆盖取消记录，减少有效约定；不取消已在途车辆，不假定已退款 |
| 申请退车 | 库管；原 VIN 尚未退回 | 原因和原车退回依据 | 立即阻断原入库车配车/调拨，主管待办；未入库的在途车可明确拒收后走退回链 |
| 批准/撤销退车 | 当前主管待办负责人；原车仍可退，申请与批准分人 | 原因、原申请版本 | 批准只派实物发出待办；实际发出前可撤销并释放退车占用 |
| 实车退回 | 当前库管退车待办负责人；主管已批准 | 供应商收车或物流交接凭据 | 对已入库原车追加 `Movement(-1,-原入库价值)`，关联原记录、旧库存置不可用、释放当前保管；在途拒收退回追加零库存记录。均不代表资金已退 |
| 原付款退款 | 当前财务退款待办负责人 | 本单原付款、原账户、实际到账流水、收退款凭据 | 金额不超过原款未退额及本单供应商应退额；追加现金与付款关联，不删除原款 |

任务保留经办人、期限和结果。逾期显示在通用工作台；店长在原单待办按有效本店岗位转交，已交出的员工不能用旧待办继续办理。计划到货日、物流预计到货日、供应商批次应付期限分别记录；本版不进行自动催运、扣款、外部联系或员工绩效排名。

所有动作采用当前 Case 版本与幂等编号。重复相同请求返回已办理结果；不同内容复用编号、旧版本、并发 VIN/流水冲突和越店引用拒绝，且本次修改全部回滚。不可盲换新请求号自动重试。

## VIN、原批次及跨店边界

客户车辆档案的共享 VIN 身份与库存批次分离。本采购沿用中央 `GroupIdentity(kind=vehicle)` 和 `VehicleCustody`；发运时用全局唯一活动 VIN 声明与保管版本锁协调。后台可只读检查各店库存/未完成销售/占用，只向调用者返回统一冲突提示，不开放别店库存成本、客户或业务列表。

已退回供应商或已具备明确客户提车事实的历史 VIN，在新的真实采购发运与验收凭据下可重新取得。新的库存代次是该 VIN 历史最大代次加一；旧记录的门店和代次不变。未知旧单状态不会按“可能已售”放行。新的在途车、销售占用、未完成调拨和并发采购不能形成第二份可售库存。

退回必须是本采购原验收车辆仍在本店且未售、未交付、未调拨的原批次。曾经调拨到别店再回来的新代次不擅自追认为原采购批次；已提车客户退车须走销售退车流程。采购退回与客户退车不能互换。

## 金额、数量与统计口径

金额为整数分，台数为整数；网页拒绝超过两位小数的金额。主管核价固定单车采购成本，每台验收和退回使用同一原价，不因后续主档变动或退款时间重估库存。

- 有效采购约定＝批准总额－未发运取消价值－在途实际退回价值－已入库实际退车价值。
- 实际净验收＝验收价值－原车实物退回价值。
- 已付净额＝实际付款－关联原款的实际退款。
- 当前应付＝`max(0, 实际净验收－已付净额)`；批次应付按原供应商期限和先到期先抵的口径列明。
- 供应商应退＝`max(0, 已付净额－有效采购约定)`。
- 采购预付＝`max(0, 已付净额－实际净验收－供应商应退)`；预付与应退不混记。
- 在途台数/价值来自尚未验收、尚未实际退回的发运记录；不作为本店可售库存。

对账页面及 CSV 逐单计算后汇总，来自同一查询集合，负项不跨供应商抵销。此为当前时点采购业务账，未提供任意历史期末库存重建或会计总账。资金唯一来源为 `CashEntry`；`VehiclePurchasePayment` 只是原款和请款关联，不可再次累计成现金。实物来源账为 `vehicle_purchase_movements`，与调拨 `vehicle_movements` 分别保留来源供后续经营报表合并。

经营总览接入三份明确数据集：`vehicle_procurement` 当前采购往来、`vehicle_procurement_transit` 当前供应商在途及同表成本图、`vehicle_procurement_movements` 所选期间原始实物变化。改变报表期间只影响期间实物记录，不将当前在途伪装为历史时点。三份表的 CSV 与来源记录逐行核对，通用导出的负数字符串可能带电子表格安全前缀，其数值不改变。全量整车采购、销售、调拨及期初综合入出存历史仍需统一期间账本。

## 权限、凭据及恢复

本模块只在具体门店开放，集团汇总不产生门店办理权。库管仅见型号、数量、VIN、物流、原车实物和本岗文件；冻结成本、建议售价、请款、现金及资金对账均由主管、财务、审计读取。审计无写权。后台重复校验，通用原单、文件下载和主档目录也不能作为越权入口。

“采购合同与核价凭据”独立归类为财务文件。实际付款和退款必须使用“收退款凭据”；合同、模板或一个愿望状态不能代替真实资金证据。所有文件沿用私有隔离、扫描状态与原单归属检查。采购不提供厂家、银行或税务直连。

追加迁移 `o915_vehicle_procurement` 依赖 `n814_vehicle_transfer`，冻结 11 张表的定义。`vehicle_backup_integrity` 在原调拨恢复校验外，验证采购来源、批准总额、数量守恒、唯一现金事实、原退款关系、入库成本及原退车冲回。无当前库存的保管记录必须有精确的最新采购在途/退回来源，不能因采购模块存在就忽略无来源库存。

## 验证与未覆盖边界

`tests/test_vehicle_procurement.py` 验证真实岗位、资金和价格隐私、越店原单/库位/文件、原款限额、取消余量、预付、部分验收、实车及在途退回、并发发运/接收、原 VIN 新代次、整单回滚、幂等和版本冲突。临时 SQLite 实际升级与备份复制/恢复检查覆盖在途、已接收、原车退回、未入库拒收退回；故意篡改凭据、价值或原退回关联会被拒绝。

`tests/browser_vehicle_procurement.py` 使用独立空合成库、随机密码及真实 Chrome HTTP。实际库管、店长和财务账号在 390px 页面完成计划→核价→请款→分笔预付→VIN拒绝/验收→余量终止→实车退回→原款退款与 CSV；截图均在仓库外，不含真实公司资料。生产 HTTPS、多机 PostgreSQL 并发和完整公司采购周期业务验收仍需部署与业务方完成。

2026-09-21 本轮结果：21 项专用测试、5 项真实 Chrome 场景通过；采购与既有车辆调拨、备份校验组合回归 34 项通过，前端语法检查通过。补充验证默认旧车辆写入口关闭、库存岗位旧详情成本遮蔽、供应商停用/原款账户改名拒绝、停用账户拒绝新付款，以及经营当前表/在途图/原实物账与三份 CSV 一致。五张手机截图逐张检查，并由另一代理复核 VIN 拒绝与最终结算画面。合成浏览器证据位于仓库外 `huakangos-browser-evidence-t6zvg6gx/acceptance.json`。这些属于自动验证，不代表业务验收签字或正式启用。

原需求映射：HK-021 车辆采购入库、HK-023 车辆采购退回与 HK-029 库存查询增加上述采购来源；HK-019 请款导入、HK-027 发货、HK-028 到货提供人工有据链，但**未实现 Excel/厂家请款批量导入**。HK-018 的车型参数选择已有主档关联，完整车型展示专题仍未交付。HK-143–145 等全量期间整车入出存统计不以本采购对账代替。

本轮不包括：厂家API、外部采购单批量导入、期初整车自动导入、随意修改已批准价格、追加运输成本分摊、部分折让/赔偿、已发运直接取消、丢车报损、其他整车出库、客户已交付退车、实际银行指令、正式会计凭证或业务方验收签字。差异必须按现有完整退车与新采购有据重办；不能覆盖原始事实掩盖差异。
