# 充值组合原款误记更正

2026-09-23，原表 HK-090 收款单调整在充值组合上的原权益联动分支。本次延续[原收款更正与供应方超收退款](原收款更正与供应方超收退款.md)，处理已经有明确冻结组合规则的录入错误；不新增客户债务、坏账、损失处理或集团实际资金清算模块。

## 办理条件和事实

财务在“业务财务结算 → 更正预收／会员充值”选择本店原组合入款。选择项显示组合名称、原每份本金，申请必须明确原购买批次；后台将正确总本金换算为原每份本金的非负整数份数。不能改冻结价格、改变赠品比例、混用其他批次或修改原到期日。

另一位经理在本单凭据齐备后批准。批准时同一事务锁定会员本金及各原赠品批次，并对负差额同时占用本金和每类原赠品；财务执行时重新核验当前来源、原份数、可用单位、期限及本单收退款凭据。原现金保留，追加误记冲正和可选正确重记；本金与每类原赠品差额分别追加，不增加实际退款或营业核销。正确金额为零不生成零元现金。

|场景|可办理结果或针对性拒绝|
|---|---|
|原完整份额尚未使用|可把三份改成两份或零份，同时追回各原赠品对应单位。原发行、原规则、原本金记录均保留|
|已使用一部分赠品|仍有完整一份可回收时可纠正这一份，原核销及内部结算不变；需要追回已用单位时明确拒绝，须先通过原服务／兑换业务合法回退，不能借其他批次或假造消费撤销|
|已经有真实部分退款|正确总份数及本金须覆盖已实际退回和批准待退责任；可更正剩余完整份额，保留每笔旧退款账户、现金和原赠品回收。后续真实退款按执行时有效的原收款账户办理|
|同金额换账户、流水或日期|现金追加纠错，权益差额为零；不重发、不改变剩余权益或有效期。原账户／凭证与当前有效账户／凭证分别展示|
|正确份数增加|只有原组合仍是当前启用版本、在发行期内且各原权益未过期时才能补记；新增单位仍属于原批次，保持原到期日，新增积分按既有原消费积分回收规则处理|
|原组合停发、被新版本替换或原权益已过期|不允许补发正差额；可以同金额改账户，或追回仍未用的负差额。不会自动恢复销售或延长有效期|
|批准后未执行|可拒绝或取消，只释放本申请的本金与原权益占额；即使发行期结束仍可以释放。实际已执行的记录不提供删除|

新单默认两日预计办理，经理复核后交当前门店财务待办。超时只提示，不自动扣减、退款或批准；责任交接仍走明确转交。版本过期、同一请求号内容冲突、跨店或非经办岗位请求均由接口拒绝。

## 原始记录、统计与恢复

`RechargeBundlePurchase.shares`、原 `GroupEntry.topup`、每个 `BenefitWallet.initial_units`、原赠送流水和到期日保持不变。原钱包增加累计 `correction_units`，有效发行量为 `initial_units + correction_units`。差额流水使用独立非现金的 `BenefitEntry.purpose='correction'`，每项关联原赠送流水和本次财务申请，不产生额外现金或核销结算。

追加迁移 `a79n_recharge_corrections` 下接 `z68m_rework_extensions`。三个不可变表分别记录财务申请与原组合、每项原赠品差额、差额的实际账本关联；旧迁移不改。当前现金口径 5 和月结定义 17 纳入套餐纠错，现金 4 与旧月结 16 及以前维持原来源约定。月结仅冻结三表，不另造钱包缓存快照；当前钱包缓存由完整恢复按不可变差额重算。

组合现金表按有效原本金减实际退款统计；误记反向记录不当现金支出。赠送金额、积分、券、套餐分别列原发行、实际退款追回及更正差额，各自保持原单位；图表、下钻明细与 CSV 使用相同行。普通预收余额、集团本金余额及赠品上限也分别校验，不能混算。

恢复校验核对原购买批次、冻结价格和份数、完整组件集合、每份单位、原钱包及原赠送、原到期日、零／正／负差额执行次数、缓存总量、批准占额和原实际退款账户。移除整套更正关联表也不能让已有更正流水被视为历史无扩展数据。
