# 员工操作与文件填表 · 2026-09-24

本轮继续减少原业务中的重复选择和离开表单补资料，沿用原 193 项需求及已确认的范围排除。本轮没有新增数据库迁移。业务助手使用固定业务表单及原办理接口，不运行模型生成的代码。

“已实现”“自动验证通过”“业务验收通过”“正式启用”分别记录。本文记录当前专项结果，不替代最终冻结源码的全量报告；公司试用尚待反馈。

## 一、从本地文件开始填表

入口为 **业务助手 → 资料整理**，或 **从文件填表**。员工明确选择文件或文件夹后，系统解析预览；员工勾行或选择文字、填写目标、核对发送内容后，才将选中资料交给 DeepSeek。缺项通过对话补充，生成的办理卡片仍须员工确认。

| 已实现 | 保留的边界 |
|---|---|
| CSV/TSV、普通 XLSX/DOCX/TXT 的表格与文字预览 | 解析仅在当前服务处理明确提交的文件，不读取用户输入的服务器路径、不扫描磁盘、不自动保存为业务凭据 |
| 按文件、表格、原行号核对并勾选；多页分批 | 不静默截断发送资料；超过 6000 字符要求减少选择；第一次预览不调用模型 |
| 对话补资料、待确认卡片、原单链接 | 原岗位、门店、版本、幂等、审批和账目规则不变；模型不会直接提交业务写入 |
| 预览表及填写卡片下载 CSV，提取文字下载 TXT | 生成新下载文件，不覆盖或自动回写源 Excel/Word；导出不是业务完成凭证 |

限制：每次 20 文件、单文件 5 MB、合计 20 MB；普通表格最多 1000 条数据、50 列、单元格 2000 字符。PDF、OCR、扫描件、宏、加密文件、Excel 外链及嵌套/合并 Word 表格不支持。公式留空并提示，不能凭缓存值生成金额事实。详细操作见 [本地资料与业务助手试用](本地资料与业务助手试用_20260924.md)。

## 二、库管在原表分配库位

已接入 **采购 → 分批验收到货**、**维修 → 按授权配件发料**、**维修 → 原领料退回**。

1. 打开原办理表，选物资或原领料，填本次数量及凭据。
2. 点 **分配库位**。系统带入物资和本次数量；只有一个可选物资库位时预填，多库位由员工分配。
3. 核对“还差”“超分配”或“已分配完整”，点 **保存库位**。数量和凭据保留在原表。
4. 核对原表，最后确认实际收货、领料或退料。保存库位本身不入出库，也不占用库存。

改变原表数量后必须重新分配。其他员工更新原单，或保存结果因断网不明确时，关闭表单、刷新原单核对后再办；不会自动用新版本重做实物动作。

尚未接入的实物步骤仍使用原单 **准备物资库位** 页面。其中，采购退库涉及同一物资多个原到货批次时，仍须按原批次安排并通过独立库位页面准备，不把多批次原成本或退货记录合并。

## 三、主管确认维修费用承担

原维修已完成本版客户授权和质检后，打开 **确认费用承担**。

1. 普通客户自付，明确点 **客户全额承担**，系统才带入当前授权总额。
2. 有保险、厂家或内部承担时，点相应 **添加** 按钮，填写实际单位、金额和到期日。保险、厂家目录按需要读取。
3. 不承担的栏目留空或填 0；不会生成无效的零金额承担记录。核对合计，补本次人工成本并选择或在表内上传承担凭据。
4. 点 **确认承担并交财务**。已有核赔的工单显示对应单位与当前结果；不会默认全额给客户，后端仍核对核赔金额及原单位。

内部返修和关联原单返修仍使用原责任处理方式。确认承担不会自动收款，已冻结的承担不能直接覆盖，财务收款仍单独办理。

## 四、仓储退回选择原批次

- 在已办理仓储作业的 **本单实物收发** 行旁点 **退回这批**，直接带入原批次。
- 从仓储入口办理“其他入库退回”“耗材退回”“礼品退回”时，可以按物资、编码或原单号查找。
- 选中后查看原日期、原数量、已退和尚可退数量，再填本次实际数量、库位、原因和期限，提交申请。

申请、主管批准和实际退回仍分开；实际收回不默认回原库位。原数量上限和原批次成本继续由原规则处理，不手填或重算成本，不自动退款。采购和维修仍走各自的原单退回入口。

## 五、理赔缺少原款时有下一步

办理转付客户、客户原款退回、退给第三方或未转付款原退时，系统按本动作列出可选择的原款，显示原凭证、日期、账户和本次可办金额。

缺少到账或退回事实时，页面说明先办哪一步；本人可以办理时提供按钮，需要其他岗位时提示交给主管或财务。无需退款的责任调整仍需要办理方案生效并关联本次凭据。

混合返还方案分别处理已转付客户款和未转付款；不得用普通账户余额替代原款。外部核准不代表收到现金，原账户、原方案及独立批准要求保留。
