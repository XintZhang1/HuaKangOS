# DealerDesk 0.2 — 门店使用说明

## 登录、门店与账户
管理员进入「门店管理」建立真实门店，再进入「账号与权限」创建员工登录账号，勾选可访问的门店并选择部门角色。新账号首次登录必须修改临时密码。请给每个人独立账号，不要多人共用管理员。

顶部的门店选择框决定当前录入归属。一个员工账号可授权多家门店，但在各店使用同一个部门角色。管理员自动拥有全部启用门店；店长、财务、审计可以只读汇总自己已获授权的门店。销售、库存和售后员工逐店操作。跨门店汇总不能录入、审核、改账或生成单店日报。

停用账号、重置密码或修改权限会撤销原会话。停用门店后，普通员工不能继续访问该店。停用门店目前不参与启用门店汇总；管理员需要查看历史时可重新启用。这里的「账户录入」是员工登录账户，不是外部银行账户的自动连接。

## 业务录入
销售、新车库存、维修工单、保单、收支流水分别录入。先保存草稿，核对后提交，交给另一位有审核权限的人处理。店长不能审核自己录入的单据；管理员自审会留痕。已审核记录不能直接修改金额。

不同门店可使用相同单据编号，但集团内 VIN 和保单号码保持唯一。本版禁止把甲店的车辆直接关联到乙店销售单，也禁止将甲店的收款关联到乙店单据；车辆调拨与跨店往来需单独设计，不能通过改门店字段绕过。

## 看板与日报
右上角选择「已授权门店汇总」查看合计看板和分店对照。分店对照为所选结束日期的当日指标，不是整个日期区间的累计。

经营汇总只统计已审核单据；销售合同、实际收款、保费代收、预计佣金分开。直接毛差不是净利润，不构成完整会计总账。合计看板是门店简单汇总，不自动抵销集团内部交易。

定时任务按门店分别保存前一天日报，默认北京时间00:15，启动后最多补最近7天。电脑与服务必须保持运行。规则检查由程序执行，DeepSeek 在允许外发时整理脱敏经营摘要。改进意见的代码生成和日报摘要是两套独立开关。

## 提交系统改进意见
进入「改进意见 / 版本发布」，说明出现问题的页面、复现步骤和期望结果。可以导入UTF-8的TXT或Markdown文本（最多48KB，正文最多12000字符）；文件内容进入意见正文，系统不保存可执行附件，也不支持截图、Word/PDF等附件分析。

不要输入客户姓名、电话、VIN、密码、API Key或真实财务明细。意见文本不会自动识别并去除其中的所有敏感内容；只有写入意见的人能确保没有泄露。未勾选外发授权时只保存意见，管理员可再次授权入队。普通员工只看自己的意见，管理员按门店范围管理。

自动维护启用且配置正确时，DeepSeek只获取这条意见和白名单前端/文档源码。它生成精确文本修改，不拥有Shell、Git或数据库工具。默认只能自动处理界面展示、样式和使用说明，后端、安全、账务、数据库、依赖或超范围需求转人工。

测试通过后才推送候选分支并发飞书卡片。负责人查看Git改动并批准后，系统备份数据库、短暂进入维护状态、检查新服务并切换版本。拒绝或不批准则不发布。刷新网页后使用新界面；不要在发布窗口继续提交未保存表单。

发布成功后的飞书卡片提供回滚。回滚只恢复代码，保留发布以后录入的业务数据；不会把旧备份覆盖当前数据库。默认卡片24小时有效。代码修改影响整套系统，不是只影响提出意见的门店。
