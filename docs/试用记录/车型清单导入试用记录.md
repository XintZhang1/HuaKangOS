# 用"比亚迪车型清单.xlsx"试业务助手导入 · 2026-09-25

> 一次性实例上的实测记录（真实 deepseek-flash + 原接口 + 确认卡真的点了）。不是公司验收，也不含真实客户资料。

## 一、给助手的东西

`docs/试用记录/比亚迪车型清单_导入用_20260925.xlsx`（7.7 KB，两个工作表）

- **车型清单**：67 行 × 14 列 —— 品牌 / 品牌编码 / 车系 / 车系编码 / 车型 / 车型编码 / 年款 / 动力类型 /
  动力代码 / 座位数 / 排量(ml) / 电池容量(Wh) / 指导价(元) / 备注
- **说明与来源**：口径、来源链接、列说明、留空原因

数据来源（2026-09-25 抓取，公开页面，价格=厂商指导价）：

- 王朝网：[易车王朝网经销商报价页](https://dealer.yiche.com/100018768/news/202609/1468241855.html)
- 海洋网：[爱卡 比亚迪海洋车型库](https://newcar.xcar.com.cn/b30/car_t3_o2.htm)

范围：王朝网 55 条具体配置（2026/2027 款，含指导价）+ 海洋网 12 条车系（起步指导价或"未核实"）。
**没有可靠来源的数字一律留空**（电池容量整列留空、部分车系价格留空），不编造。

## 二、助手实际怎么做的（两轮）

**第一轮**（只上传表格 + "先告诉我怎么建，先别动手"）：

- 正确读出 67 行 × 11 列（当时还没有编码列）与说明表，并指出两个缺口：**编码列缺失**（品牌/车系/车型编码系统必填）、**电池容量对纯电车型为空**。
- 给出正确的三层顺序：车辆品牌（1）→ 车辆车系（按车系）→ 车型参数（每条一行），并说明"品牌和车系必须先建好拿到真实编号，车型才能挂上去，不能一次全建"。
- 指出动力代码 `electric / plugin_hybrid` 正好对应系统选项，备注列系统没有对应字段会自动忽略。

**第二轮**（补上编码列，回答"编码按清单、电池容量先按 0"）：

- 准备了**品牌卡**；我点确认后，实例里真的建出 `品牌 比亚迪（编码 BYD, id=1）`。
- 车系卡它**没有**接着准备，理由是"车系要挂到品牌下，需要品牌的真实编号，等你确认品牌这张、系统生成编号后我才能准备"——**这正是我们要的"前序没完成不往下走"**。

## 三、两个要你拍板的点

| 问题 | 现状 | 可选做法 |
|---|---|---|
| 电池容量(Wh) 空 | 我没有可靠来源，不编数字；助手说系统这项对纯电"必填"，不接受 0 糊弄 | ① 以官网配置表为准逐款补；② 允许先按 0 建、之后在车型页补（数据库默认就是 0）；③ 导入时跳过纯电车型，先建插混 |
| 车型与车系的挂靠 | 助手读到的车型字段是"品牌（文本）"，没有"车系"选择项；而写库接口其实接受 `series_name` | 我可以先查清 `POST /api/vehicle-catalog/entry` 到底按什么挂车系，再把清单列名对齐，减少助手的来回确认 |

## 四、你想自己在预览里跑的话

1. 预览里进"业务助手"，上传这个 xlsx，然后发：

   > 这是比亚迪车型清单。请按"品牌→车系→车型"建立车型目录，编码就按清单里的（品牌 BYD、车系 YUANUP、车型 YUANUP-2027-01 这种），电池容量先按 0，之后我在车型页补。**从元UP开始，把品牌、车系和这 5 条车型的确认卡都准备好**，我逐张确认。

2. 它会先说计划再动手；点掉品牌卡后它才准备车系卡（需要真实编号），车系建好后才是车型——67 行建议按车系分批。
