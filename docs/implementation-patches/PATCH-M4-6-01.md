# PATCH-M4-6-01：单次 Run 的必要队列与外发接线

日期：2026-09-28。适用：R4-20260928 / M4.6。依据用户“批准，后续授权不用再问我，都默认允许”，先登记精确范围，再实施与独立源码审阅；不重复申请授权。

## 范围与原因

原 M4.6 已要求跨恢复预算、每次模型外发复验及后台在完整工具边界让出。仅 runner 薄接线无法满足：provider 非流式路径会自行重试一次 POST；queue 入队用户消息当前立即对背景 Run 设置 stop_requested，导致正在办理的完整工具无法保存；现有 release 的 retry 仅适用真实瞬时错误，不能借它伪造优先级让出。

除 M4.6 原允许的 runner/service/prompt 外，仅补充：

- `app/assistant_runtime_provider.py`：为内部 `call_model` 增加可选的服务端外发前回调，每个实际 POST/stream（含已有一次重试）先调用。回调失败直接向调用方传播，不作为传输失败重试；legacy wrapper 不传回调，原模型参数、端点与重试上限不变。
- `app/assistant_runtime_queue.py`：用户入队保留原优先级，去除将普通输入等同显式取消的即时 stop；增加真实高优先用户候选检查及完整工具边界的后台让出。保留同 Run、原 request_id、usage 与所有工具成果，释放原 busy/lease，经原领取过程重新获得新 fence。让出不伪造 runtime_unavailable、不消耗故障重试额度。增加以现有 Run.usage 保存本轮预算与安全 usage 的固定内部接口；所有写入使用原授权/租约/fence/CAS，不添加列、状态或任意写入入口。

独立同库 Session 调用原 heartbeat 即可时直接复用；不为此改变90秒租约、20秒心跳、单执行槽和原故障退避规则。具体内部签名由 runner 与 queue 作者对齐后记录实际源码，不提供模型/HTTP调用入口。

2026-09-28接口审阅补充：Run.attempt仍记录真实领取次数；仅固定安全让出事务可单调增加usage中的yield_count，release与reclaim统一以attempt-yield_count计算故障重试档位。没有该ledger的旧Run仍完全使用原attempt；不降低attempt、不清空故障历史、不延长原三次故障/30、120、600秒退避合同。固定预算接口预留轮数后才可外发；真实新增准备数通过无commit接口与卡片事务一起保存。持久usage只收安全计数/枚举/服务器时间，不收模型内容、reasoning、凭据或客户端任意字典。

集成审阅发现：`release(outcome='retry')`可能因原安全判定或额度耗尽而实际进入failed，须在同事务追加最终回复。因此仅将既有`before_finish`服务端同步回调扩展为可由retry传入，分类后的真实target为failed时才调用；target为queued时绝不调用，cancelled仍禁止。共用原严格终态事件cap、原唯一消息键和最终验权，不能先提交failed再补消息，也不能为写回复放宽安全重试或将所有503改成永久失败。

## 状态与异常

- 合法后台 Run 在完整工具边界发现可领取的更高优先员工输入：running → queued，成果及预算保留；不写最终回复，不代表业务完成。正常用户入队不再触发权限停止。
- 真正停止、撤权、目标结构变化：沿用原即时阻止新成果和控制取消，不能因优先级补丁推迟安全守卫。
- 每次实际模型外发前，重新检查当前身份、门店、来源授权、目标、租约/fence和剩余预算。回调拒绝时该次请求不发出，不能自动降级到无回调路径。
- 进程重启仍使用同 Run 的预算；已预留而无法确认返回的请求保留占用，未知 token 仍为 unknown，不能记为0或重新获得完整轮数。
- 预算耗尽保留原卡、完整未完行及原因，原请求号最终回复与终态同事务。让出时不借虚构错误触发原安全重试，不放宽原未知确认拒绝。
