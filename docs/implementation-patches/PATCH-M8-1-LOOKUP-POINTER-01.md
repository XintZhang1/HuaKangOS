# PATCH-M8-1-LOOKUP-POINTER-01：候选展开时的原生鼠标提交

日期：2026-10-01。全新外部 IAB `business-manual-presales-20261001-02`，390px接待新增成功；768px主管原分派表单输入员工名称但不选择候选，必填进度已正确显示。原生鼠标点击提交没有显示校验，键盘提交才显示“请核对：接手员工。请从列表中选择”。本轮保留失败，不将键盘绕路记通过。

已观测提交按钮从 y=698.84375 移至654.17712，向上44.66663px。原因是原 `focusout` 在 pointerdown 转移焦点时立即收起 `position:relative` 候选列表，居中表单在 pointerup 之前移动，释放点不再落在提交按钮。原员工值为空、原customError和后端守卫仍有效；不是业务权限放宽。

精确允许范围：`web/livechoices.js`，只在真实指针按下期间、焦点转到原表单按钮等非空目标时，保留候选布局至原 document click 的外部收起循环；仍即时作废迟到搜索。以捕获阶段 pointerdown/up/cancel 与窗口blur记录指针状态，不把普通程序focus等同鼠标。纯程序移焦、Tab/Escape、空目标blur仍原收起，不引入计时器、重试、自动选择或值注入。`tests/browser_click/sales_business.py`在390/768/1440px各重新打开原分派表单，实际鼠标拒绝未选候选，无POST且完整原业务摘要不变，之后正常选员工继续同一业务。根实施计划M8.1、本任务页及审阅说明追加事实。

异常边界：候选内点击仍可选择；选择后修改文字仍清空原select；取消仍允许放弃填写；纯程序移焦不留候选；指针取消和窗口失焦清指针状态。拖动释放未生成click时沿用下次外部click/Tab/Escape关闭，不声称拖动是提交。生产四开关、业务API、数据状态、角色权限和原确认合同不变。

验证：三个宽度使用全新原表单，不能复用已有错误文字冒充鼠标触发。IAB另核768px原鼠标路径；相关定向和注册场景在全新外部镜像执行。未执行前不记passed，193全业务、PostgreSQL/Linux、真实模型与员工试用边界保留。
