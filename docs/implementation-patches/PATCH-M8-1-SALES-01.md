## 原因与约束

原服务 `CURRENT_ORDER_VERSION=4`、`is_quoted` 支持 3/4，而适配器只登记 3。原详情未提供可证明 Consent/报价/VIN/签回源的完整关系；原交付动作写入 `handover_file` 而非适配器猜测的时间字段。扩展原已授权 GET 的最小布尔/未知投影，不增加写路由，不给助手数据库权限，不扩大岗位或附件可见性。

批准、客户签回、实际交付分别判断。无权限/缺失证据/扫描不可用为未知，不当作否定事实。新报价在办时不以旧报价签回证明新意图；撤回后可重新核对原有效版本。当前 Consent 必须对应当前报价、VIN、签回文件及源文档指纹。交付必须核对原 deliver 事件、完成任务、实车占用交付标记及本单签回件；状态字符串、上传、收齐、出库均不充分。

## 验证

使用原 HTTP 创建车型/明确归属/订单，独立主管原接口批准、配车、生成/上传签回、确认、收款、检查、出库、交付；加入换报价/撤回/换车、隔离附件、岗位脱敏、跨店、过时/畸形投影、只读无副作用以及计划条件的正反例。v3 兼容样本单独标记为历史合成库版本，不宣称原当前 API 创建了 v3。所有数据仅在仓库外随机合成环境；不改旧失败证据、不降低原权限和状态机守卫。四个默认开关不变，不运行真实模型。
