# b80o 会员等级实际定价：实施与验证

来源：HK-121 / HK-188。候选目录实施；原目录和 8000 预览未改。迁移 `b80o_member_pricing`，父迁移 `a79n_recharge_corrections`；旧迁移未改。

## 已批准的产品边界

集团会员身份和有效会期决定会员是否符合某个等级，本店独立批准的价格规则决定本店哪些项目实际打几折。两者缺一不可。没有本店批准规则时不会自动打折，也没有替公司填写比例。`MemberTier.discount_basis_points` 仍是参考主档；界面明示需要独立价格批准，可引用其 id / version / rate 作为参考证据，再明确逐项实际比例。

实际入口覆盖 repair/v3-v4 普通维修和返修新增自费、retail/v2 商品与安装及明确允许的精品套装、addon/v3 商品与安装。旧报价没有会员快照时保持原金额与摘要，不把新字段补进旧事实。原责任返修 `original_liability` 不参与折扣；`customer_extra` 可以按批准范围选择。已购买维修套餐 `package_contract` 组件同时排除会员折扣和人工优惠。

## 员工办理与事实

主管建立本店价格版本，明确集团会期原版本、有效日期、每一实际商品/工时项目、整数万分比例及叠用方式，可附参考等级。草稿未生效；申请人提交本次凭据后生成另一主管的独立批准待办。提交和批准必须使用不同原件，管理员也不能自批。引用项目在审批期间变化须重新申请。批准版本不改写，停用/修改通过同编号新版本独立批准。乱序批准旧申请、陈旧版本、重复同键变更、跨店引用、未扫描原件均拒绝。

前台报价时明确选择本次价格规则。后端在同一事务校验本店客户的已确认共享身份、启用会员、当前实际会期和等级、本店适用范围、最新生效本店价格及逐项范围。冻结原会期、规则版本、原明细基价、会员折让、另行人工优惠、净额和责任类别。报价仍进入原域主管最低价格审核及客户本版原件授权；授权前再次核对有效会期和价格版本。过期、停用、变级或新价格批准会拒绝尚未授权旧报价，不暗改其金额。单纯充值导致会员版本变化不会使语义不变的有效会期失效。

已授权金额不因之后变级/停用重算。维修开工后增量只对本次新增收费定价，原已授权量原金额承接。加装已授权固定行不重定价，新行另报。原工单的人员交接、逾期待办和取消/停工/原退仍由原域办理；会员价格没有另设自动生效或超时自动批准。规则尚未批准可取消，批准后用新停用版；价格的实际领料、施工、质检、验收、结算、退款仍逐项实际确认。

## 金额与权益

金额整数分，物资数量整数千分。新增组件会员净价为 `(basis * basis_points + 5000) // 10000`。正价经会员比例舍入为零直接拒绝，需另行适当价格或原域赠送授权。会员优惠之后再以整数最大余数分配人工优惠，仅新增可收费部分参与。历史承接量、原责任返修与已付套餐合同不参与此分配。

规则的叠用模式必须显式选择：

- `member_then_benefits`：折后原剩余容量可按已有券/套餐/赠金原规则占额和核销；不改其原 C/P/S 或固定单位。
- `exclusive_benefits`：实际取得此会员折让的项目不能再使用券/套餐/赠金；本金仍是正常支付。精品按实际匹配的组件排除容量。旧维修标量权益不能定位任意行时保守拒绝与该报价冲突的新增券包。已购买混合套餐履约通过明确合同组件独立核销，不冒充新增券包折扣。

折让不是现金、余额、发行收入或内部结算。精品套装保留每套原 C/P 分摊及原数量，会员价必须指明该套装版本；原退以本次实际折后商品与安装金额累积分配，不回到折前参考价。新付款和退款继续使用唯一 CashEntry 及原账户，不伪造现金或发票。

## 数据和集成协议

六张本店附属事实表：`member_pricing_rules/scopes/decisions/snapshots/lines/authorizations`。快照 `definition_version=1`；未改旧报价表列。报价合同保留 `price_source`、`contract_rule_id`、`contract_component_id`，套餐领域的原组件恢复接口独立证明合同基础。

主要函数：

- `candidates(db,user,row)`：本店真实客户的明确可用规则，无其他店钱包或历史。
- `prepare_quote(db,user,row,selection,components,manual_discount_cents=0)`：返回合同或 None，不提交事务。组件包含 line_key/component/source_id/basis_cents/carry_cents/charge_scope，及可选 bundle_rule_id、合同字段。
- `freeze_quote(db,user,row,quote_kind,quote_id,contract)`：与原报价同事务冻结。
- `guard_authorization(db,user,row,quote_id)`、`record_authorization(db,user,row,quote_id,evidence_id)`：授权前语义检查及本版独立原件绑定。
- `benefit_exclusions(db,row,kind)`：返回实际互斥 `(line_key,component)` 集合；`guard_benefit_use(...,component_keys=None)` 支持明确组件检查。
- `describe_quote(...)`：沿原域金额岗位权限投影本次折让，不扩张会员履历或其他店金额权限。
- `member_pricing_integrity.validate(connection)`：独立重算规则、批准时点、会期、原新增/承接金额、整数优惠、报价摘要及客户授权。若已有价格 Case/事件却删除全部六表，拒绝伪装旧库；真正旧库无新事实允许为空。
- `member_pricing_analytics.build_member_pricing(db,user,cases,stores,bounded,yuan,in_period)`：同源表/图/CSV，集团仅门店和汇总数量金额。

API `/api/member-pricing/catalog|candidates|rules`；规则 `/rules/{id}` 和动作 `/actions/submit|approve|reject|cancel`。列表详情、附件及后台配置仅本店财务/主管类；报价候选给原业务前台。原单 safe_data 仅规则 ID。前端 `memberPricingPage(id)`，导航 `member-pricing[/id]`。公共 catalog 的 `capabilities.member_pricing` 单独声明报价能力，旧后台缺该能力时不请求新 API，不选规则时旧报价请求不新增字段。

月结定义 18 起纳入六源明确字段，金额均为 0，仅证明价格来源；旧 1–17 摘要不扩展。后续月结定义保留这一范围。统一发票/收款以原工单折后金额为依据，不重复计折让。

## 报表定义

`member_pricing_current_quotes`：当前正常已授权报价的会员折让，按其当前授权日期筛选，每单只一版；继承仍存在的原行优惠。等待授权的增项不重复增加，已取消工单和停工报价排除。这里是当前价格事实，不是期间实际消费优惠、营收或现金；实际退货不反写原授权价。集团投影没有客户、会员、会期、规则、原单、报价 ID 或 route。时点均由 UTC 时间按公司 `APP_TIMEZONE` 转业务日期，再判断会期、规则和统计期间。

指标 `current_authorized_member_discount_cents` / `current_authorized_member_quote_count` 不加入营收或现金。表、图、CSV使用同一行群体。
