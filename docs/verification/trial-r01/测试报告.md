## 改了什么，为什么

| 文件 | 作用 |
|---|---|
| `docs/trial-source/world.json` | 虚拟经营世界（星驰汽车，两家直营同级门店、10 个岗位账号、5 位客户、5 台 VIN、5 种物资、主档与金额日期约定） |
| `docs/trial-source/rounds.json` | 41 轮登记：每轮的模块、带冒号大功能、虚拟需求、前置、前置不足时的替代做法；R01 含数据、步骤、分支、观察点、核对 |
| `scripts/build_trial_guides.py` | 生成 `docs/试用脚本/总表.md`、`docs/试用脚本/Rxx-*.md`、单文件 `docs/试用操作手册-XC.html`；`--check` 校验逐字节 |
| `tests/test_trial_scripts.py` | 14 项校验，见下 |
| `docs/试用运转说明-XC.md` | 环境、每轮怎么跑、反馈格式、判定分类、提交与 PR 约定、重启与刷新协议 |
| `docs/试用记录/试用问题台账.md` | 反馈登记台账（判定六类 + 状态）与原始反馈记录 |
| `docs/试用材料-XC/*.txt` | 6 个模拟凭据（采购合同、收付款、验收检查、客户确认、实物交接、整改），内容标明“试用” |
| `README.md` | 补两处：预览库按源码目录路径绑定（换目录会重新要求设管理员）、文件导航新增试用入口 |

**为什么用“JSON 源 + 生成”**：脚本里的岗位、页面路由、搜索词、需求编号都要和真实系统一致。生成器直接从 `docs/requirements.json`、`docs/workflow-source/{business,services,coverage}.json` 和 `web/app.js` 取事实，`--check` 保证生成物和源一致；以后我们改按钮文案或入口时，脚本能一键重建，不会出现“脚本里的按钮在页面上不存在”。
