# huakangos · 维修实际领退料分析（HK-149）

入口“维修实际领退料分析”按实际领退料日期，查询原维修单、配件、冻结车型和原报价作业。它补充“最终报价配件”统计：客户授权或报价尚未形成实际领料时，不增加本报表数量和成本。净领料是已领未退的原账数量，不能据此断言每件配件已经施工耗用。

## 来源和期间

明细维修 v3／v4 通过 `RepairStock.stock_move_id → StockMove` 取实际业务日期、数量、原账价值，通过原 `quote_id + line_key → RepairLine` 取当时配件名称、单位和报价版本。对应报价必须有相同摘要的客户授权。原报价金额、单位销售价、最新报价数量、当前配件成本均不替代实际流水。

显示方向按维修领用理解：库存发出转为正领料，实际退库转为负领料。每次退回追溯同工单原领料，数量和金额冲回原成本；分次全退后原量与原成本必须全部冲回。退料属于退料实际日期，跨月退料会使本期净量或净成本为负，并不自动改写上月领料日期。

```text
期间净领量 = 期间实际领量 - 期间实际退量
期间净领成本 = 期间原领成本 - 期间原退成本
```

已有通用维修子单 `material_issue / material_return` 的真实 `StockMove` 可以作为历史原账列示，但不补造 `RepairLine`、作业和车型。仅有旧维修金额、车牌或自由文本而没有库存流水的历史记录，无法推断真实物料数量；“暂无实际记录”不是“历史没有耗用”的结论。

期间来源缺失、数量／原成本不一致、原退关联或日期错误时列出具体差异，不生成完整成本图或净成本指标。已读到的库存原行保留供核对。差异不会因选择某作业或车型而悄然消失；其中未能关联所选维度的来源仍需要人工核对。

## 冻结车型和作业筛选

新增车辆绑定在同一事务追加不可覆盖的 `repair_vehicle_model_snapshot` 事件，保存来源 `CustomerVehicle` 编号、版本、当时车型名称和与绑定相符的 VIN。车型没有新增员工填写字段，直接来自此次已核验的车辆档案。转换预约失败或重复请求不会重复生成绑定或车型事件。

之后修正车辆主档名称不会改变历史报表。旧绑定没有该事件时显示“历史车型未知”，不能用当前名称反查或补填当年的车型。新增加的、有凭据的旧维修身份绑定也只表示本次绑定时冻结的车型资料，不能证明名称在更早领料日就已如此。

作业筛选的准确含义是“这笔原领料授权报价包含所选作业”。同一报价可能有两个作业和一条配件，但没有证据说明配件成本各属于多少；系统采用半连接筛选，每笔原库存流水只出现一次。不按作业数量复制领料，不用比例猜测逐作业消耗或成本分摊。增项后领料使用各自原授权版本；原退仍使用原领料版本，不改挂最新报价。

## 权限和使用

| 岗位 | 查询范围 |
|---|---|
| 库管 | 获权本店实际数量、原单和冻结维度；页面、API、CSV 隐藏原成本 |
| 主管、财务、审计、管理员 | 获权门店数量和原成本；成本不是售价或客户承担额 |
| 其他岗位 | 本独立统计接口拒绝访问，原维修办理权限不因此改变 |

集团只读汇总按已授权门店查询，不返回原单跳转，也不增加对店客户、VIN 档案或附件权限。筛选选项取获权实际原事实，不从任意电话或共享车辆身份扩大查询。

开始／结束日期及原单、物资、车型、作业可以组合筛选；倒置或未来日期用中文拒绝。前端保留原条件供改正，按 25 条分页并支持手机卡片。最大期间跨度一年，相关源表最多 25,000 条，超限拒绝而不静默截断。指定原单会缩小原账查询范围。

图表按冻结车型汇总净领料原成本，未知车型独列；其数值来自同一“实际维修领退料净量及原成本”表。不同单位数量分别保留在各配件行，不把升、件等相加。CSV 使用相同构建器和筛选条件；支持原始流水编号和获权原维修单下钻。报表在同一数据库快照中读取，并发实际退料不会把两次状态混在一个合计里。

## 文件和接口

- `app/repair_material_analytics.py`：`build_repair_materials(db, user, start, end, case_id, item_id, model_name, work_item_id)`，返回来源差异、冻结维度、图表、同源表格和独立指标。
- `app/repair_material_api.py`：`GET /api/repair-material-reports`，`GET /api/repair-material-reports/export/{table_key}`，参数 `date_from/date_to/case_id/item_id/model_name/work_item_id`。`model_name=__unknown__` 显式查询旧绑定未知车型。
- `app/service_intake_service.py:_bind`：原绑定事务追加车型快照，无回填迁移，不改变维修流程版本。
- `web/repairmaterials.js`：中文筛选、手机明细、同源下载和会话退出缓存清理。

## 验证与边界

`tests/test_repair_material_analytics.py` 验证：报价不冒充实际领用、原成本部分／全部退回、跨期负净量、多作业不重复、车型改名后快照不变、旧绑定未知、快照不可改、重复请求、过期版本、转换失败、库存与维修关系损坏、岗位成本隐藏、串店 ID、集团只读、历史通用维修原账、并发快照，以及图表／明细／CSV／经营组合报表一致。

`tests/browser_repair_materials.py` 在全新隔离合成数据库、随机密码、真实 Chrome HTTP/Cookie/CSP 中，以库管和主管的 390 像素网页核对原量、原成本、车型及作业筛选和实际下载，检查具体中文日期错误。证据只写临时目录，仓库不含真实客户截图或密码。

未实现的含义保持明确：此报表没有逐配件对应施工项目的成本分摊凭据，没有补录旧绑定历史车型，没有把实际领料等同于实际安装耗用，也没有把业务原成本变成会计结账成本。这些不是本报表自动推断的数据。自动测试通过仍不代替公司业务验收和正式启用。
