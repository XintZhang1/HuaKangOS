# 剩余验收与公司规则

本说明把“已有默认处理方式”“公司尚需决定的变体”和“正式环境仍需验收”分开。默认范围的实现、自动模拟、公司业务验收和生产验收是不同结论；最终自动验证结果以总验收记录为准，公司业务及生产验收目前仍未验证。本机预览已升级并保留原账号与资料；正式启用仍待验。

今晚可先用现有管理员在本机试用，见[晚上试用指引](晚上试用指引.md)。下面的公司规则可以结合试用逐项确认，正式环境事项在相应落地阶段安排。

## 四类公司规则

| 事项 | 已实现的默认范围 | 需要公司确认的变体 |
|---|---|---|
| 其他车辆出库用途（HK-025） | 明确用途、独立主管批准、按车架号确认实物出库；原单退回保持原成本并建立新的库存记录。 | 公司“其他出库”具体包括哪些用途：是否包括试驾、借车、报废或变卖；各自的归还要求、凭据、审批及收款方式。通用出库不能自动代表这些用途各有完整专用流程。 |
| 已用充值组合的退款（HK-123） | 充值组合默认关闭，由版本化规则明确本金及赠金、积分、券和作业次数；发行时冻结。可退尚未使用的完整份额，并回收该份原赠品；一部分份额已用，不妨碍其余符合条件的完整份额按原规则办理。 | 已使用的单份如何退、是否重算已用赠品或追价、已花积分怎样处理；若组合内多项分别收费，如何分摊实际售价与退款。公司先定具体条款，系统不自行推断追偿金额或额外债务。 |
| 特殊消费券类型及渠道（HK-129/130/131/132/169） | 会员持有的固定面额电子券：类型与版本、生成批次及张数、免费赠送、授权门店核销、原退、信息查询和统计。实际券名、面额、售价或赠送条件、有效期、适用门店、优惠承担及退款规则需按公司政策配置。 | 是否需要满减券、百分比折扣券及额外促销叠加、实体印券、单张外发券码、外部平台发券或会员互赠；需要时再明确核销、退款和渠道凭据。原表没有指定这些扩展，既不能默认宣称已覆盖，也不据此否定已实现的固定面额电子券。 |
| 会费金额与会期撤销（HK-090） | 已有续会收费及符合既有条件的未生效续会整笔原款退款。账户、凭证或证据登记有误时，可独立批准同额更正，固定原会员、金额、到账日期、会期及权益；以后的实际退款使用更正后的有效原账户，既有实际退款保持原事实。 | 金额收多、收少怎样补退；实际没有到账却误登记怎样处理；已生效会期能否撤销、已用权益和积分如何结算。不能用“同额登记更正”改变会费金额或撤销会期，也不能用虚构退款代替登记纠错。 |

这些待确认变体不是用户已经排除的需求，也不是今晚体验现有默认流程的前置条件。确认需要后，应写明适用情形、经办与批准岗位、金额或权益算法及原单凭据，再决定配置或补充分支。

消费券五项的原文、实现范围和具体证据见[消费券五项范围复核](消费券五项范围复核-e13r.md)；续会费同额更正的限制见[续会费同额登记更正](续会费同额登记更正-e13r.md)。两份专项说明均不能代替最终整树验证或公司验收。

## 后续验收

| 验收事项 | 仍需实际确认的内容 |
|---|---|
| 公司岗位与日常业务 | 由真实岗位确认责任分工、接手、权限、中文提示和例外办理符合门店习惯；自动模拟和管理员试用不能替代各岗位确认。 |
| 正式合同与表单 | 公司确认正式合同、报价、委托、验收及退款等实际使用模板的内容、经营主体、审批版本和签署方式，再核对生成、打印及签署件关联。示例模板通过不代表公司已批准正式文本。 |
| 期初资料 | 在正式开账日前核对门店、经营主体、账户、库存数量与成本、客户会员余额及其他需承接的原始资料；按批准来源试导、对账，再正式导入。未知历史保持未知，不把旧未完单自动推断为已完成流程。 |
| 一个完整经营与月结周期 | 用公司选定周期核对实际收支、采购及原退、会员发行与使用、跨店往来、发票、应收应付、月结和导出；检查跨期退款及更正仍能追溯原事实，并确认开结账责任。合成案例通过不等于真实月结已验收。 |
| 最终版本的真实 PostgreSQL | 如正式环境选用 PostgreSQL，在目标版本与实际部署方式下验证有数据升级、并发办理、完整备份和独立恢复。历史版本的 PostgreSQL 实跑记录不能代替当前最终版本验收，也不要求今晚本机试用先改数据库。 |
| 正式 HTTPS 与网络访问 | 在实际域名、证书和访问网络下验证登录、会话、权限、上传下载及代理配置；本机 HTTP 浏览器通过不能代替。 |
| 实际 ClamAV 与文件存储 | 验证正式查毒服务可用、危险文件隔离、扫描失败时阻止使用，以及采用实际存储方式后的附件备份与恢复。合成试用的文件结构检查不等于真实病毒扫描。 |
| 手机与跨设备使用 | 用实际手机、平板或另一台电脑，在预定网络下验证登录、拍照上传、下载、表格阅读、岗位交接和时间显示。电脑窄屏及真实桌面浏览器测试不代替这些设备实测。 |

正式使用前还应在目标环境完成一次可恢复的完整备份演练，确认资料与附件一起恢复，并明确日常备份责任。上述部署和公司验收按实际启用计划完成，无需把复杂部署作为今晚本机试用的准备工作。
