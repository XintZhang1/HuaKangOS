# 跟进与进出厂统计

原表 HK-136 只列“售前跟进分析”，HK-166 只列“进出厂统计”。本次提供现有业务事实可支持的售前事件及维修接待进出厂统计，不推断原表没有定义的员工绩效指标。

## 当前补充（q79d）

非维修有据实际进出厂、同一原进厂转维修、取消维修后的明确实际离场，以及独立纠正已接入本报告。见《非维修进出厂》。原来源表、图和CSV保持同源，新增 `gate_corrections`。售前阶段时长由 `presales_stage_analytics.py` 按原事件计算，重复跟进不重置，结束重开另段；未结束阶段单列，不当员工工时。下文标为历史的限制/浏览器证据仅说明原检查点，不代表当前测试结论。

## 业务口径

| 集合 | 实际来源 | 不计入的计划或状态 |
|---|---|---|
| 售前沟通与需求记录 | 售前原单的 `remind` 本次沟通结果、`intent` 购车需求、`follow` 本次沟通结果及原 `FlowEvent.occurred_at` | 新建、分派、未来回访任务、任务完成、当前意向状态 |
| 售前转预订与结束重开 | `reserve`、`close`、`reopen` 原事件，单独列示 | 不与期间沟通次数相除冒充同批转化率 |
| 普通、预约、快捷及洗车到店 | `ArrivalFact`，同预约、客户车辆、核对 VIN 及原到店凭据；已转单时同时核对维修绑定 | 预约时段、预约状态、转单事件、工位占用 |
| 原单返修到店 | 唯一 `intake_rework_convert` 原现场核验事件，与本次返修申请、维修绑定及本次凭据一致 | 返修申请或责任批准 |
| 未开单实际离场 | 同原预约唯一 `intake_leave` 及本单离场凭据 | 未到店取消、未到店结案 |
| 维修客户实际接车 | 按版本明确识别 `release` / `repair_v3_release` / `repair_v4_release`，核对原接车凭据及实际日期 | 完工、质检、收款、已完成状态、工位移出 |

一张接待单转换为一张维修工单只形成一次到店。本表按次数统计，不将同 VIN 不同到店混为一次，也不按客户或车辆当前名称改写历史。完整的到店—离场记录可以计算经过分钟数；这是两次记录之间的时间，不是施工工时。

期间按系统配置时区确定。期间进厂、出厂分别按各自实际日期选择，出厂可能关联前期到店。本期间到店批次的后续结果只观察至期间末：下月实际接车不追改上月“尚无离场记录”。进出次数差值不能作为当前在厂数。

## 权限与操作

入口为“跟进与进出厂统计”。主管、财务及审计查看获权门店数据；销售、服务顾问、接待和客服仍受原业务阅读权限约束。集团汇总不提供原单办理入口，隐藏沟通内容和 VIN。统计不下载文件或暴露附件存储路径，原文件继续经过独立下载授权。

| 分支 | 岗位与入口 | 必要事实及原子影响 | 下一步、文件及异常出口 |
|---|---|---|---|
| 查询与筛选 | 获权岗位，统计页面或只读 API | 有效起止日期、获权原单；读取原事件，不改业务或任务 | 日期反向、未来日期、超过一年及来源超限用中文拒绝；原筛选保留可修改；无业务超时或撤销 |
| 导出 | 同查询权限 | 服务端重新构建同一原始行集合，写导出审计一次；CSV 对公式前缀转义 | 每张图明确关联原表，下载失败可重试；不创建资金、库存或跟进事实 |
| 来源不足 | 原业务获权岗位查看差异明细，按原单下钻核对 | 缺少原到店、错误凭据关联、重复接车或 VIN 绑定不一致显示具体差异；不补写原事实 | 通过各原业务的有效异常出口处理；没有任意改时间、改状态或补造到店接口 |

上传是原件关联及经办岗位确认，不是签名真实性认证。历史实际确认不因附件后续隔离而自动抹除，下载和重新使用仍按现有扫描门槛执行。

## 接口与注册

`GET /api/visit-activity-reports`、`GET /api/visit-activity-reports/export/{key}` 接受 `date_from`、`date_to`、可选 `case_id`。

同源表为 `presales_activity`、`presales_transitions`、`service_gate_movements`、`service_visit_cohort`、`visit_source_issues`。`build_visit_activity(db, user, start, end, case_id)` 返回表、图、指标及口径。原 l248 版本没有新增模型；q79d 的非维修进出厂使用六张新表和独立迁移，见《非维修进出厂》。

## 历史检查点的限制与验证（非当前验收）

本次不是通用厂门登记系统。没有实际到店来源的历史维修，只能列“待核对”；不按建单、付款或完工补算。到店转单后取消但没有实际离场记录，也只显示尚无离场，不能认定仍在厂。售前阶段停留及同接待批次漏斗尚未新增；没有员工排名、自动通知或经营决策。
