- M4.6：内部 run_once 与 service 薄封装，组装真实上下文、恢复完整意图、驱动 provider 与工具循环；未接新 HTTP 路由或启动 worker。原完整 assistant/tool 对仅在当前内存链使用，恢复观察不作为孤立 tool 消息发送，原始推理不持久化。
- Run.usage 固定 ledger 保存首次预算、已预留轮、真实安全用量、一次纠正/截断额度和新增卡计数。预留后崩溃不归还轮数，未知请求/token明确保持未知；默认24轮、硬上限40轮/600秒沿原配置。200仍是原同时待确认卡容量，不新增任意整批行数限制；可选内部准备预算只数真实新增卡，复用/失败/待补行不算新卡。
- 90秒租约和20秒心跳沿用原合同；心跳用独立同库短Session，当前协程的同步写事务不与它交错。单连接StaticPool/SingletonThreadPool不能满足独立心跳要求，明确拒绝，不改写匿名内存库语义。
- 真正取消/失权/目标变化仍立即阻止新成果；普通新用户消息不等同取消。后台在每完整工具及新模型轮前检查全局有效高优先用户，running→queued保留成果和预算；实际领取attempt保持单调，合法yield计数只抵扣让出占用，不增加三次故障重试额度。
- 原唯一最终消息键、最终展示、Run终态和事件同事务。retry实际转failed时也写最终回复，仍queued则不写；提交后查看权限复验失败不再取消已终态Run。预算耗尽一律failed，原卡、未准备行及原因保留；Run成功不代表Plan或实体业务完成。
