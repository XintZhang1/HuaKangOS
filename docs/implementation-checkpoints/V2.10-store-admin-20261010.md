## 基准与授权

分支 `codex/customer-feedback-20261010` 基于阿里云已核对的 `436f913c8b34eb96e6257a2c7d4bc442661f958a`。首轮提交 `12b546999e0b2ab444f170880a9f44c148e9491f` 的结果保留在[原检查点](V2.10-customer-feedback-20261010.md)。本轮业主追加授权总经理查看完整核价，新增独立、严格单店的门店管理员，覆盖旧版总经理敏感指标限制。

## 最终权限

| 对象 | 允许 | 保持禁止 |
| --- | --- | --- |
| 总经理 | 原授权门店的成本、利润、赠品成本、返佣和完整原表明细、核对说明，现有审批职责 | 扩大门店范围、改变销售等岗位的敏感权限、自批及修改已批准合同 |
| 门店管理员业务读取 | 唯一当前店的当前记录域合同、核价、客户、售后、日报、目标、统计、CSV、历史、标准价清单和发票原件；批准合同打印 | 跨店/集团汇总、旧业务模块、业务写入/审批/核价/到账/发票确认、标准价导入或估算、目标下达、助手和全局运行配置 |
| 门店管理员账号维护 | 当前店独占的销售、销售经理、销售内勤、收银账号：单建/批量新增、编辑普通岗、启停和重置密码；本店安全审计 | 自身、其它管理员、总经理、集团副总、董事长、跨店/集团账号；提权、增加门店或修改全局配置、删除 |
| 现有系统管理员 | 原能力，另可创建和分配独立门店管理员 | 新角色必须仅有一个有效门店、岗位一致、无其它成员关系、无集团汇总 |

服务端集中按方法/完整路径限制新角色，账号全局表显式筛选并在事务写前重验发起人及目标；保留版本冲突、幂等、会话撤销和审计。账号回执、完整性校验、后台撤权事件绑定同店；运行身份重验禁止门店管理员进入助手。前端能力展示与后台一致，直接拼接ID、改header/query/body不增加授权。

追加 `h61s_store_administration`，不修改既有迁移和历史账号授权。迁移在合成 SQLite 验证；不创建生产账号，不自动将任何现有人员改为门店管理员。
