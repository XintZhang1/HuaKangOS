## 2. 修复内容

| 可复现问题 | 修复与保护 |
|---|---|
| 提交 Run 后，注册域适配器即异常，接口不能正常返回 | 补齐 Case 事实的原 kind/version 适用范围，消除原操作注册重叠；49 个 adapter 能完整加载，重复注册和未定范围仍拒绝 |
| 助手页 `.map is not a function`；输入区出现 Promise | 目录异步读取与同步呈现分离；表单 HTML 同步返回；保留岗位筛选、四项上限、草稿与迟到响应守卫 |
| 显示准备完成却没有最终消息/卡片 | 终态必须聚合真实会话回读后再通知页面；回读失败要求刷新，不假称结果已完整显示 |
| 确认成功后，旧缓存把卡片变回待确认 | 新的原会话事实优先；完成的旧 Run 不重新覆盖已确认卡片 |
| 换店迟到 401、取消与旧 GET 交错、断流/乱序 | 上下文、读流所有权、服务端版本与 Run/session 标识共同校验；不误退出新账号，不前移错误游标，不应用半帧 |
| 已进入运行后离页再回来丢结果 | 只释放本地订阅，重新核对当前 Run；换店/新会话不挪用旧上下文，不自动取消业务或重发 |
| 模型畸形工具参数被当网络故障重新排队 | 单独区分协议拒绝；整段验证失败即终止本次准备，不执行部分工具、不空转、不补造卡片 |
| 手机卡片标签无效、确认按钮裁切、空白区冗余解释 | 标签绑定实际 DOM，修复面板高度；保留必要业务状态和确认操作，删除两段重复解释 |
| worker 运行时登录偶发 503 | 独立连接稳定复现 SQLite 517；只对登录会话发放前的旧快照冲突重新验证一次，不重试一般数据库失败或任何原业务提交 |

## 4. 浏览器边界与原始失败

当前 Chromium 对 HTTP 导航返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，没有改变环境策略。使用 about:blank 中的完整原页面和显式 fetch/Cookie 桥接，到真实本地 HTTP 服务；实际点击登录、发送、刷新、确认、换店、取消及移动端标签。测试过 1440 / 768 / 390 宽度。页面内异常由测试断言必须为空。

这不证明 Chromium 原生 Cookie/SameSite、同源 CSRF/CSP、代理、实际网络 SSE 或 HTTPS 部署通过。分块协议由 Node 另测，不能替代该验收。页面关闭时部分 Playwright 绑定回调有 TargetClosedError 收尾告警，保留完整原日志，未删除或包装成产品错误已修复。

保留部分修复前证据：Runtime 客户端初始 4/14、渲染 Promise 错误、注册阻断、先前浏览器 9/10（登录 503），以及独立 SQLite 517 复现。失败不是被删掉或放宽断言后变绿。
