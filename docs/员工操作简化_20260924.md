# 员工操作简化 · 2026-09-24

本轮按销售、售后、库管、财务的办事路径检查页面，不只处理车型和预订两个例子。依据仍是原193项需求；简化入口、选择、带入和补资料，不取消独立核价、实物确认、客户签回或实际到账登记。

## 已调整的操作

| 场景 | 以前的负担 | 现在怎么做 | 保留的规则 |
|---|---|---|---|
| 新增车型 | 分别建品牌、车系、车型，再去另一页确认归属 | “新增车型”一张表完成；已有品牌/车系输入即选，没有就在原表新增；内部代码自动生成 | 主档版本、门店岗位、明确归属、参数校验和防重；不产生实车库存 |
| 各类资料选择 | 搜索框、查找按钮、下拉框分开；部分页面没有转换 | 一个输入框实时出结果，中文输入、上下键/回车、手机点击均可；失败可重试 | 原隐藏选中ID、禁用/必填与当前门店权限不变 |
| 车辆预订合同 | 入口在整车仓库，不易识别；客户必须先去建档 | “整车销售 → 预订与合同”；“我的工作”有“新建预订合同”；同表录新客户或选择已有客户 | 同号只提示、不自动合并；客户与报价同事务；仍待主管核价及客户本版签回 |
| 预订缺车型 | 离开报价去多个基础资料页，回来重填 | 有维护岗位的员工可原地“新增车型”，保存或取消都回原预订，保留姓名、价格、约定 | 销售不会因此获得主档维护权限；已有预订需正常版本变更 |
| 办理缺凭据 | 关闭表单、上传、再次打开，金额说明重填 | 通用办理表直接上传并选用；进出厂专用表也可直接上传 | 文件归当前单、原类别/签回源版本/文件检查均不变；待检查的文件不能选用 |
| 维修报价 | 换项目还沿用上个项目单价 | 明确换项目时带参考价，仍可手改；重复选择同项目不抹掉手改价 | 已冻结/已开工行不被改写，核价授权仍在 |
| 维修退料 | 选择框只有领料数字编号，须回表查 | 显示配件、原领料日期、可退量，可搜索选择 | 用原领料ID及原批次；日期只取本单同一库存流水，读取失败不猜日期 |
| 采购退款 | 原付款只有内部编号 | 按实际凭证、原金额、本笔剩余选择，可搜索 | 原付款关联和累计可退量仍由原接口校验；没有日期就不编日期 |
| 精品附带维修销售 | 要手填维修单数字ID | 选择客户后列出其可读维修单，按单号/标题选；换客户清除旧关联 | 同店同客户和岗位权限仍校验，精品与维修独立结算 |
| 精品安装报价 | 选安装项目后仍手填参考安装价 | 换安装项目时带已有标准价，可修改 | 未安装默认不产生履约和收入，仍需主管及客户确认 |
| 新建保险 | 先查客户、再选客户、再进入另一表 | 在同一表输入姓名/电话选客户，联动车辆、销售、保单、续保候选 | 换客户立即清除旧关联，迟到回包不覆盖；不跨客户复制保单 |
| 保险公司切换 | 切换公司可能沿用上家公司账户 | 切公司清空不属于它的账户；切回恢复同公司的本轮输入/原单快照 | 现有公司主档无收款账户字段，不能凭公司名称猜账户或付款事实 |
| 库位历史查询 | 物资、仓库各一套“查找+下拉” | 单框搜索，选中即刷新；保留“全部”与历史停用资料 | 图表与CSV使用同一已选范围，输入中不会悄悄回到全量 |
| 现场来访 | 与预约一样默认一小时后开始 | 切“现场”时，未手改的默认时间改为现在；手填时间保留 | 此处仍是安排，不自动确认真实到店 |
| 常用入口 | 所有岗位共用前五个新建按钮；维修套餐藏会员菜单 | 首页按岗位显示常用办理；维修管理增加“维修套餐”入口 | 入口只调用已有受限业务，套餐与会员权益账本不合并 |

## 先试这三段

1. 主管/库管：“我的工作 → 新增车型”。选择或新增品牌、车系，填车型名称、动力及对应参数，一次保存。实际VIN的采购、验收、入库仍走整车采购。
2. 销售：“我的工作 → 新建预订合同”。输入客户姓名，已有客户选结果；新客户直接填。选择车型、成交价、日期和约定后提交。在订单页下载合同。订单仍等待主管核价及客户签回。
3. 财务/业务岗位：打开一个需要凭据的办理表，先填金额和说明，再点字段下“上传文件”。上传并通过检查后自动选用，已填内容保留。

用虚构资料试用。真实主管、销售、财务账号的浏览器证据见[本轮报告](verification/employee-journeys-20260924/测试报告.md)。没有在你的门店库插入测试客户或单据。

## 继续排查的具体问题

| 问题 | 后续改法 | 为什么本轮未直接合并 |
|---|---|---|
| 仓储其他退回仍需原收发流水ID | 按物资列出可退原批次、数量和价值，再选择 | 当前原批次成本与退回限额有独立校验，需补专用候选查询和真实库位链验证 |
| 库位准备需再选动作、重填总量，回原单再确认 | 从原业务带动作/数量，员工只分配实际库位 | 库位准备仅保存分配计划，不占数量；实际收发才检查并过账，不能合成一次隐式过账 |
| 维修多方承担表对纯客户自付也复杂，未承担项填0会被拒绝 | 单客户常见方式与“其他承担方”分开显示；明确未承担项留空，避免零值陷阱 | 不能默认保险/厂家责任；需覆盖增项、预付、已有部分到账等分支 |
| 理赔缺原款时的错误太笼统 | 指出缺少哪一笔已到账事实，并回到原业务 | 索赔核准、代收代付、客户原款是不同来源，需要逐动作链接正确原单 |
| 跨店协同选原单仍手动点查找 | 保留最少查询字数，输入后即时给允许选择的原单 | 涉及原单/附件范围申请及角色限制，继续按授权专项覆盖旧会话和撤销 |
| 已有主档仍有重复维护页 | 把常见创建入口集中到实际业务，保留管理员维护页 | 不能隐藏停用/历史修订和公司规则维护，也不能将不同账本合并 |

这些是已发现的体验问题，不把它们当成新业务需求。具体操作、代码位置、建议顺序和必须保留的校验见[后续清单](操作简化后续清单_20260924.md)。下一轮按员工试用卡点与发生频率排序；不把“功能有接口”当成“员工容易用”。

## 验证边界

车型/预订新增路径有原子性、拒绝、跨店、重复及过期版本测试；其他改动主要复用原业务接口。前端专项覆盖字段值、联动、过期回包、切店、冻结行和报表导出范围；真实浏览器区分使用实际合成业务与模拟接口。全量自动结果及本机数据保护以本轮报告为准，公司业务验收仍待实际试用。
