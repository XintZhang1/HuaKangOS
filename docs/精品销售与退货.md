# 精品销售与退货

本模块提供 `Case.kind=retail, flow_version=2` 的独立精品订单。员工入口为“精品销售与退货”；销售、服务顾问可开单，商品可选关联本店同一客户的可读维修单。关联只便于查阅，维修与精品分别记库存、收款和应收，不把精品金额再次加到维修单。历史维修、加装流程不改变语义，精品没有通用改状态接口。

## 已交付的业务范围

一单多商品，数量整数千分位，金额整数分。一次整单实际出库，可多次分笔收款和多次部分退货；暂不支持一张精品单分批出库。安装项目选择启用的作业主档，冻结作业编码、名称和每单位商品安装价格，不生成虚构工时或人工成本。

每张订单冻结一份第 1 版报价，包括商品身份、单位、数量、价格、安装项目与整单优惠。改价需要在未出库时取消原单，再创建新订单；这不是可编辑报价的版本链。优惠按商品和安装原金额比例使用最大余数法分摊，合计严格等于原合计减优惠。零金额行也保留实物、安装及客户交接事实。

报价明示默认退费约定：已实际完成安装的对应安装费保留；未施工的对应安装费随实际验收退货减免。主管须明确本报价最低可接受金额；低于此金额需要显式确认例外及原因，系统不从成本猜测商业折扣线。客户确认凭据关联当前报价 revision，未确认不能出库。

## 动作与岗位闭环

所有命令带请求编号与当前 Case 版本。申请、待办、账本、事件及幂等收据一次提交；冲突返回中文提示，员工刷新核对，不能盲目重试新编号。待办默认交给相应本店岗位，人工交接后的原接手人与到期日保留。表内“凭据”均指本单、岗位允许且通过附件检查门槛的文件；上传不等于恶意软件扫描通过或法律上的电子签名认证。

| 动作／岗位 | 入口与必要事实 | 原子影响、凭据及下一责任人 | 撤销与异常出口 |
|---|---|---|---|
| 开单／销售、服务顾问 | 本店客户、启用商品、可用数量；安装选择启用作业 | 冻结报价及安装退费约定；追加库存占用记录并更新 Item 版本，不产生实物或现金；交主管 | 未出库可由主管取消；无自动到期释占 |
| 价格审批／主管 | 本单待办、明确最低金额及例外原因；普通员工不可自批 | 留审批事件；交原销售／服务顾问取得客户认可 | 未出库可取消并重新开单 |
| 客户确认／销售、服务顾问 | 已批准报价第 1 版及实际客户认可凭据 | 记录确认；交库管出库；客户须认可安装保留费 | 未确认不能发货；不允许传其他 revision |
| 实际收款／财务 | 已审批；本单尚欠金额、实际账户与流水凭据 | 一个 CashEntry，通过一个 PaymentLink 与 RetailPayment 关联；分笔收款 | 领取前收款是预收；退货或取消后按原收款退款 |
| 取消／主管 | 尚无实际出库、填写原因 | 全部释占，不修改库存；已有收款时转财务待退款 | 原款退清后取消完成；已出库必须走原单退货 |
| 实际出库／库管 | 已审批、已客户确认及出库交接凭据 | 整单解除自身占用并追加负 StockMove、冻结原出库数量／成本；有安装交技师，同时交销售／服务接收任务 | 不覆盖原出库；错误或客户退回通过原单退货纠正 |
| 安装／技师 | 已出库、有未退回的安装商品，无待办理退货 | 记录实际安装结果与凭据；不编造工时成本 | 尚未安装的商品全部退回后不能虚构安装；待退货先完成退货或撤销 |
| 客户接收／销售、服务顾问 | 已出库、必要安装已确认、无待处理退货；客户实际接收凭据 | 留实际接收日，实物履约完成；欠款继续留财务待办 | 本版允许实物先交付后到账；后续退货另办原单 |
| 退货申请／销售、服务顾问、主管 | 引用本单原出库行、部分数量、原因及实际申请凭据 | 不改库存及应收；交主管复核 | 待批准可取消；不得引用其他订单的出库行 |
| 退货批准／主管 | 普通员工不能自批；原出库尚有未被其他获批退货占用的数量 | 占用该原出库可退数量；冻结是否已实际安装的保留费规则；交库管 | 未实物验收可撤销、释放原出库可退量；批准不代表已退货 |
| 可售验收／库管 | 已批准或已整改，实际检查结果、凭据 | 合格才按原出库剩余数量／价值比例回可售库存，并减应收；已收超额交财务退款 | 不合格进入待整改，不过库存、不减应收，不产生退款额度 |
| 整改／技师 | 原退货检查不合格，实际处理结果及凭据 | 留实际整改事实，交库管独立复检 | 复检可再次失败；无法整改由主管决定拒收 |
| 拒收决定／主管 | 有不合格记录、拒收原因 | 转库管待实际交回客户；仍保留原可退数量占用 | 决定本身不代表实物交回 |
| 拒收交回／库管 | 主管已决定拒收、本人实际交回结果及凭据 | 结束此退货、释放可退量；不增加库存、不改变应收 | 不伪造损失冲销或收回入库 |
| 原款退款／财务 | 实际验收退货或未出库取消形成应退；原收款账户、凭证及退款结果 | 一个反向 CashEntry 和指向原 PaymentLink 的链接；追加事实不覆盖历史 | 受本单实际应退、原收款未退金额双重上限；跨账户拒绝 |

每一步使用现有任务到期机制，超时显示待办，可由主管按实际原因转交；不会自动出库、扣钱、安装、接收、销账或取消库存占用。退货验收不合格的商品不属于可售库存，待整改／待交回状态及凭据用于跟进客户物品交接。本版不提供独立隔离仓会计估值。

## 库存与金额口径

当前可用量 = Item 账面数量 − 全部有效精品占用。占用是不可变正负记录，销售创建、实际出库或取消都触碰同一个 Item 版本。维修发料、采购退货、旧物资出库及物资调拨也通过公共可用量校验，不能挪走已占商品。实际出库排除自身占用后校验，避免扣两次。

出库按 Item 当前剩余数量／价值比例分摊，出尽时取全部余分；退货按对应 RetailDispatch 尚未退回数量／原成本分摊，最后一次取尽原成本余分，不用现价重估退货。采购 StockMove、精品出库和退回都进入统一入出存来源。原退货审批确认的是冻结单价、优惠分摊与安装保留费规则，实际验收按剩余量计算，分批先后可能产生 1 分舍入差，末次收尽余分；总数量、商品原金额、安装分摊金额及原成本不会超原单。

当前合同应收 = 原冻结合计 − 已可售验收商品金额 − 对应未履约安装费；未出库取消时为零。实际净收 = 本单 CashEntry 所链接的收款 − 原款退款。尚欠 = max(合同应收 − 实际净收, 0)，应退 = max(实际净收 − 合同应收, 0)。未收过的钱只能减少应收，不生成退款。客户已接收后的当期收入、跨期退货冲减和当前应收分别统计，不把现金到账时间当成交付时间。

库存／技师页面及专用 API 不返回商品价格、安装价格或成本，也不允许下载本单客户报价确认附件；客户确认必须引用 authorization 类文件，实际收退款必须引用 receipt 类文件；销售／服务可以看客户报价而无成本与资金账户流水；管理、财务、审计按各自权限看结算与成本。普通员工仍受原 Case 的负责人、待办与门店读权限限制，跨店相关 IDs、文件、原收款和原出库均再次核对。

## 接口与数据来源

`GET/POST /api/retail/orders`、`GET /api/retail/orders/{id}`、`POST /api/retail/orders/{id}/actions/{action}`。`/api/retail/items` 与 `/api/retail/installations` 只向可开报价的岗位提供商品可用量、安装项目与参考费，销售不会因此获得物资成本或全部主档管理权限。专用命令见 `app/retail_api.py` 的严格字段表；不接受客户端状态或库存成本。退货命令同时携带 `return_id/return_version`，收款／退款同时携带 `account_id/reference/evidence_id/amount_cents`，退款另带原 `PaymentLink.id`。

迁移 `p016_retail` 接 `o915_vehicle_procurement`，冻结 8 张表：报价头、报价行、占用记录、原出库、退货申请、退货行、实际退回、现金关联。事实表在应用层拒绝覆盖或删除；数据库管理员仍有底层技术权限，不宣称密码学防篡改。

## 验证与实际限制

自动用例包括多行优惠、零售与维修／采购竞争库存、出库／收款／退货／退款并发、拒绝过期版本、相同请求重放、跨店全部动作、伪造原出库、原账户退款上限、附件隔离、实际安装前不得接收、已安装部分退货保留费、未安装退货费用减免，以及不合格整改／拒收交回。浏览器脚本 `tests/browser_retail.py` 使用全新合成数据库与五名实际岗位账号、真实 HTTP Chrome、390 像素视口，不以管理员代替员工链。证据在临时目录，不将密码、数据库或客户文件纳入仓库。

本模块没有集团本金／赠金／积分／券／套餐抵扣，没有套餐销售、分批出库、佣金或完整工时成本，也没有会计总账、外部支付退款直连或独立精品正式合同模板。退款凭据是财务对实际办理结果的确认。此模块推进精品独立销售、维修附带精品和原单退货，不能据此宣称所有精品及维修套餐需求完成。
