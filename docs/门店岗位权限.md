# huakangos 门店岗位权限

本轮新增独立门店岗位；已通过隔离 SQLite 自动测试和真实 Chromium 员工账号浏览器验证。没有改变历史业务记录的门店归属。

## 授权规则

- 账号的 `User.role` 继续保存全局管理员身份或旧版本默认岗位。每个 `UserStore` 可指定本店岗位，前台、技师、客服、销售、库存、售后、财务、店长、审计共九种岗位；本店岗位不能填写系统管理员。
- 本店岗位为空表示**明确保留旧版兼容**：该店采用账号默认岗位。已有账号迁移后保持此模式；管理员可逐店改为明确岗位。旧客户端仅变更门店列表时，保留仍在列表内的明确岗位，新门店使用默认岗位。
- 登录或切换门店的每个请求重新查询岗位，返回请求专用身份对象。`role` 是当前有效岗位，`account_role` 是账号默认岗位。不会修改、提交或临时覆盖 ORM `User.role`。
- 账号管理只允许全局系统管理员。店长岗位不允许管理账号；任何门店岗位、汇总权限、启停、个人资料修改都会撤销该账号的全部会话，重新登录后生效。个人密码修改直接更新真实账号并撤销会话。
- 任务分派检查任务所在店的有效岗位；财务任务只能交给该店财务或全局管理员，不能因另一家店的财务岗位获得资格。

## 集团汇总

`can_group_summary` 是显式授权，新普通账号默认关闭。全局管理员具备汇总权限。迁移仅为原管理、财务和审计账号保留原有汇总资格。

汇总仅包含本人获授权且有效岗位为店长、财务或审计的在用门店，管理员可包含所有在用门店。`group_store_ids` 是实际汇总范围。某人在 A 店为店长、B 店为销售，即使开启集团汇总，也只汇总 A 店；这避免通过汇总布尔值扩大 B 店的明细、财务或附件访问范围。仅为一线岗位授予汇总勾选，不会产生可用汇总范围。

`X-Store-ID: all` 下身份显示“集团汇总（只读）”，办理、账号管理和门店管理写请求均返回 409。本人修改密码、退出登录可用；单店切换后恢复该店岗位。汇总指标沿用原指标口径，范围按 `group_store_ids` 裁剪，不把排除门店的数据纳入图表或导出。未来若需要“能看某店数值汇总但不能看该店经营明细”的额外管理模式，必须增加独立接口和脱敏策略，不能扩大当前汇总范围。

## API 与兼容

账号创建及修改可传 `store_roles: [{store_id: 1, role: "sales"}, {store_id: 2, role: "service"}]` 和 `can_group_summary`。同时提供 `store_ids` 时，两个列表必须对应。修改时省略 `store_roles` 保留原映射；提供时完整替换。重复门店、不存在或停用门店、非法岗位整体拒绝，账号与映射不会部分写入。

账号列表返回 `store_roles`，其中 `legacy_fallback` 标明是否使用默认岗位。登录信息中的 `stores` 带各店有效 `role`；前端切店必须先刷新 `/api/auth/me`，再刷新业务目录和界面。现有登录 Cookie 和旧接口 URL 保持兼容。

数据库迁移为 `d904_store_roles`，接续 `c803_workflow`，定义固定 SQL 约束而不引用当前模型。存在明确门店岗位时，降级会拒绝执行，避免降级后默认岗位扩大权限。正式迁移仍须在备份副本验证及完成恢复演练。

## 验证与边界

`tests/test_store_roles.py` 覆盖不同岗位切换和刷新、账号角色不被污染、非管理员越权拒绝、显式汇总权限、低权限门店排除、汇总写拒绝、任务财务岗位校验、密码更新、会话撤销、非法映射原子回滚、SQL 约束及旧库迁移。

运行 `python tests/browser_huakangos.py` 可复现本地真实 HTTP 浏览器验收：脚本自行建立仓库外临时数据库、生成随机密码，实际填写员工表单、修改首次登录密码，在 390px 页面切换销售／售后岗位、创建隔离的客户资料，并检查中文拒绝信息、CSRF、Cookie 与汇总写入限制。还包括财务员工跨店集团本金充值与核销、独立店长批准退款、批准后撤销释放占额和实际原款退款；13 个验收场景全部通过且没有 JavaScript 错误。集团汇总退出后同页登录下一账号，清空上一个账号的门店范围和隐藏表单内容。截图和无密码结果 JSON 留在系统临时目录，数据库与服务进程在结束时清理。需要单独安装 Playwright 和 Chrome／Edge；不使用 DOM 传输桥。生产 HTTPS 与 Secure Cookie 的部署验收仍未完成。

此模块没有业务金额或库存变化，也不生成业务凭据或下一办理任务。管理员是唯一岗位配置经办人，权威来源为账号与门店授权表；变更与审计在同一事务提交，下一次登录使用新授权。配置没有自动到期；撤销通过移除门店或修改岗位，保留审计，不覆盖历史操作身份。实际进行中的业务按新权限继续办理或由主管转交。

账号修改现在必须携带员工列表返回的 access_version 和本次 request_id；同事务核对版本、岗位、会话撤销及审计回执，旧页面不得覆盖他人已保存的授权。相同成功请求重放不再次改权或撤销新会话。密码专用接口与岗位版本分开。详见《账号授权版本与并发》及其实际验证记录。
