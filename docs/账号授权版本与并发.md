# 账号授权版本与并发

本分支保护已有固定岗位与逐店授权。只有全局系统管理员可以办理，集团汇总界面仍只读；没有新增自定义角色，也不改变业务记录归属。

## 办理规则

员工列表返回 `access_version`。管理员编辑表单保留打开时的版本及本次请求号；提交时同时核对目标账号版本、经办管理员当前有效身份和完整门店映射。其他管理员已经保存时，本次整体拒绝，提示关闭窗口、刷新员工列表、核对最新岗位后重新办理。不能以新请求号自动重试过期授权。

账号修改按固定顺序锁定管理员及目标行，然后以旧版本作为数据库更新条件。账号资料、逐店岗位、集团汇总开关、版本递增、全部登录会话撤销、审计和不可变回执在同一事务提交。门店不存在、映射非法或并发冲突会全部回滚，不会仅撤销会话或只改一半岗位。

相同管理员、相同请求号及相同原输入返回原成功回执，不重复修改权限、不再次撤销后来新建的会话。相同请求号换内容会被拒绝；另一管理员不能用该回执代替自己的授权校验。每次执行都复核管理员仍启用且已完成强制改密。

不能停用或降权当前管理员自身；并发互相撤权不能绕过有效管理员检查。启用的非管理员账号须至少获权一家在用门店。旧空岗位映射仍明确采用默认岗位，省略岗位映射不替换现有关系，已有明确岗位不自动覆盖。

个人改密和管理员重置密码使用现有专用接口，不属于岗位版本修改；姓名或岗位编辑不会覆盖新密码，也不会清除首次登录强制改密。密码、哈希及会话令牌不进入本分支回执。

配置没有自动超时或业务账目影响，没有虚构的下一业务待办。撤销授权通过新的明确修改完成，不改写历史审计；已经分派的业务由获权岗位继续或主管明确转交。

## 数据与恢复

静态迁移 `k137_user_access` 接续 `j036_addon_lines`，为已有账号建立版本 1，并新增 `user_access_receipts`。存在版本化修改后禁止直接降级丢弃回执。

只读恢复校验核对请求摘要、审计前后版本、完整回执链，以及最新姓名、账号岗位、逐店岗位和汇总授权。密码修改及门店显示名称变化不改变这条授权链。数据库管理员仍然具备技术权限，本机制不是密码学防篡改存储。
