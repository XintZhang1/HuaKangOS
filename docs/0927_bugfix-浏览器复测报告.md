## 4. 本次复测中新增的修复（`fe8ceff`）

`web/addonorders.js`：

1. **按动作声明凭据类别**（原为除"取消"外一律 `file_category:'evidence'`）：批准/授权/接收确认/处置申请与处置批准同意=`authorization`；安装/质检/整改/拆回验收=`inspection`；收款/退款=`receipt`；领出保留 `_proof` 默认的 `evidence`。**未改任何服务端守卫生效逻辑**，只修"本步需要哪一类"的界面预选与候选过滤。
2. **本页用词改取服务端词表**（`state.catalog.upload_categories`）：原文写"安装、检查、实物验收选择**检查凭据**；真实收退款选择**收款凭据**"，而词表里只有"检测记录/收退款凭据"；文件行原不显示类别，现显示"类别 · 扫描状态"。

**验证口径（以服务端为准，不用页面自证）**：① 故意让动作收到错类别原件，读服务端 422 原文里"本次需要「X」类别"；② 用页面预选类别真实办成；③ 修复后该动作的面板上传**只提供**所需类别。

| 动作 | 声明 | 锚定 |
|---|---|---|
| `resolution` | authorization | ① 422 原文「客户授权」② 正向办成（处置单落库 `requested`） |
| `receive` | receipt | ① 422 原文「收退款凭据」③ 面板唯一 |
| `resolution_approve` / `resolution_cancel` | authorization | ① 二者 422 原文均「客户授权」 |
| `approve` / `authorize` / `resolution_consent` / `return_receive` | authorization / inspection | ① 复测中实测 422 原文；② 用该类原件真实办成 |
| `install` | inspection | ② 已办成 + ③ 面板唯一（① 未取到 422 原文，见 §6） |
| `dispatch` | evidence（`_proof` 默认） | ② 已办成 + ③ 面板唯一 |
| `quality` / `rectify` / `accept` / `refund` / `resolution_reject` / `return_rectify` / `return_handback` | inspection / authorization / receipt | 仅源码字面锚定，未取得浏览器原文 |

> 说明：本项修复的第一版验证只比对了"页面提示 ↔ 页面自带映射"，属自证且把 `resolution` 误判为"检测记录"；本报告采用的是服务端锚定结论（已更正）。
