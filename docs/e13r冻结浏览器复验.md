## 时间问题与最小修复

旧续会费截图中，附件上传显示15:17，办理记录显示07:17。数据库 `utcnow()` 的契约是 UTC 无时区对象：附件 API 明确加 `Z`，业务财务与会员事件的历史序列化没有加 `Z`；原 `time()` 将后者按浏览器本地时区解析，因此中国浏览器少显示8小时。独立 Chrome 诊断证明，在 UTC 浏览器恰好正常，在纽约则又产生另一偏差。这是已有通用展示边界问题，并非新增会费更正写错时间。

本轮仅修改 `web/app.js` 的 `time()`，增加 `tests/js/time_display.test.cjs` 和 `tests/test_time_display.py`，并给 `tests/browser_member_fee_corrections.py` 加入真实事件与关联附件时间断言。API、数据库、历史快照、账目、业务日期和预约输入转换没有改变。

显示函数现在接受以下明确输入：

- ISO 日期时间：无时区按后端 UTC 契约解析；带 `Z` 或 `±HH:mm` 的原偏移保持，统一显示上海时间。支持分钟、秒和最多6位小数秒。
- 有效 `YYYY-MM-DD`：保留原业务日期文字，不添加08:00等虚构时刻。
- 空值、不支持的数据类型、无效日历日期或时间、歧义本地文字：显示“—”。

已查明的19个前端文件、40处调用传入的都是 API 时间点或空值，没有把预约原始本地输入交给 `time()`。预约与进出厂表单仍先将 `datetime-local` 值转换为明确 UTC 后提交；其原转换和回填保持。纯业务日期继续由各原页面按日期展示。
