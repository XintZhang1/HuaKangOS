# 经营主数据与期初资料导入

当前交付为阶段二的一条可运行链路：有明确字段与引用守卫的门店资料、新店期初资料预检、试导入、确认入账以及库存来源核对。它不代表原表所有采购、维修、会员等级权益或统计需求已完成。正式业务仍须由公司按验收用例确认。

## 资料及权限

入口为“经营主数据”。维护使用选定门店的有效岗位；集团汇总只读，不因持有汇总权限获得维护权。所有列表、查找和保存由 API 再检查权限及门店范围。

| 资料 | 明确的业务字段与约束 | 维护岗位 | 额外可读岗位 |
|---|---|---|---|
| 供应商 | 信用代码、联系人、电话、付款天数（0–365） | 管理员、店长 | 财务、审计；库管仅基础联系资料，不返回信用代码、付款天数 |
| 保险公司 | 许可证、理赔电话、结算天数（0–365） | 管理员、店长 | 财务、审计、服务顾问 |
| 仓库、库位、物资分类 | 库别、地址、所属仓库、上级分类 | 管理员、店长、库管 | 财务、审计、服务顾问、技师 |
| 作业项目 | 计费单位、参考工时、收费、质保天数 | 管理员、店长、服务顾问 | 财务、审计、技师；技师不返回收费字段 |
| 班组 | 本店启用负责人 | 管理员、店长、服务顾问 | 财务、审计、技师、库管 |
| 代办项目 | 服务收费、预计天数 | 管理员、店长、服务顾问 | 财务、审计、销售 |
| 车型参数 | 品牌、年款、动力、座位、排量、电池容量、指导价 | 管理员、店长、库管 | 财务、审计、销售、服务顾问 |
| 会员等级 | 参考年费、有效月数、结算比例 | 管理员、店长 | 财务、审计、销售、服务顾问 |
| 物资归类与库位 | 现有物资、类别、物资库位、可选供应商 | 管理员、店长、库管 | 财务、审计、服务顾问、技师 |

前台接待、客服当前不能读取这些经营设置。车型指导价是对外参考售价，有意向销售、服务顾问、库管提供；不包含车辆进货成本。库存来源核对页对库管只返回数量及数量核对结果，财务、店长、管理员、审计还可核对价值；CSV 与 API 采用相同权限和数据集合。

编码在本店唯一；新建、编辑有请求编号，编辑还须提供当前版本。重复编号且内容一致返回原结果，内容变化拒绝；过期版本拒绝覆盖。资料不物理删除。仓库有启用库位、分类有启用子类或物资归类、供应商有启用绑定或未结采购时拒绝停用。使用资料时同时核对本店及启用状态，不因前端曾显示过便放行。分类拒绝循环；物资只允许进入物资或混合仓库；班组负责人必须是本店有效的管理、售后或技师岗位。

新采购通过 `require_active(db, 'suppliers', id)` 消费正式供应商主档，并冻结供应商名称、编码、税号及付款天数快照。仓库、库位、类别、供应商用于物资归类的有效引用。其他作业、保险、代办、车型、等级为严格类型基础资料和查询筛选，本轮没有把所有旧流程改为按这些 ID 办理。会员等级是本店预配置资料，**不等于集团已发行权益的冻结规则版本**，修改年费或比例不会修改会员账本和旧权益。车型筛选实际应用动力、座位和指导价上限条件。

## 期初办理顺序

1. 管理员或店长进入“期初资料”，选择公司核对后的 JSON 文件或粘贴原资料。页面有全部虚构的格式示例。
2. 预检返回逐行错误表；有效资料保存原始文本、SHA-256 摘要、来源、日期和数量金额汇总。此时不创建客户、账户或物资。
3. 点击“试导入并回滚”。系统在保存点中实际建立全部客户、账户、物资和期初账，检查引用及约束后全部回滚；只保留试导入状态、审计及请求回执。
4. 店长核对客户行数、账户行数、物资行数、库存行数、数量及价值后确认。确认请求绑定批次版本、原资料摘要及完整汇总。系统重新验证空库、用户引用、日期和原资料，在一个事务中建立所有资料、原始期初账、审计及幂等回执。
5. 查看“期初与库存流水”，按期初账加实际库存流水核对当前数量与价值；逐笔导出 CSV 使用同一集合。历史库存缺少来源时显示差额，不补造历史。

数量用整数千分位，金额用整数分，拒绝小数或悄悄舍入。每个有库存的物资必须提供来源；零数量不能有非零价值。库存单位成本仅是展示参考，原始库存价值完整保留。客户需指定本店有效客户业务岗位的负责人；电话不自动合并身份。资金账户只创建银行或现金账户主档，**不导入现金余额、应收应付、未结订单或旧流程状态**。

JSON 顶层字段固定为 `opening_date`、`source_reference`、`customers`、`accounts`、`items`；多余字段、重复 JSON 字段、无效引用、重复物资编码、重复账户名称、完全相同的客户姓名电话均返回错误。原资料最多 85 KB，客户最多 300 行、账户 100 行、物资 300 行。样例由 `/api/masters/opening/example` 提供。

只有本店尚无客户、账户、物资、车辆、业务单据、会员或账本的空业务数据可确认；演示数据库整体拒绝，已确认门店拒绝再次导入。已配置员工、门店及类型主资料可以保留。其他门店已有业务不影响当前独立新店。准备后若有人先建立本店业务，确认时也会拒绝，不覆盖任何行。

原始文本和期初账不允许通过应用改写或删除。确认前可放弃批次，再准备新批次；没有自动超时办理或无人值守确认。确认后没有“撤销覆盖导入”按钮，纠错应使用获准的业务冲正流程；若还未启用且整库录错，管理员按备份恢复流程处理。并发确认由唯一已确认门店键和事务约束保证只有一批入账；冲突要求刷新核对，不盲重试。

原资料接口保留提交文本的前后空白和换行；网页加载 JSON 文件时，未修改内容会保留原始换行，摘要不被表单自动去空白改变。改变资料后点击试导入或确认会要求重新预检。重新进入未确认批次时，本店管理岗位可重载原文本继续核对；库管、财务、审计和跨店请求不能读取原文本。

## 技术契约与核验

API 位于 `/api/masters`：`catalog`、`{kind}` 列表/新建、`{kind}/{id}` 编辑、`lookup/{kind}`、`opening/example`、`opening/preflight`、`opening/batches`、`opening/{id}/trial`、`opening/{id}/confirm`、`opening/stockflow` 及 `/export`。追加迁移 `h208_master_data`，前序 `g107_file_security`；迁移冻结表定义，不导入当前模型创建历史表。

`OpeningStockEntry` 是不可变原始期初账：它保存物资、门店、原批次、来源、数量、价值、日期和经办人。后续采购、领退料、调拨继续使用 `StockMove`。不为期初伪造业务工单或收付款。`OpeningBatch` 及回执与实际数据同事务提交，不存在半批成功。

自动用例在 `tests/test_master_data.py`：类型校验、读写岗位、逐字段隐藏、引用停用、跨店、重复请求、过期版本、整批失败回滚、试导入无业务数据、原资料不可变、摘要和汇总绑定、并发只入账一次、领退料精确价值守恒、流水与 CSV、冻结迁移约束。实际浏览器用例在 `tests/browser_masters.py`，独立临时数据库、随机密码、真实本地 Chrome HTTP，截图及验收 JSON 位于仓库之外。浏览器验证不替代部署环境 HTTPS、PostgreSQL 并发、公司真实期初审核和业务验收。

2026-09-21 本轮结果：37 项自动测试通过，9 个实际 Chrome 员工场景通过，前端语法通过。截图检查覆盖 390px 逐行中文拒绝、试导入核对、正式确认、库存流水和引用拒绝。全部为虚构资料，未连接或修改正式业务库。
