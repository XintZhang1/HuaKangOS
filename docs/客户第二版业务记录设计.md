# 客户第二版业务记录设计（2026-10-08）

## 目标与已确认范围

独立业务记录系统，不对接ERP。取消新业务的库存、车型主档、接待分派、会员和完整财务流程依赖；保留旧数据和原代码。人工负责填报、核算、审批与对账，系统负责保存、关联、汇总和可视化。金额存整数分，未知成本保持未核定。

合同绑定单个真实销售账号，不做跨店合作、多人分摊、调店离职特殊业务。个人、门店、品牌、集团提供权限内统计排名，利润贡献优先，不新增加权考核公式。实际到账日期作为实收和销售业绩的期间口径，退订退款/补录成本仅保留统计，不引入业绩冲回流程。

销售录单（自由品牌/车型/VIN等）→内勤人工核价（成本、利润、赠品成本）→总经理/董事长审批→允许打印→客户线下签字并分客户/财务保存→财务按合同号人工核实后确认实际到账金额和日期。内勤审核不是最终打印放行，门店管理岗位无最终审批权，系统管理员保留配置验证能力。当前所有合同管理审批，不自动免审；固定金额/车价比例阈值供总经理/董事长设置，标准价格上传仅预留，现阶段人工核价。

应到账取批准合同的核定金额，实到账取财务确认记录；没有到账日期的应到账合同不丢失。应到账用合同日期筛选，实到账/利润/实销量用实际到账日期，页面明确两种期间口径。同一合同到账确认不重复计销量和利润；本版提供一份合同一次人工核实汇总金额的最小路径，不推导银行事实或后续业务。

售后包括维修、保养、事故维修、续保、延保、精品销售，仅记录客户、车辆、服务项目、材料费、工时费、成本、经办人及统计日期，不形成派工/领料工作流。客户只建档。原11截图和Excel结构的统计字段全部保留，合同以外的目标、库存数量、营销、人员、保险等由人工填写，不恢复相关管理模块。

电脑端默认经营看板：每次一张主图，用户选择指标/报表、时间、分组和权限内门店/品牌/人员；明细按需展开、相同范围导出，显示更新时间。基础报告为应到账、实到账、内勤核定利润、实销量、售后产值；其余来自人工统计目录。销售仅本人，内勤/财务处理所属门店职责数据，店长仅其门店，总经理/董事长按获授权门店汇总。AI是独立辅助入口，查询/填单准备/解释报表；核价、管理审批、到账必须人工操作。

业主追加纠正：侧栏业务菜单仅「销售业务、售后业务、财务流水、客户信息」，按岗位显示可访问项。经营看板经Logo/顶部进入，人工统计为看板内部按钮；赠品阈值配置放销售业务内部。AI为顶部小入口，必要账号/门店配置放头像菜单。旧整车仓库、物资、会员、基础数据、每日汇总、数据复核、原有单据等菜单及页面分发全部撤下，旧书签返回经营看板，不恢复旧菜单或加载旧业务目录。原数据留存不等于旧模块继续出现在新系统中。

## 合同模板

采用业主空白 `新--确认版++车辆销售合同修改版2026.pdf`，两页分别为汽车销售合约书和销售条款。保存版本标识、批准时填单快照和合同号，服务端审批检查后输出可打印合同。线下签字版不强制回传。第一页面字段包括买卖双方、证件/电话/地址/邮件、品牌/车型/数量/外内颜色/VIN、购车价/补贴押金/定金余款与付款方式、其他/赠品约定、提车时间地点、销售代表和签订日期；第二页条款保留。

## 接口约定

统一前缀 `/api/business-records`，JSON金额字段为整数分。POST使用 `request_id`，原单修改使用 `version`。身份、岗位、当前门店、本人归属均服务端校验，集团汇总只读。详情返回可用动作，前端不得猜权限。

- GET `/catalog`：`capabilities`、`sales_people`、`service_types`、`reports`。能力键：`create_sales`、`price`、`approve`、`confirm_receipt`、`manage_settings`、`record_statistics`、`create_after_sales`、`manage_customers`。
- GET/POST `/contracts`，GET/PUT `/contracts/{id}`，POST `/contracts/{id}/price-review|approve|reject|receipt`；GET `/contracts/{id}/print`（审批后PDF）。
- GET/POST `/customers`、`/after-sales`、`/manual-reports`；GET/PUT `/settings`。
- GET `/reports` 和 `/reports/export`，参数 `report`、`date_from`、`date_to`、`brand`、`salesperson_id`、`group_by`（salesperson/store/brand/month）。报告返回 `title`、`unit`、`period_basis`、`series`（label/value）、`rows`、`columns`、`updated_at`；导出使用同范围同事实。
- 原模块和原报表口径不重写；新域不得由模型直接调用审批/打印/到账动作。必须避免旧工具目录继续推荐本版已取消的业务链路。

## 本轮验收与交付

一个新外部合成环境完成：销售无库存建合同→内勤核价→管理审批→下载并目视检查两页PDF→财务确认到账→图表明细与金额一致；核实审批前打印拒绝、本人/跨店隔离、重复请求不重复到账、过期版本拒绝、六类售后及人工报表可录入。实际浏览器走原登录Cookie/CSRF，不发真实模型请求，不接触原预览库。验证据实记录，不恢复已延期旧全量验收。

发布到现有GitHub main及阿里云，先读取目标服务现状，备份业务/附件及运维数据，在外部副本验证追加迁移；新release逐文件指纹，保留旧release和数据。当前请求无重置授权。部署完成以health、实际页面和登录结果确认，员工试用由用户安排。
