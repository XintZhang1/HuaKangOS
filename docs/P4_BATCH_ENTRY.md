# P4 · AI 批量填单（人工复核）

> **实现状态（2026-09-19）**：已实现**无状态**版本，与下面「数据模型」一节描述的有表版本不同。
> 现在的链路是：`POST /api/entry-draft/parse` 用 DeepSeek 把文本解析成草稿，**草稿只回给调用方**，
> 不落库、不写任何业务记录；人逐条复核修改后，通过**既有的** `POST /api/records/{module}` 写入，
> 于是创建人、校验、门店作用域、审计全部复用原有路径——这正是「人对这条记录负责」的落点。
> 代价是**没有留痕「AI 曾提出过什么」**，也没有草稿的跨设备续办；需要这两点时再按下面的表结构补。
> 权限与手工录入一致：接口会做 `require_module(user, module, write=True)`，只读角色无法调用。
## 目标

把一段非结构化文本（粘贴的多行记录，或上传的 txt / md / csv）交给 DeepSeek，
按模块的字段定义解析成**草稿**；由人逐条复核、修改、确认之后，才写入正式业务表。
**最终写入的每一条，责任在人，不在模型。**

## 为什么必须人工复核

录入的是经营数据——金额、客户、VIN、保单。错一条就会污染报表和提成口径。
而模型的抽取是概率性的："3.5万" 会被读成 35000 还是 3500，没有任何提示词能预先保证。
所以草稿与正式记录必须**物理分离**，并把"谁确认的、改了什么"留痕。

## 边界（不做什么）

- **不自动提交**：没有 `confirmed` 的草稿永远不进业务表。
- **不碰口径**：金额算法、权限判断、审批发布一律不改；AI 输出按不可信数据处理。
- **不替人签字**：审计日志记录的是复核人，不是"AI 已确认"。

## 数据模型

新表 `entry_draft`（StoreScoped，与业务表同样受门店作用域约束）：

| 字段 | 说明 |
|---|---|
| `id` / `store_id` / `created_by` | 常规归属 |
| `batch_id` | 一次粘贴产生的多行草稿 |
| `module` | 目标模块（vehicles / sales / repairs / policies / cash） |
| `source_text` | 该行对应的原始文本，便于人核对 |
| `payload` | JSON：模型抽出的字段 |
| `issues` | JSON：校验失败项（字段、原因） |
| `status` | `pending` / `confirmed` / `rejected` |
| `confirmed_by` / `confirmed_at` | 复核人留痕 |
| `created_record_type` / `created_record_id` | 确认后指向真正写入的业务记录 |

## 流程

1. 界面：粘贴文本 → 选择模块 → 提交（一次一批）。
2. Worker 调 DeepSeek，用模块字段定义作为提示词契约，要求返回 JSON 数组。
3. 落成 `entry_draft`，逐条跑一遍现有 schema 校验，失败的进 `issues`。
4. 人在表格里改字段、删行、批量确认或拒绝。
5. 确认时**走现有模块既有的校验与写入路径**（同一套 Pydantic schema、同一套门店作用域与审计），不新开写库捷径。

## 安全与预算

- 复用 `ALLOW_AI_EXTERNAL` 开关与 `AI_MAX_RECORDS` 上限；关闭时整条链路不可用。
- 只发送用户粘贴的文本，**不发送数据库内容**。
- 模型输出只当数据：未知字段丢弃、类型不符标 `issues`、绝不直接入库。
- 每条确认都记 `confirmed_by`，审计可追溯到具体的人。

## 验收标准

1. 一段含 5 行记录的文本 → 5 条草稿；字段正确率由人抽查确认。
2. 故意写错（金额非数字、日期非法、VIN 不足 17 位）→ 标 `issues`，**不能直接确认**。
3. 未确认的草稿在任何业务列表、报表、导出中都不出现。
4. 确认后审计日志能看到复核人；写错并已确认的记录可按常规流程作废，而不是删库。
5. 关闭 `ALLOW_AI_EXTERNAL` 后，批量填单入口不可用，手工录入不受影响。

## 与自动维护的关系

P4 是 P0–P3 之外**独立的业务功能**：它不经过候选分支、不需要审批卡片，
也不受 22:00–06:00 运维窗口限制（它不在构建机上跑 Docker，也不是 GitHub 操作）。
它复用维护链路里已经验证过的东西：`ALLOW_AI_EXTERNAL` 开关、DeepSeek 调用与超时、
以及"模型输出一律不可信"的处理原则。
