# 代办与其它客户服务收入

本模块对应原需求 HK-015、HK-016、HK-017 及相关收款／统计 HK-088、HK-100 中的独立及销售关联代办、明确的本店客户服务收入。本次提供可复核的内部办理与资金闭环，不把菜单存在等同于原表全部验收通过。

新单入口为“代办与其它客户服务”，API `/api/service-orders`。代办使用 `Case.kind=agency, flow_version=3`，其它客户服务使用 `other_income/2`。旧 `agency/1、2` 保持原流程，不能经新 API 自动升级；新版本无通用任意状态动作。

## 范围与岗位

服务可独立建立，也可明确关联本店、同一客户的有效销售单。客户主档、车辆 VIN 和关联销售必须由经办人明确选择；建立时冻结客户名称与可选车辆身份。仅显式勾选“交车前办结”的关联服务进入销售交车门禁，默认允许先交车后按实际进度继续办理。创建与办理触碰原销售版本，不能与竞争交车静默并行。

父销售发生退订／退车时，明细服务必须先在自己的原服务单完成客户同意的终止、保留费及原款退款。仅显示“完成”不能代替这项明确确认；允许客户明确保留全部已履约费用，无需伪造减费。处理妥当的服务只从父售后资金来源中排除，不能再退一次服务费或已交第三方的本金。历史排除证明按父申请时刻的不可变事件及真实资金时间重建，后来第三方迟到退款或取消父申请后新增服务不会破坏旧快照；正在办理的父售后仍重新检查当前子服务状态。

其它收入限于有业务依据的客户咨询、资料办理等本店服务。借款、股东出资、资产处置和无客户收入不在这个入口登记。代办项目使用本店启用的类型主档；其它服务项目与代缴单位有专用本店资料。代缴单位冻结真实收款户名／账户或缴费识别号，不按名称猜测另一主体。

| 分支 | 经办岗位与入口 | 必要事实、原件及原子结果 | 下一责任人、超时与异常出口 |
|---|---|---|---|
| 建立／报价 | 销售或服务顾问；明确客户及业务类型 | 冻结多行项目、数量、单价、到期日及服务费折扣；不产生现金 | 当前经办人核价，另一主管复核；任务到期按约定办理期限跟进 |
| 价格批准 | 另一位主管；当前报价 | 明确本版最低服务费、是否允许本版低价及原因；新上传客户授权类别原件 | 经办人取得本版客户授权；申请人／报价人包括管理员均不可自批 |
| 客户授权 | 原经办人；报价已独立批准 | 原件须绑定当前 `quote_id`，类别为客户授权且已通过扫描 | 财务核对实收；经办人实际办理；旧版本原件不能授权新版 |
| 实际提交／补件 | 经办人；本项目已获当前客户授权 | 真实受理号、提交日期和本次原件；补件必须引用本项目最新真实补件要求 | 经办人跟进实际结果；外部等待不生成批准或到账，超期待办仍保留 |
| 外部结果 | 经办人；最新提交尚无结果 | 明确批准、拒绝或要求补件，以及本次实际通知原件 | 补件回到经办；批准可实际办结；拒绝进入协商终止，不能标为成功 |
| 实际办结 | 经办人；授权及实际办理事实 | 代办项目须有实际批准结果；代缴行还须本金收费与第三方净支付一致；单行原金额冻结 | 财务继续收尾应收，全部事项及钱款均结清才完成 |
| 客户收款 | 财务；已授权且无正在终止的冲突 | 本单新收款原件、原账户、独立流水；唯一 CashEntry 与 PaymentLink，明细分配同事务追加 | 未付部分继续财务待办；分笔收款按未付原明细比例分配，末项承接整分余数 |
| 实际代缴 | 财务；本行实际原客户本金可用 | 选择原资金分配、原公司资金账户和本次支出原件；CashEntry 支出与 ServicePassEntry 关联，不产生客户退款链接 | 经办人继续实际代办；余额不足、原款已占退额、已办结或终止均拒绝新增代缴 |
| 第三方退款 | 财务；选择原实际代缴 | 只允许原账户、原支出未退余额内的分笔真实到账；追加原路退回记录 | 不自动改客户收费；产生未用本金时，经办人明确原客户退款方案，保留待办 |
| 终止方案 | 原经办人或主管；当前授权报价 | 逐项保留费用及减免，逐笔选择真实原客户款；新方案原件；已在第三方的本金只能保留实际净支出，不能凭愿望退客户 | 另一主管独立批准 → 客户同意 → 财务实际生效，允许生效前撤回方案 |
| 费用生效 | 财务；主管及客户已同意本方案 | 新财务原件确认原实际事项与款项；追加负收费调整，原报价／履约／现金保留 | 每条原款退款形成财务待办；本步骤不自动虚构退款 |
| 原客户退款 | 财务；已生效方案 | 选择本方案原款分配、原账户、本次退款原件及流水；分笔且合计不超过原未退资金及获准额 | 真实现金追加原 PaymentLink.out；预收抵用恢复原 Advance 余额，不产生现金；未退清继续待办 |
| 普通取消 | 经办人／主管；没有真实提交、履约、客户资金或预收占额 | 记录原因、关闭未发生的待办；不改原资金事实 | 已有实际事项必须走终止与保留费，不可用取消抹除历史 |

所有动作核对门店、岗位、接手人、Case 版本及请求编号；同事务写入报价、任务、现金、明细分配、事件和幂等回执。竞争请求有且仅有一个成功，另一方收到中文冲突提示，应刷新核对原结果，不自动换请求编号盲试。

## 费用、本金与原资金

金额为整数分，数量为整数千分位。行金额按“数量×单价”四舍五入到整分；服务费优惠按原行顺序比例分摊，最后一行吃余数，代缴本金不可折扣。已有真实办理或资金的原行不得改价、换项目、删除；新增服务另加新编号，生成新报价、主管批准和客户当前版授权后再办理。

客户收款和本店预收抵用都分配到原行。预收已批准待抵用金额先扣除可收额度；本模块不新增现金来表示抵用。集中收款的一笔 CashEntry 可以合法分配多单，每张服务单再把自己的 PaymentLink 金额分到服务费与代缴本金，不能重复计现金。原收款误记更正追加相反分配并重新分配正确事实；已代缴使用的原款须先追回，或先完成待退方案，不能通过“更正”绕过原路径限额。

代缴实际支出用 `service_pass_pay`，实际原路返回用 `service_pass_return`；这两类只影响客户本金在店余额，不改变客户已经支付的金额。客户退款用 `service_customer_refund` 并追原 PaymentLink。客户本金在店余额为“本金净客户资金－实际第三方支出＋第三方原退”，结束时必须为零或仍有明确未办／待退责任。已办结第三方返还会重新产生明确跟进待办，不能被旧完成状态吞掉。

终止的保留费不是自动罚金。经办人记录实际办理、客户同意和独立主管责任；财务核对后生效。已办结原项目的收入保留在原履约期间，后来的减免发生在生效期间。尚未完整办结但客户同意保留真实办理费时，只在终止生效日确认保留额，不确认未履约原全价。未用代缴本金与任何真实代收／代付／退款都不计本店服务收入。发票来源上限只取当前净服务费，不含代缴本金。

## 文件、恢复及接口

文件沿用统一私有存储、扫描隔离和下载权限。新报价批准、客户同意、提交、结果、终止方案使用 `authorization` 原件；实际收支及费用生效使用 `receipt` 原件。文件必须属于本单、当前岗位可读且扫描可用；集中资金原件仅通过其不可变现金分配／预收链接例外关联，不放宽成任意跨单借件。重复上传同一字节不能伪装另一次实际事实。上传关联不等于对外部原件真实性认证。

`e531_service_orders` 追加 21 张冻结表，前序为 `d430_retail_bundles`。恢复检查 `service_orders_backup_integrity.validate(connection)` 重建原报价摘要、数量／金额／折扣、独立复核、客户版本授权、外部结果、原资金分配、代缴原款账户与金额、终止批准及每笔原退款，拒绝跨店、错误路径、重复／超额分配和篡改。CashEntry 仍是唯一真实现金来源，既有整库文件／扫描／现金校验继续运行。

同事务集成接口：`source_finance` 返回原单客户结算结构；`record_collection`、`record_advance_credit` 只追加行分配；`sync_after_finance` 只更新待办及同步发票；`assert_advance_return` 验证已生效方案后，公共财务域恢复原 Advance 并返回负 CreditLink；本域追加反向行及原退款证据。`guard_order_delivery` 只判断显式交车前关联单。`source_summary` 与 `actual_income_rows` 分别提供当前余额和不可变发生期事实，报表、下钻与 CSV 使用同一集合。

## 验证与尚未承诺的范围

本域 20 项自动用例覆盖双明细分笔收款／代缴守恒、拒绝和补件、独立批准与低价／当前报价版本、收款后增项、已履约费保留、原客户分笔退款、原预收退抵、一笔集中现金多单及追加更正、岗位／跨店、原件隔离、过期请求、并发收款／退款，以及非空恢复和篡改拒绝。父售后原单排除、取消后新增子服务和迟到第三方退款的历史恢复也通过实际链路。实际 Chrome 390px 用独立销售、服务顾问、主管、财务、库管账号验证四条链，无 JavaScript 错误；截图均为独立合成数据库，存于临时目录。

本版不支持集团本金、积分、赠金、券或套餐抵付这些新服务，不伪称所有业务都可用权益。没有外部税务、政府缴费、银行或代办单位直连，也不自动认证外部文件。没有代办物料采购成本／工时成本核算、非客户会计收入、跨店服务结算或会计总账。本地合成业务通过不替代公司业务验收、正式模板确认与生产试点。
