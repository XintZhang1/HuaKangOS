## 页面验收实际操作

接待新建 → 分派 → 接待回访 → 转意向 → 转预订单 → 自动生成确认书 → 上传留痕附件 → 确认订单产生并行任务。

另检查：经营图表明细下钻、维修与会员分析、模板管理、合并新旧业务的本地日报、中文审计时间、受权限保护的文档下载、中文CSV导出。桌面和手机页面已截图检查。手机待办为卡片；截图展示管理员的全店任务，不代表普通员工能查看全部业务。

**桥接测试没有覆盖浏览器实际网络、Cookie安全属性、CSP执行、真实导航下载及公网反向代理。** 这些需要在实际电脑和部署环境执行。API级权限/CSRF测试不能代替完整浏览器验收。

## 可复现命令

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --check web/app.js
```

Node只用于可选语法检查，运行系统不需要Node。

可选浏览器脚本需要另装Playwright和Chromium，并可用 `CHROMIUM_PATH` 指定浏览器路径：

```bash
python tests/browser_smoke.py
# 仅用于明确区分的DOM+HTTP桥接测试：
python tests/browser_smoke.py --bridge --screenshots docs/screenshots
```

脚本生成临时库及随机管理员密码，关闭服务后清理，不读取正式数据库，不连接模型。正常浏览器模式已提供，但在当前受限环境不能执行。

原有业务回归测试在隔离测试环境显式开启 `LEGACY_BUSINESS_WRITE`；正常启动默认关闭。另有测试确认关闭时旧销售/维修/保单无法通过旧接口新增或变更，且生产配置禁止启用该开关。不可将回归测试模式当作日常部署配置。

## 数据与文件边界

任务、动作、金额记录可追溯，不意味着系统能够证明员工所填现实事实真实发生。重要凭据仍需适当复核。程序日志也不是外部不可篡改存证。

文件有类型、大小、配额和部分结构校验，但**未集成病毒查杀或电子签名真实性验证**。下载到本地后，系统不能继续控制复制和传播。默认模板正式环境未启用，公司需确认内容后启用；演示库启用的模板明确只用于虚构试用。

合同签回必须关联具体生成件和业务快照，文件更新后可能需重新签回。这个关联不是法律意见，也不是具有身份认证和签名验证的电子签约平台。

库存、应收、储值、任务图表是查询时的当前状态；日期区间不代表任意历史时点重建。每类明细最多25,000行，超过明确拒绝而不静默截断。客户批次转化按接待记录而不是全公司唯一自然人去重。

默认每日程序汇总可运行，可选DeepSeek仅用于脱敏汇总的文字辅助。本次未调用真实DeepSeek API；接口失败不阻断本地汇总。自动改代码、Git推送、飞书审批和自动发布已移除。

## 首轮公司试用建议

先用演示库按前台、销售、库管、维修、财务、主管轮流处理同一笔业务。重点试接待回访转意向、并行配车/签回/服务、未满足条件不能交付、退款原路约束、维修领退料、月结、跨门店拒绝访问及图表原单核对。

不要急于导入真实数据。优先确认默认岗位与交付政策，再用副本验证旧数据，最后确定新增业务的启用日期和未完成旧单的接续方案。旧单默认只读但不会自动转换为新流程，重复录入会造成重复统计。
