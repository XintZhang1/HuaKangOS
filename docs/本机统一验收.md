当前u13h原需求业务分支使用独立合成数据执行自动回归和真实Windows浏览器验证；t02g-fix1成绩保留为历史；准确结果见《验收与限制》。真实 PostgreSQL 仍单独待本机验收，不把它作为功能修复的前置阻塞。这份说明随完整源码保留；发现问题后返回失败命令、日志与最小业务步骤，不发送公司密码、连接串或完整真实数据库。

当前数据库头为 `e13r_member_fee_corrections`，新月结使用定义21，现金使用定义7；旧月结1–20的来源范围保持冻结。续会费仅支持同额的实际收款账户、凭证及证据登记更正，须独立批准；原金额、客户/会员、会期和原到账业务日期不变。更正追加原款冲正与有效替代登记，报表只计一次有效会费；后续真实退款沿有效原账户，按实际退款日期计入并保留原款依据。已有实际退款后再更正，不重写原退款或再次作废会期。

本轮最终成绩必须对应最后一次完整同源回归。此前完整或专项成绩只证明其记录的源码及范围，不能沿用为更改后的当前通过，也不代表真实 PostgreSQL、公司业务确认或正式部署通过。

## 1. 环境与边界

本轮按用户确认直接修复候选目录，原压缩包留档。重新验证时使用该候选源码及独立测试数据。按README建立Python环境并安装 `requirements-dev.txt`。应用支持范围沿README；本轮实际Python版本和依赖记录见本轮验证目录。测试使用全新合成数据，禁止把 `DATABASE_URL` 指向公司库来执行测试或 `init --demo`。

```powershell
python -m pip install -r requirements-dev.txt
python scripts/requirements.py check
python -m pytest -q --junitxml=../huakangos-local-junit.xml
```

pytest 经 `tests/conftest.py` 建立独立临时 SQLite 库，并强制普通附件使用 BLOB、清空外部私有目录；私有对象专项使用本次临时目录。测试收集/执行不是生产数据库迁移。失败时保留完整终端输出及JUnit，不把曾经通过的旧记录当作最新源码通过。

本轮完整验证使用 `scripts/verify_candidate.py`，将全部 pytest 模块分配到四个独立进程，并在运行前后比较应用、前端、迁移、脚本与测试源码。可在候选环境重现：

```powershell
$runOutput = Join-Path $env:LOCALAPPDATA ('huakangos\verification\manual-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
python scripts/verify_candidate.py --output $runOutput --workers 4
```

输出目录必须是尚不存在的独立目录且位于源码之外；日志和完整 JUnit 留在该目录，摘要写入交接。源码变动或任一分区失败均不记为通过。

## 2. 真实浏览器

实际浏览器脚本使用现有 `tests/browser_huakangos.py` 的隔离测试服务，不要求登录真实系统，不上传真实附件。需安装锁定的浏览器测试依赖，并安装Chrome/Edge或设置有效的 `CHROMIUM_PATH`；网络依赖由本机负责。下例路径需按真实安装位置替换：

```powershell
python -m pip install -r requirements-browser.txt
$env:CHROMIUM_PATH = "C:\Program Files\Google\Chrome\Application\chrome.exe"
python tests/browser_local_preview.py
python tests/browser_questionnaire_exports.py --screenshots ../acceptance-questionnaires
python tests/browser_dossier_grants.py --screenshots ../acceptance-dossier
python tests/browser_master_completion.py --screenshots ../acceptance-masters
```

目录应使用新的独立路径。首次设置组包括390px界面、过期与不一致密码拒绝、一次性提交、登录和再次启动；问卷组比较多版本单题图、明细与CSV。档案组包括原单真实建单/附件、发起/独立批准/指定员工读取、同内容未批准文件拒绝及撤销后旧链接失效。主资料组包括品牌引用/停用限制、七类字典、换店清空、参数原页面及改密对话框。实际截图与JS异常由脚本输出；t02g-fix1 的真实浏览器结果及外部截图路径见本轮验证记录；Node 契约检查不冒充实际浏览器。

已有其它业务的 `tests/browser_*.py` 脚本继续保留，参数以各脚本 `--help` 为准；逐项按原表执行，不用某两个新增页面代替整个系统验收。

## 3. 真实PostgreSQL

安装可信PostgreSQL发行版，使用它的 `bin` 目录。以下脚本创建**自己拥有的全新临时集群**，拒绝拿公司已有数据库做破坏性初始化；请使用非数据库超级管理员日常业务环境以外的测试目录。

```powershell
python -m pip install -r requirements-postgres.txt
python tests/postgres_dossier_grants.py --pg-bin "C:\Program Files\PostgreSQL\17\bin"
```

路径及版本按本机真实安装替换，不是指定必须安装17。该脚本测试真实服务器迁移、跨店原授权和文件、两个独立数据库会话争用同一复核版本、撤销后的旧链接、pg_dump/恢复、行指纹/序列及回转SQLite独立校验；合成源同时包含物资品牌/引用与领域字典。

```powershell
python tests/postgres_dossier_grants.py --prepare-only
```

后一命令**只准备并校验合成SQLite数据，不启动PostgreSQL、不算服务器验收通过**。先前检查点曾执行源准备；不能计作 t02g-fix1 的服务器通过，实际服务器分支仍待单独验证。已有 `tests/postgres_*.py` 的运输、主体、会员等专项继续按各自帮助执行，不用新脚本覆盖所有旧领域验收。
