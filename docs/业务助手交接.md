## 2026-09-27 卡片必填项光标修复（用户报告）

用户反馈："我在侧边卡片中填入信息时，填入一个数字（比如我要输入150000，输了一个1就跳出来了）光标就会跳出来无法继续输入。"

排查结论与处理：

- 打字路径本身已经没有整栏重建：`businessAssistantQuestionInput` 在 `input`/`change` 时只记值并调用 `businessAssistantRefreshGates`（只改按钮文案/可用状态与提示），不动输入框。真实 Chrome 逐字输入 `150000`、`150000.50`、含空格与中文都完整、焦点保持在原输入框。
- 仍有一条真实可复现的丢失路径：**打字过程里发生整栏/整页重画**（一轮结束、批量结果、切换"办理事项"栏、刷新结果都会重画）。此时输入框被换掉，后面的按键落空、光标消失。已修：重画前记下"正在输入的必填项 key + 光标位置"，重画后把焦点与选区放回去（`businessAssistantFocusedField`/`businessAssistantRestoreField`，用于 `paintBusinessAssistantCards()` 与 `paintBusinessAssistant()`）。真实 Chrome 复测：在 `1500` 之后强制重画再输入 `00`，值为 `150000` 且焦点仍在原输入框（整页重画同理）。
- 新增确定性回归 `node --test scripts/check_assistant_caret.cjs`（4项：打字不重画、整栏重画还原光标、整页重画还原光标、换卡片才允许重画）。

本轮验证（不新增业务验收成绩）：新回归 4/4；真实 Chrome 光标检查 6/6；归档检查套件在本机镜像中运行——`check_ux.py` 8/8、`check_workspaces.py` 18/18、`check_ux.cjs` 29/30、`check_workspaces.cjs` 21/23，后两项的失败在**未改动的 HEAD 上完全相同**（归档用例断言的是 R4-B1 已改掉的旧文案），`build_workflow_guides.py --check` 的失败同样在 HEAD 上复现（R4-B1 改过 CSS 后未重新生成手册）。这些属于既有漂移，不是本次改动引入。
