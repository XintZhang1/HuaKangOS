# 业务助手接入飞书（自建应用 + @机器人）· 想法记录 2026-09-25

> 状态：**仅记录需求与设计要点，尚未实现、未验证**。这一页是给后续开发用的约束清单，
> 不改变现在网页端助手的任何行为。

## 一、业主原话

“我们这个助手完成以后需要接入到飞书，所以现在业务助手的网页端的工作流，也会通过企业自建应用接入飞书，通过 @机器人的方式收发指令。”

## 二、目标形态（我的理解，待你确认）

- 企业**自建应用**（不是第三方应用、不上架应用市场），用飞书的机器人能力。
- 员工在群里 **@机器人** 或在私聊里发一句话，助手按同样的业务助手逻辑回答、准备确认卡。
- 确认也在飞书里完成：确认卡以**交互式卡片**呈现，点“确认”才由原接口执行；不想在群里点也可以回到网页端点。
- 员工在飞书里发的就是现在那 27 条口语化 prompt 那种随手说的话；不需要记内部编号。

## 三、必须先定下来的（需要你决定）

| 议题 | 选项 | 影响 |
|---|---|---|
| 身份对应 | ① 飞书 user_id ↔ 本系统账号一一绑定（推荐）；② 群里谁 @ 都以“机器人身份”查询 | ①能沿用岗位/门店与全部留痕；②等于绕开权限，不做 |
| 首次绑定 | ① 员工在网页端生成绑定码，飞书里发给机器人；② 管理员在员工账号页维护 | 绑定关系本身也是权限事实，需要审计 |
| 使用场所 | ① 只允许私聊机器人；② 允许业务群里 @（易泄露客户信息） | 涉及客户姓名/电话/金额，建议默认只私聊，群里回复只给“去私聊看” |
| 门店上下文 | ① 绑定账号时确定默认门店，可切；② 每条消息都要求带门店 | 与网页端“当前门店”语义保持一致，禁止跨店汇总 |
| 确认卡位置 | ① 飞书卡片点确认；② 飞书只发提醒，回网页端确认 | ①体验最好，但要处理卡片回调签名/重放/超时；②最稳 |
| 谁收到评审通知 | 沿用现有评审通道（本店店长 / 集团管理员），飞书只做**通知**，办理仍在原业务页面 | 与 2026-09-24 裁定一致，不能让飞书变成第二个权限入口 |

## 四、实现上必须保持不变的（现在就要守住的接口边界）

1. **助手契约不变**：以员工本人身份调用已评审接口，能不能办由接口判定；超出权限就提示可提交评审申请；
   中间单据先补前序事实。飞书只是**另一个入口**，不是另一套权限。
2. **确认仍由人点**：飞书卡片必须带一次性凭据（digest + 过期时间），点击即原接口执行；
   不得出现“@机器人一句话直接落库”。
3. **不新增旁路**：飞书适配层不允许直接写业务表、不允许绕过岗位/门店/版本/幂等/证据校验；
   也不允许把凭证（密码、密钥）或原始文件发到飞书。
4. **消息内容同样脱敏**：沿用现有 `scrub()`/`SECRET_KEYS`/`DENIED` 规则；飞书群里默认不展示客户敏感字段。
5. **幂等与重放**：飞书事件会重推（回调重试），必须用飞书的 event_id 做去重，助手会话按 `request_id` 幂等。
6. **审计留痕**：谁在飞书里问、问到哪张单、生成了哪张卡、谁点了确认，全部写入现有审计表，
   并记录渠道（web / feishu）。
7. **限流与配额**：一个人一分钟内能发多少条、一轮最多多少工具轮次（当前 24 轮/每轮 6 工具/单轮 300 秒），
   在飞书侧要同样的上限，避免刷额度。
8. **失败要说人话**：额度不足、连接异常、超时、被权限拒绝、业务规则不允许，五类分开表述
   （现有的错误分类可直接复用）。

## 五、落地顺序建议（等你说开始再动）

1. **先把网页端跑稳**：R02–R14 试用、口语化 prompt 批次、确认卡实测；把助手的问题清单清干净。
2. **抽一层渠道适配**：现在是 `app/business_assistant_service.py` 的 `messages → model_reply → run_tools`，
   把"会话/消息/确认"抽成与渠道无关的内核（网页端先调用它），飞书再挂第二个适配器。
3. **飞书应用与回调**：自建应用 → 机器人能力 → 事件订阅（接收 @ 消息）→ 请求签名校验 → event_id 去重 →
   调用渠道无关内核 → 交互式卡片回调（确认/取消）。
4. **绑定与开通**：员工账号页生成绑定码 → 飞书私聊发码 → 绑定落库（带门店与审计）→ 管理员可见/可解绑。
5. **验证**：真实飞书租户里用员工账号跑同一批口语化 prompt + C01/C02/C03 确认卡；
   断网/重复推送/额度不足/跨店/非绑定用户 五类异常各一条用例。
6. **再谈通知**：评审申请、任务到期、审批完成是否推送到飞书，按你的选择逐项开。

## 六、这一页不承诺什么

- 不等同于"飞书就是一个新的前端"：网页端仍是有权限、有留痕、有完整页面的正式入口。
- 不做无人值守：不自动确认、不自动审批、不在飞书里改权限或改配置。
- 公司实际业务验收、生产部署、真实 PostgreSQL 仍是独立门槛；飞书接入同样需要单独一轮评测与证据。
