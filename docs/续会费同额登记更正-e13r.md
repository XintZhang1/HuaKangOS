# HK-090 续会费同额登记更正

2026-09-23，候选目录专项已实现并冻结。最终整树回归及保留账户的预览升级由总集成记录统一确认。本说明不修改需求台账状态。

## 业务入口与不变量

财务在“业务财务结算 → 本店客户 → 更正续会费登记”选择已经实际收到的本店正数续会费，填写正确原账户、流水或凭证及原因。新能力由目录 `member_fee_corrections` 门控；旧后端不会因加载新脚本而出现未发布按钮。

系统固定原金额、会员、原会期、原实际到账日。申请不能携带金额、会员、期间或日期覆盖值。即使当前会期、等级或规则已变化，更正仍只处理该笔历史登记，不重算卡、会期、等级、钱包、券包、积分或其他权益。

申请由财务发起，另一位本店主管独立批准，当前财务待办经办人执行；管理员也不能自批。两天到期待办沿既有业务财务责任机制。审批和执行分别要求本单可用凭据。批准前可以退回，执行前可以明确取消；取消释放原款办理占用。完成后保留事实，只能从后继有效原款追加另一笔更正。

执行在同一事务追加原款记账冲正、同金额正确登记及不可变更正事实，不修改原 `MembershipFee`，也不追加第二笔正会费。正确登记仍使用原实际到账日期；记账冲正不是客户实际退款，不产生钱包、权益、支付关联或清算。

## 与真实退款的关系

登记更正不调用 `renew_refund`。原续会单的版本写锁供两类动作共同使用，SQLite 下也实际触碰版本，不能仅依赖 `SELECT FOR UPDATE`。

在办真实续会退款会阻止批准原款更正；已批准更正会阻止新实际退款。双方可先完成或明确取消再继续。并发争用同一原来源只能由有效的当前状态办理，不盲目重试。请求号、内容摘要、财务单和原来源版本共同防止重复与陈旧操作。

未来真实退款按更正后的有效原账户办理，原规则的未生效、整笔、独立批准等限制保持。每次新真实退款另存当时有效原现金依据，仍关联原正会费。已经实际发生的退款继续保留原金额、账户、凭证、日期及会期作废事实；之后的同额登记更正不会重新付款或恢复会籍。

## 数据、权限与集成

追加迁移 `e13r_member_fee_corrections`，上接 `d02q_partial_corrections`。新增三表：申请 `membership_fee_correction_requests`、不可变执行事实 `membership_fee_corrections`、不可变真实退款原款依据 `membership_fee_refund_bases`。旧迁移不改，不从运行时模型生成历史迁移。

`FinanceOrder` 新用途为 `fee_correction`，沿用 `business_finance/v2`。创建值严格为 `fee_id/original_cash_id/source_version/account_id/reference`。金额、原账户、原日期、原单及已退款事实由服务端冻结。申请只有状态、版本与更新时间可变，其他字段受不可变守卫保护。

新财务原单、事件、附件和候选原款限本店财务、主管、管理员或审计员按权限读取；审计员不办理。销售、服务、接待、客服等岗位不读新财务原单。会员退款结果对非财务岗位仅显示已按原款办理，内部原现金和会费编号不通过事件旁路泄露。集团汇总不能办理或读取新财务原单。

原账户和正确账户必须符合原经营主体。新更正继承有据原现金来源，新真实续会退款用明确 `membership_refund` 派生类型继承原收费会期的主体。未知历史保持未知，不因本店后来启用主体策略而取得当前法人。

总集成采用现金定义 7、月结定义 21。原误记和记账冲正从新现金口径排除，正确登记只计一次；原 `MembershipFee` 报表仍是一行原金额，另附有效登记投影供现金日期查找。原现金定义 1–6、月结定义 1–20 不扩充新来源。更正自身不增加经营收入，真实退款仍按实际退款日统计。

独立恢复从原正会费、原会期、来源链、冻结账户日期、三笔现金、独立批准、执行证据及实际退款时点重放；删除整套新表、孤立现金、串店、篡改金额或退款原现金均不能仅靠重算月结摘要掩盖。合法旧退款没有新依据表记录时仍保留原恢复语义。
