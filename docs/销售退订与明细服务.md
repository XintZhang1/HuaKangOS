# 新销售退订与明细服务

`order / flow_version=4` 的未执行退订不替加装、保险和代办业务确认取消。各服务单即使只有待核价草稿，也须由有权岗位在自己的入口明确取消。父订单“申请退订”“批准退订”“原收款退款”三个关口都会再次检查：全部关联加装、保险、代办单必须已取消或已拒绝。服务已实际执行后再独立终止、结清而得到 `completed`，仍须走原单售后，不视为未执行取消。

主管批准时检查最近一次有效退订申请的实际经办人，申请人即使是管理员也不能自批。申请被退回后重新提出，按新申请人判断，不用原订单创建者替代本次经办人。

各子单仍完整保留取消原因、岗位记录和已生成资料。父单无实收款时，主管批准退订后释放原 VehicleHold；有实收款时进入财务退款待办，沿原 PaymentLink 和原账户实际退款，净实收归零后释放车辆占用。批准本身不造退款现金，也不改变车辆库存成本。已经出库的整车不能走这个退订入口。

父单进入退订审批、退款等待或已经取消后，不能再新建或继续办理关联明细服务。需要恢复办理时，先由主管退回退订申请，使父单恢复原状态，再办理子单。携带最新父版本也不能绕过状态限制。

父退订动作先锁并触碰父 Case 版本，然后读取子单集合；三类子单创建及命令也在同一事务触碰父 Case。两个请求竞争时，要么成功建立子单而退订冲突，要么成功进入退订而子单创建冲突，不会留下父单正在退款但子单继续执行的合法组合。请求、任务、车辆占用和资金记录仍一次提交。

只对新的 `order / v4` 增加这组规则；旧 `order / v2、v3` 的动作语义没有重新定义。现有报价变更期间允许的子单整改、处置和退出规则继续保留，新守卫只针对明确的父退订状态。

实现位置：`flow_engine.blocker/_process_action`、`sales_quote_service.guard_child_action/guard_source_action`，以及 `insurance_service`、`addon_service`、`service_orders_service` 的同事务父源检查。没有新增迁移、任意状态接口或现金写入入口。

`tests/test_sales_cancellation_v4.py` 六项通过：三域显式取消后无款退订释放车辆；实际订金退款与两阶段最新父版本新建拒绝；过期/重复/跨店请求与退回后恢复；子单创建和父退订竞争；已执行且独立退保结清仍须售后。每项把非空合成库复制到独立 SQLite 并执行全量恢复校验，验证来源、现金、车辆占用和账本一致。退订六项通过，保险十六项通过；新增独立复核测试在原组合通过后复验。公司业务验收及正式启用状态仍未验证。
