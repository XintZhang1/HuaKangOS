# 可视化指标口径

开发中u13h：佣金发票只采用独立批准的实际佣金，客户保费不占额度。回访合并原callback及新销售/维修回访，按建立期间看当前进度，多次跟进不重计，财务及集团只看分类数量。新月结definition13与现金定义4纳入更正/预付原来源，旧1–12集合字段不扩展。完整口径和验证边界见《保险佣金发票与回访统计-u13h》；后文历史说明按原版本阅读。

后续原分支口径：供应方超收应退单列为负债，实际原账户退款计一次现金支出，不用负应收抵其他客户欠款。厂家及供应商整车收入按独立批准日记每版目标差额，按真实到账/退款日记现金；客户原销售的应收保持独立，未指定逐车分配的厂家收入不自动摊入车辆毛差。图、表、CSV来自同一集合；集团页按授权门店只读汇总，不暴露该收入原单、供应商身份或凭据。返修原责任计内部承担，仅新增客户行形成客户应收/收入，原店旧现金不复制。月结definition14/15/16依次增加供应方退款、非客户整车收入、本店返修责任分类，旧版本不得扩充。开发中专项证据见《verification/u13h-in-progress/专项进度》。

组合充值更正采用现金定义5和月结definition17：本金按有效原收款，赠品按原批次不可变单位差额复原；同额更正账户不发行第二份权益。会员等级实际定价的月结definition18只冻结本店批准规则、报价分摊及授权依据，不另计现金或收入；实际应收/原退继续使用所属业务的原折后金额。该会员功能正在接线，当前通过范围以专项记录为准。

独立栏目提供经营总览、整车销售、整车库存、维修服务、物资周转、财务收支、客户跟进、会员储值、工作协同9个视图。增加集团本金/权益往来、物资与整车在途、内部往来及权益单位图。折线/柱形使用同口径明细；柱形以零为基线，负净额绘在零线以下。

## 日期与数据范围

报表默认近30天，可选不超过一年且不晚于今天的区间。所有查询按授权门店范围，不允许通过“汇总”读取未授权店。金额内部为人民币分，图表和表格显示元，金额轴较大时以“万”标注；不会把不同物资计量单位相加。

**期间指标**按实际业务日期过滤；**存量指标**为生成时最新有效记录。库存/待收款/储值余额/任务不因选择上月就变成上月快照。客户转化按所选期间接待形成同一批次，截至当前查看其后续转化。历史业务若有后续有效调整，重新查询会按当前有效状态重算；已保存的日报保留其生成时快照。

## 图表与明细一致性

维修进度图看本期创建工单的当前进度；维修结算趋势看本期实际交还的工单，所以它们有不同明细，不能共用开单日期筛选来假装相同。会员变动图对应期间储值流水，不下钻到当前余额表。

图表“明细”展示该图完整对应数据集；“原单”进入具体业务，部分主数据进入对应目录。库龄、待办风险提示的“查看”目前进入相关完整明细，不自动只筛命中子集。目录跳转不是全部都定位到某个编辑行。

新旧业务、付款和客户接待没有自动去重迁移：同一真实业务如果又录为新单，会重复统计，需通过数据迁移或人工核对避免。统计不能修正从未录入或被填错的现实事实。

本版每类数据表设置25,000行上限，超过会明确拒绝，**不会截断后悄悄返回错误总数**。后续应升级数据库端聚合/分页钻取，而不是只提高内存上限。

尚未实现完整原表的每张统计报表：全类型整车及分库位历史入出存重建、厂家返利和综合毛利、完整服务单分析、客户价值、完整积分/券专项分析等。新增明细和图表不代表原表36项统计已完整交付。


## 新增维修、权益及整车口径

- 维修v3按实际接车日统计外部承担（客户、保险、厂家），内部承担排除。当前应收按每一外部承担方自己的到期日和实际已结列示，客户已付可接车不代表保险/厂家到账。
- 权益抵扣面值C、购买对价P、内部结算价S随发行规则冻结。本版约束P≤C；集团承担优惠时S=C，履约店承担时S=P。购买现金先作为实际现金和预收事实；履约对外结算按P确认，原工单外部金额减C−P；集团承担S−P、服务店承担C−S分别列示。内部S不重复算营业收入。
- 赠金用分、积分用整数、券与套餐用次数，四种单位分别成图，不能相加。期间核销与冲正正负对应，未用退款只冲原发行现金和剩余单位，不能再次冲已经履约收入。
- 整车实际调出后原库存不可分配，在途由调出店计一次；合格接收或原店实际退回后创建新的库存代次，原车辆门店归属不变。申请占用、在库、在途分开显示，拒收/退运不自动清除在途。
- 整车内部往来以双方合格接收时冻结成本配对，不产生现金或对外营业收入。选择全部相关授权门店时配对净额为零；单店显示本方待清算额。

对应数据集为 vehicle_transit、vehicle_clearing、benefit_bonus、benefit_points、benefit_coupon、benefit_package、benefit_redemptions、benefit_clearing，图与明细/CSV读取同一数组。期间表过滤实际账本日期，当前往来和库存表不伪装历史期末重建。

## 新增采购、精品与实际清算

- 精品在客户实际验收日期确认冻结报价减此前已验收退货金额；后来退货在实际退货日期冲减当期收入和原商品成本，不改写原交付月。已获事先授权的安装保留费继续保留。此直接毛差尚不含人工成本。
- 整车采购的约定、净到货、净付款、应付、预付及供应商应退按当前原单计算；实际出入库按Movement业务日期。供应商发运而本店尚未验收的车辆另列采购在途，不能计入可分配库存。
- 单店实际收支包含本店店间清算真实收付款；集团对外收支排除标为interstore_clearing的内部现金。所有相关现金另外进入internal_cash明细，不因抵销消失。付款后对方尚未收款的金额列internal_cash_transit，收到后才归零。
- 物资/整车往来展示原配对余额加已结清的ClearingOffset。同一笔申请尚未两方实际确认时不冲销往来。两店全部授权的净余额可抵销为零，但未收在途款仍单列。
- 期间对账版本冻结生成时可核对来源及当前应收，独立封存只确认这一版。晚到记录需要复开后继版本，不假定原业务被全局封锁，也不把当前应收称为历史月末余额。
- 物资期间入出存另见《物资期间入出存》；它从全部有据期初和库存流水重建，不以当前库存减后续变动来补造缺失期初。物资预占仍只反映当前。

图表/明细/CSV共用retail_settlements、retail_orders、vehicle_procurement、vehicle_procurement_transit、vehicle_procurement_movements、internal_cash、internal_cash_transit集合。内部现金有各自本店原单；人员无权读取的客户服务任务不进入其可读任务统计。单店管理员的全局审计范围0不被当成第二家经营门店。

## 库位、会员办理、接待及实际票据

- warehouse_balances 为当前已明确启用物资的库位及店内在途分布，与 Item 数量/价值核对不符就拒绝出报表；它属于已有库存，不另加一次。warehouse_local_moves 按期间全部配对位置流水展示实际发出/接收/退回及移动平均分摊，净价值变化应为零；warehouse_counts 只计已批准实盘差异 StockMove，已包含在出入库成本中。
- membership_fees 按关联现金的业务日期列实际续会费与原款退款；现金已记录一次，不等于会期收入摊销，也不是本金充值。membership_points 是冻结规则下应得积分目标的有符号变化，消费基数为变更后状态不能逐行相加；membership_points_debts 单列当前未追回积分、原债ID及原消费单，不作现金应收。实际可用积分仍查询权益单位账。
- service_appointments 按计划开始当地日期取接待批次，查看当前状态；改约可改变批次。service_arrivals 按不可变到店事实及返修现场核对事件的当地日期计数，到店后离场仍保留事实；不与另一批次人数混算转化率。service_resources 是实际工位占用，不按预约结束自动释放，不作员工考核。
- invoices 按实际票面日期统计新专用蓝减红，invoice_corrections 列原业务当前超额待核对。申请和待冲红没有实际结果时不计票额；票额不是收入或到账，原单变更不会抹掉真实票据。
- 新月结来源定义2纳入上述实际票据、库位流水/余额、续会费、积分目标/抵债和当前未追回摘要。保留历史定义1的范围与哈希，不因软件升级自动扩张旧批次；需要补核对时另建后继版本。各来源独立核对，不把重复关联的金额相加。

上述图表、明细和CSV均读取同一数据行集，详见 operations_analytics、invoice_analytics 及各业务专项测试。只有新接待来源有实际到店事实；完整进出厂、全部36项专项报表仍以需求台账逐项记录。

## 本批新增口径（x824）

加装、代办、保险完工及维修项目/配件取原实际事件和其冻结报价；保险保费、预计佣金、客户业务收入分开。精品施工按实际安装事件，安装之后的退货不抹去施工事实。客户车辆按明确共享身份去重，不按电话归并。

车辆交付/维修原结算额保持原履约日，实际售后减免按生效日负数单列；recorded_business_net 为原业务事实加本期已确认收入减免，未履约退订单不造负销售收入。套餐退回按原对价处理，原优惠不在两个期间重复抵减。现金退款按实际现金日列示，减免不代替退款。

新增通用预收余额/变动、客户最新月结分配余额、原款分配、误记更正、其他退货应收六表；冻结客户账单不是第二笔应收。整车当前库位、实际移库、其他出退库与隔离在验车辆分别展示，位置变化不冒充第二次入库。图表、明细与CSV使用相同集合。

定义1/2已封存的对账仍按原现金集合核对；定义3及后继保留更正后的现金口径，保留全量原现金来源并明确排除误记及冲正ID。详细来源、例子和恢复拒绝测试见[专项统计与售后口径](专项统计与售后口径.md)。

## a127 期初与充值组合口径

- opening_account_balances 是当前余额：已确认日初 OpeningAccountEntry，加期初日起按现金口径3核对的实际收支。期初余额不是 CashEntry，也不计期间收入；误记原款和其纠正冲正不再分别膨胀收入及支出。账户身份/期初日期冻结。
- recharge_bundle_cash 按原实收/实退 CashEntry 的业务日期列充值组合净现金。本金100元和赠金10元只收100元；赠品发行不会再生成现金。该表是现金的专项明细，不再加到集团总现金或销售收入。
- recharge_bundle_bonus / points / coupon / package 按实际发行与原组合退款回收的当地日期列带符号赠品单位。赠金为分，其余为积分/张/次；不把发行数当已核销、当前余额或履约收入。跨店使用沿原权益流水统计。
- recharge_bundle_refund_holds 列当前获批未实际退款的原组合本金占额；已计集团本金占额，只作原单下钻，不能重复扣减。原赠品同步占额，已使用的发行批次不能由另一批次补足。
- 新对账定义4纳入以上原组合订单、发行、原赠品和退款过账，以及期初确认/原始资金车辆条目和私有对象引用。旧定义1/2/3保持原范围；现金计算仍使用已验证的口径3。修改新来源关键原始字段即使重算摘要，恢复检查也会拒绝。

图表、明细和CSV使用 foundation_analytics 的同一集合；集团可看统计但不获得新期初或套餐业务办理入口。专项验证见 tests/test_foundation_analytics.py。


## d430 核赔、客户报销与精品套餐

- claims_responsibility 按实际责任调整日显示保险/厂家负额与内部正额，同一调整配对为零；内部承担不计客户应收或维修对外金额。
- claims_business_adjustments 只把原外部承担减免计一次业务净额。先履约后调减在生效期扣减；先调减后履约随原交车确认，不能在尚无原履约的月份先记负收入。原报价/原结算保持，实际退款只改现金。
