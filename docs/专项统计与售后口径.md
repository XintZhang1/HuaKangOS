# 专项统计与售后口径

建设版更新：2026年9月21日。以下是已实现分支的统计合同，尚不是全部36项统计需求的公司验收记录。

## 员工查看与核对

具备经营统计权限的店长、财务、审计或管理员，在“数据可视化”选择当前门店和期间。图表右侧“明细”进入相同记录集合；“查看原单”回到业务，“导出明细”下载相同集合的CSV。集团汇总只查询获权门店，办理动作仍需选择门店并具备该店岗位。

客户分析按明确关联的客户身份归集；同名或同电话不合并。没有关联客户的历史单据单列，不悄悄丢失金额。客户详情只导出当前客户、当前期间和获权门店的数据；手机以逐笔业务卡片显示日期、金额和原单入口。财务的车型统计不提供客户车辆隐私历史入口。

## 来源与期间

| 数据集 | 原始事实与口径 | 边界 |
|---|---|---|
| addon_orders / addon_completed | 前者按建单日查看本批当前进度；后者按实际完工事件及该事件前最后一次核价 | 办理金额不是到账；售后另列实际调整日期 |
| agency_orders / agency_completed | 代办建单批次、实际办理完成及相应核价 | 不把任务生成当作已经办理 |
| insurance_orders / insurance_completed | 原保险单、实际出保事件、代收保费与预计佣金分别显示 | 保费不是收入；预计佣金尚无真实确认收入事实，不能混入客户业务净额 |
| repair_projects / repair_parts | 实际接车日期、最终结算所引用的冻结报价及项目/配件明细 | 原报价范围含各承担方，不能冒充按项目分配的客户实收或外部收入；旧报价不重复累计 |
| retail_installation | 实际安装事件、原安装范围减安装前已实际退回的部分 | 后续退货不能抹掉已经完成的施工；不同物资数量不混加 |
| customer_vehicle_stats | 获权范围有效客户车辆关系，按明确共享车辆身份去重 | 当前关系数与车辆数分开；冲突车型列待核对，不推断所有权或历史期末库存 |
| customer_value / customer_value_details | 原交付、对外维修结算、精品履约及加装代办核价，加本期对应售后调整 | 充值、预收、保费及预计佣金排除；不是利润、未来价值或员工考核 |
| aftercare_adjustments | 已生效售后方案及原单减免、Application业务日期 | 原现金退款不再次扣业务金额；未交付车辆原价减免不制造负收入 |
| business_net_facts | 上述原履约事实与实际发生期的售后调整逐笔并列 | 原交付/结算表保留毛额，净额看此表；不把完整历史改成当前净价 |
| vehicle_locations | 已明确定位车辆的当前在位、店内在途或待客户交接状态 | 属于库存分布，不另加库存；未定位旧车不能猜库位 |
| vehicle_location_moves | 实际店内移库发出、接收、拒收原位退回的位置流水 | 期间只发出可能为负；在途仍归本店资产，位置变动不作采购或销售 |
| vehicle_other_movements | 实际退出库存、原车退回及客户退车最终验收入库的库存增减 | 批准、隔离接收不增加可售库存；采购/调拨位置流水不重复计入 |
| vehicle_return_quarantine | 已实际隔离接收、尚未合格入库或实际交还客户的车辆 | 单列现场隔离位置，不作可售库存或退款已完成的证据 |

例如：昨天维修结算109.97元，今天经独立批准减免20元。昨天的原结算明细仍是109.97元；今天的业务净额调整为−20元。之后真实退20元时，今天现金支出增加20元，业务净额不再减少。两天合计业务净额89.97元。

## 现金与月结版本

真实现金只有CashEntry这一份来源。客户月结的一笔到账可以通过经校验的财务批次分配到多个PaymentLink；报表按现金行统计一次，下钻到原财务批次，再查看原单分配。预收抵用只改变结算关联，不再产生现金。

误记更正保留原现金、追加账务冲正和正确记录；正确记录采用冻结的实际到账日期。实际现金统计排除被替换的原误记和账务冲正。后者不代表真的退给客户；原记录仍可追溯。

新对账来源定义为3：保存原始现金集合及冻结的排除集合，并将财务批次、分配、更正、预收、原权益退回、售后调整和车辆位置事实纳入各自来源。恢复时核对冻结摘要、原单归属和排除集合对应的原更正批次。旧定义1/2仍按其原始现金口径读，不覆盖旧快照；采用新口径须明确建立后继版本。

## 已执行验证与限制

专项自动验证见 tests/test_service_analytics.py、test_customer_analytics.py、test_aftercare_analytics.py、test_vehicle_operations_analytics.py、test_operations_reconciliation.py。已通过实际Chrome员工390px浏览器的客户明细、原单跳转、CSV下载；脚本为 tests/browser_customer_analytics.py。各资金和实物分支另有本域测试。

上述结果只代表合成数据验证。全部统计字段、经营定义及正式启用仍需按193项台账逐项验收。车型、客户、工时和配件的更细业务维度、完整整车期间入出存及公司确认的成本口径继续追踪，不用现有图表替代未完成需求。
