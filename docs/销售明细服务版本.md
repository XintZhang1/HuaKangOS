# 新销售与明细服务版本分派

新销售使用 order / flow_version=4，报价、配车、独立批准、客户签回、PDI 与实际交车沿用已经明确的报价规则。新版本的区别是客户签回当时，按明确选购的另单服务创建 addon v3、insurance v3、agency v3 的待办与来源快照。创建待办不确认服务收入、库存领出、保费到账或实际投保。

既有 order v3 保留旧的 v2 配套服务分派；已有明细服务仍可按明确来源关联既有订单。不会根据菜单或旧数据推断未结业务应如何迁移。其它内部子单例如交付回访仍按既有 v2 规则创建。

新报价移除配套服务或变更车型前，必须先在相关原服务单处理取消、终止或原实物；不能通过修改车辆报价绕过原保单、原领料或收费。已存在未取消的配套业务不因再次签回创建第二份。服务是否阻断交车由明确的 delivery_blocking 约定和本域实际事实决定；保险佣金待结不自动阻断实际投保已办妥的交车。

整车售后排除已独立结清的明细服务时，分别冻结 service、insurance、addon 的原单编号清单，并与原申请事件一致。恢复验证使用申请时已经发生的事实，避免后来的合法记录改写早期证明。加装随退车无偿移交还必须在整车售后生效前有真实收车、新库存代次和装件清单，库存及车辆成本不凭空增加。

月结来源定义升级为 7，新增采购成本差额、保险及加装的不可变原事实。旧 1–6 定义继续保留。已确认保险佣金按独立审批发生日和累计目标变动计入业务金额；保费和预计佣金不作为门店收入。加装按客户实际验收和原单实际退回列示净额，现金仍只从 CashEntry 计算一次。

2026-09-21：新销售自动创建三类明细域、实际服务净额、佣金/保费/现金分离、CSV 和 v7 月结原件篡改拒绝已有专项验证。全量、PostgreSQL、正式模板及公司业务验收以总记录最新证据为准。
