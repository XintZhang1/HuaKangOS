## 运行与配置

需要 Python 3.11–3.13，依赖见根 `requirements.txt`。Windows 推荐 `start-preview.cmd`：账号和数据按源码目录存放到 `%LOCALAPPDATA%/huakangos/preview-<目录标识>/`，首次由页面创建管理员。移动源码到新路径会产生新的预览身份，不能把“新路径没有老账号”误认为数据删除。

普通启动使用 `start.ps1` / `start.sh`，首次复制 `.env.example` 并交互初始化管理员。默认 SQLite 位于 `data/dealer.db`。只有在全新、独立的模拟库上使用 `-Demo` / `--demo`。Node 仅用于前端开发验证，运行页面不需要 Node。

业务助手配置在仓库外，详见 [业务助手交接](业务助手交接.md)。日报开关与助手开关不同。未配置助手不会阻止原生业务页面运行。

## 升级、备份与部署

现有库升级前：停止相关写入，执行一致性备份，复制到独立位置迁移并核对记录/附件，再验证恢复，最后才升级原库。不要用 init --demo、seed 或测试操作已有库。

常用管理命令（先确认 DATABASE_URL 指向正确目标）：

```text
python -m app.cli backup --output <仓库外的新备份路径>
python -m app.cli migrate
python -m app.cli check
```

SQLite BLOB 模式备份包含库内附件；private_local 模式需要数据库与私有对象联合备份目录，可用 `verify-backup`、`restore-backup` 验证及恢复到全新目录。PostgreSQL 使用对应数据库工具备份/恢复；`requirements-postgres.txt` 提供额外驱动。`scripts/migrate_database.py` 只用于人工控制下向空目标库转移，不能拿来覆盖运行中的库。

`Dockerfile`/`compose.yml` 是运行示例，不自动建立已验收生产环境，也不自动替你处理数据库升级。生产仍要求 HTTPS、安全 Cookie、明确 Host、ClamAV、禁止 legacy write、备份恢复和公司验收。独立日报/提醒进程的 service 示例在 scripts，按实际路径与调度模式配置。

## 打包

在 Git 检出中执行：

```powershell
python scripts/package_source.py
```

默认写入仓库同级、带时间戳的 ZIP，并给出 SHA-256。也可用 `--output` 指定仓库外新路径，已有文件拒绝覆盖。打包读取**工作树当前文件**，含未提交修改，已删除的历史文件不会因仍在 HEAD 里而被带回；不必先提交，也不应使用 `git archive HEAD` 打包未提交的清理结果。

工具从 Git 跟踪文件及未被忽略的交付目录新文件取材，按目录和后缀排除私有数据；打包前应检查新增文件。解压交付包运行不依赖 Git，但再次使用此打包工具需要 Git 检出。源包安装依赖需要联网或另备依赖镜像，本包不是自带解释器的离线安装器。
