# huakangos 升级部署与恢复

当前代码为0.4建设版，目标仍是完整v1。正式启用须完成《验收与限制》中的公司业务周期和部署验证。没有替用户部署公网、注册系统服务、推送仓库或创建外部自动任务。

## 先留原目录，不要原地覆盖

先停止原服务并用原环境的一致性备份命令保存数据库。0.2的自动维护/监督进程也需停止；本版不再使用它的发布目录、Git权限或飞书密钥。后续可由你撤销不再需要的远程凭据，本包不会替你操作外部账号。

把huakangos放到独立目录。复制 `.env.example` 为 `.env`，重新填数据库和必要参数，不整份照搬0.2维护配置。新建独立虚构试用库使用 `-Demo`，并明确配置 `FILE_SCAN_MODE=structure_only`（只做结构校验、未查毒）。正式环境禁止演示初始化。有旧业务数据则先把备份复制到新文件，用配置指向复制件，执行 `python -m app.cli migrate`，不要带演示参数。

升级脚本保留原19张表数据并新增流程表/扩展角色约束。旧的维护历史表仅为兼容保留，没有接口、进程或后台执行能力。原有销售/维修/保单不自动变成新流程单，默认只读；未完成旧单先设计接续和对账，不能随便重新录单造成重复收款或重复库存。

`LEGACY_BUSINESS_WRITE=false` 为默认。这个开关只有离线历史导入/回归测试可能需要，生产配置禁止开启；它不是日常员工功能。

## 验证顺序

核对门店与员工、旧单数量、销售和维修历史、库存、资金流水、日报；再新增一条流程业务，实际走完并回看统计。正式切换前练习从备份恢复到另一个库，并通过系统打开附件下载，验证不是只有一个空数据库壳。

本轮在Windows完成本地真实Chrome员工网页验证，并用临时PostgreSQL完成迁移、版本/锁冲突、转库和dump恢复核对，详见《PostgreSQL验证》。这不等于真实多门店负载、生产HTTPS、Docker或macOS平台验证。SQLite仍用于有限人数试用。

## 一致性备份

```bash
python -m app.cli backup --output /安全目录/备份.sqlite
```

不要在SQLite正在写入时只复制主 `.db` 文件而忽略日志。该命令使用SQLite备份API，检查完整性、外键、所有附件大小/SHA、最新扫描状态对应关系、集团本金/占额及配对账、物资与整车调拨库存映射、集团权益单位/占额及内部往来。检查失败保留目标供核对，不称为已验证备份。附件和隔离状态在库内一起保存。程序未安排自动备份，也不替你保管备份密钥。

恢复：停止服务，先保存当前库，以一致性备份替换另一个新库路径，检查完整性与外键、文件SHA并登录验收，再切换配置。不得同时保留同名旧WAL/SHM文件去拼凑新库。恢复为旧备份会丢失备份之后的业务，需要先制定补录/核对方案；本版不会自动回放外部交易。

## 服务器

技术示例位于 `Dockerfile`、`compose.yml`、`scripts/dealer.service.example`、`scripts/Caddyfile.example`。它们是部署起点，不是本次已实测的公网安装方案。

正式启用前至少配置：HTTPS；`APP_ENV=production`；`COOKIE_SECURE=true`；明确的 `ALLOWED_HOSTS`（移除testserver，不能*）；`FILE_SCAN_MODE=clamav`和受私网访问的扫描服务；仅反向代理能访问业务端口；最小权限服务账号；数据库和备份只读写给服务角色；建立定期备份及恢复演练。

新上传文件默认隔离；旧文件没有扫描记录也隔离，不能因升级就自动放行。扫描失败不允许下载或用于业务/签回，获权员工可重扫；不得通过改用结构校验绕过已发现风险。详见《附件安全》。当前附件仍为有配额的私有数据库BLOB，较大正式规模的对象存储、分片、留存及联合恢复仍需建设。

Caddy示例允许最大12MB请求，应用上传文件默认10MiB并有单据/门店配额。调大文件上限要同步反向代理、应用请求体限制和配额，并评估内存，不是仅改 `.env` 一个数字。

本地单进程可保留 `SCHEDULER_MODE=embedded`。独立运行时，Web和日报进程均设置 `SCHEDULER_MODE=worker`、`SCHEDULER_ENABLED=true`，另外启动 `python -m app.report_worker`；Web不再启动内嵌日报。`--once`只进行一次到期/漏跑检查。原数据库租约和按门店/日期唯一键保留。Linux服务示例为 `scripts/huakangos-report.service.example`，需按实际路径/账号配置后由管理员启用；本轮没有注册服务。不要把独立日报进程与外部自动部署混为一谈。

## PostgreSQL与异机迁移

`requirements-postgres.txt` 和 `scripts/migrate_database.py` 提供空目标全量迁移入口，包含新业务与文件/扫描模型，排除活跃登录会话、限流记录及任务租约。源端必须停写，目标必须空库，不能合并已有业务。脚本按数据库类型归一化逐表值并比较摘要，BLOB包括长度和SHA，不能仅靠记录数相同认为成功。本轮真实临时实例测试见《PostgreSQL验证》，正式迁移仍须用实际副本重新完成核对和恢复。

新正式库默认不迁移旧未结流程。使用“期初资料导入”预检公司清单、试导入回滚、核对汇总后确认。当前支持客户、账户主档、物资目录/期初库存，其他期初项目仍未开放；不能通过在备注填写余额冒充资金或应收账。


## 客户提醒独立进程

管理员确认规则和车辆日期/里程后，可独立运行 `python -m app.reminder_worker`，或 `--once` 只扫描一次；示例为 `scripts/huakangos-reminders.service.example`。该进程只按已批准规则生成内部待办，不发送客户消息、不自动办理业务。规则批准员工失效或失去岗位后停止该规则自动生成，须重新批准。重复扫描有指纹和唯一约束保护；生成事件明确为系统按规则执行，保留规则批准人。未自动安装或启动此服务。
