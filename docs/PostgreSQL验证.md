## 复现方法

先准备可信 PostgreSQL 二进制，以及当前项目的开发依赖和 `psycopg[binary]`。脚本接受二进制目录，不接受已有数据库地址、公司来源库或已存在的集群。

```powershell
.\.venv\Scripts\python.exe -m pip install "psycopg[binary]==3.3.6"
.\.venv\Scripts\python.exe tests/postgres_acceptance.py --pg-bin "C:\已核对的PostgreSQL目录\bin"
```

脚本在系统临时目录创建独立集群，绑定 `127.0.0.1` 随机端口，使用随机数据库账号与密码和 `scram-sha-256` 认证。密码仅存在于进程内存、子进程环境及初始化临时文件，不写入仓库、日志或终端；初始化后删除密码文件。不继承宿主 `PG*` 连接配置，防止客户端被现有服务配置改指其他地址。Windows 子进程使用隐藏模式，调用 `pg_ctl`，不安装服务。成功和失败路径都会尝试关闭本次临时实例；结果以退出码和临时 `result.json` 为准。

合成源使用 `tests/conftest.py` 强制创建的仓库外SQLite数据库和现有业务验收助手，实际调用期初、集团本金及权益、维修、客服授权、采购及两类调拨、精品销售退货、会员、库位作业、到店及返修、开票协同、月结和实际清算接口创建记录；合成客户、原始期初车辆和部分主数据由隔离测试资料初始化。历史月结定义1生产者的模拟在脚本中单独标注。该SQLite源通过当前测试模型建立，**PostgreSQL目标是通过实际Alembic迁移从空库建立**，两者区别保留在脚本中。使用的附件均为明确 `structure_only` 模式的合成凭据，不声称本次运行完成查毒。

脚本在恢复核对完成后，只在恢复出的临时库执行序列和竞争探测。竞争测试是两个真实数据库连接与重叠事务，验证数据库／ORM 的版本拒绝和行锁行为；它不等同于把整个浏览器业务验收套件切换到 PostgreSQL。
