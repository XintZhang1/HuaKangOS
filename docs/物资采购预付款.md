# 物资采购预付款与原款退款

适用 HK-045、HK-052、HK-069、HK-074。仅采购 v3 原单主动申请本功能，历史 v2 不推断预付款。第一次申请前不得已有实际付款，原采购合同和逐行金额保持不变。

|步骤|经办与入口|原事实、原子效果与接手人|退出与超时|
|---|---|---|---|
|申请预付款|财务/主管；采购已批准且尚未结束到货|明确金额、有效期、真实合同凭据，冻结本次申请；不记现金或库存；另一名本店主管复核|原申请人或主管可取消；过期后显式结束未付余量|
|独立批准/拒绝|本店独立主管；不能复核自己的申请，管理员无例外|重新检查采购剩余约定、其他申请占额及凭据可用；追加决定，财务接实际付款|拒绝保留原申请；已批准只能取消未付部分|
|实际付款|本店当前财务待办；批准未过期、原单及申请版本一致|明确实际付款确认、原账户、唯一流水号、收付款凭据；同事务创建唯一 CashEntry 与 PurchasePayment、申请关联及原验收抵用|批准不是银行支付；过期/余额不足/重复流水整笔拒绝|
|分批到货|原采购库管入口|原采购库存价值规则不变；可用原付款按先到期批次抵用并追加关联，抵用不再记现金|超原数量、他店行、过期版本整笔拒绝|
|终止未到余量|原采购主管入口|关闭未到货约定，并结束所有未付申请余量；实际已付款和到货保留；未用款转供应商应退|已到货须原批次实退，不可伪造取消|
|实际退货|原采购退货审批及实物发出|冲减原供应商信用；库存按现行 v3 均价与差额记账；释放对应原付款抵用，仍有到货未付时重新抵用；若退货令未付批准占额超过剩余约定，追加结束原未付余量决定，后续重新申请|实退不自动制造退款|
|原路退款|财务；存在终止余量/实退形成的应退|只可退该原付款未抵用且未退款额度，原账户、实际收款凭据及唯一流水；现金只登记一次|尚有有效采购约定的单纯资金调整不作为虚构应退，先明确终止余量或实退|

申请、独立决定、实际付款关联和抵用/冲回均保留不可变原来源。采购 Case 版本统一串行化付款、到货、退货、取消与退款；申请本身有版本，所有副作用和幂等回执一次提交。当前预付＝净已付−已验收净额−供应商应退；当前应付＝已验收净额−净已付，取正值。净现金＝到货抵用＋有效预付＋供应商应退。退款仅减少原款未抵用部分；申请占额不属于现金。

金额为整数分、数量为整数千分位。财务页面和CSV采用同一原单 totals；库存岗不见金额、账户、财务凭据。月结新增来源必须以新定义注册，不扩充旧封存。恢复器检查原申请/决定/实际款、原批次抵用/冲回、金额与现金/库存来源及同店归属。

## 当前口径与全局集成

采购付款仍只有原 `PurchasePayment→CashEntry` 现金一份。新增申请和独立决定不是现金；`PurchasePrepaymentDisbursement` 仅连接批准申请与实际原付款；`PurchasePaymentAllocation` 是原现金抵扣到货应付的非现金关联。正向关联和原退冲回分别留账，不作为新增采购或新增支出。

原现金剩余＝原付款金额−该原款累计退款−该原款抵用净额，不能选择已全额抵用的另一笔原款退款。到货应付按实际批次到期顺序抵用；原批退货先冲回原关联，再抵其他已到未付批次。批准申请额度按实际累计付款消耗，后来退款不恢复原批准付款额度。

供应商对账 API `/api/procurement/payables`、明细和 CSV 采用同一 `totals`：`prepaid_cents` 为当前有效约定预付；`prepayment_reserved_cents` 为待复核/已批准未付占额；`applied_cents` 为累计到货抵用净额。它们是查询时当前余额，不伪称期间末历史余额。库存与实际现金期间数沿原库存/现金来源，不加总申请或抵用。

新月结必须另开定义，原1–12不扩大。固定来源字段位于 `app/procurement_prepayment_sources.py::SOURCE_FIELDS`，只含5类原事实；请求的当前 `status/version/updated_at` 不是历史金额事实，若展示需显式标为当前状态。`app/procurement_prepayment_integrity.py::validate` 独立只读检查同店原单、独立批准、期限、实际现金、原账户退款、抵用与退货守恒，并与每次原动作的来源摘要双向核对；没有完整5表时拒绝，不用ORM当前状态猜测缺失来源。
