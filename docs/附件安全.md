# huakangos 附件隔离、扫描与凭据使用

本交付保留数据库 BLOB 附件路径，在不可变的 `FileAsset` 原始字节之外增加扫描状态和独立扫描审计。没有把文件写入公共静态目录，也没有启用外部 AI 读取文件。

## 配置与实际能力

| 配置 | 行为 | 可否用于正式环境 |
|---|---|---|
| `FILE_SCAN_MODE=quarantine`（默认） | 新上传、系统生成的文档保存后保持隔离，不能下载或作为业务凭据 | 不允许，正式启动配置检查拒绝 |
| `FILE_SCAN_MODE=structure_only` | 明确选择本地试用：检查允许的格式、文件头、图片、DOCX 包结构及受限内容；标注“仅结构校验通过（未查毒）” | 不允许，正式启动和运行时使用检查均拒绝 |
| `FILE_SCAN_MODE=clamav` | 先做同一结构检查，再将内存中的文件内容通过私有 ClamAV 服务扫描；仅有效完整的未发现威胁结果可使用 | 正式环境必需；仍须部署验证服务及病毒库维护 |

ClamAV 连接配置为 `CLAMAV_HOST`（默认 `127.0.0.1`）、`CLAMAV_PORT`（默认 `3310`）和 `CLAMAV_TIMEOUT_SECONDS`（默认 `5`，允许 `1–30` 秒）。配置、服务安装和病毒库更新由部署人员管理，本次实现没有安装外部服务或连接公司扫描器。

适配器使用 ClamAV 官方的 `VERSION` 与 `INSTREAM` 协议，先确认扫描器版本，再以 64 KiB 分块传递文件，记录扫描器返回的版本／病毒库标识。两次连接共享超时预算，收发每一步检查剩余时间；超时、拒绝连接、断流、超长／不完整／无法识别的结果均保持隔离。协议依据：[ClamAV 官方协议文档](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)。

`clamd` TCP 协议本身不提供本应用的用户鉴权或传输加密。仅配置受控的本机或私有网络扫描服务，不把端口直接暴露到公网；建议使用固定私有 IP，避免系统 DNS 解析延迟。服务器须维护病毒库，并配置合理的 `StreamMaxLength`、扫描大小／递归限制，以及对超限、加密文档的风险报告，不能让服务器静默跳过部分内容后当作完整扫描。部署侧配置指导：[ClamAV 官方配置样例](https://github.com/Cisco-Talos/clamav/blob/main/etc/clamd.conf.sample)。

本地演示和合成测试必须显式选择 `structure_only`；程序不会因为 `APP_ENV=local/test` 自动放行历史或未扫描附件。正式环境要求 `clamav` 只是系统配置关口，尚不能替代真实 ClamAV 服务、病毒库、访问控制和容量的部署验收。

## 状态、权限与办理关口

| 对外中文状态 | 是否可下载／办理 | 下一步 |
|---|---|---|
| 历史文件未扫描，已隔离 | 否 | 有权限的员工发起重扫 |
| 已隔离，等待扫描 | 否 | 配置可用扫描策略后重扫 |
| 扫描未发现已知威胁 | 是，仍须满足原门店与岗位权限 | 正常办理；不代表电子签名真实或绝对安全 |
| 仅结构校验通过（未查毒） | 仅明确启用该模式的本地试用可用 | 切换严格策略后须重新查毒 |
| 扫描发现风险／扫描失败／结构校验未通过 | 否 | 保留隔离记录，重扫或上传其他凭据；不提供人工强制放行按钮 |

曾被 ClamAV 发现风险的同一文件，不能通过改成本地结构校验模式解除隔离；必须有后续 ClamAV 未发现威胁的记录。重新上传完全相同的文件沿用原附件和原扫描状态，也不能绕过隔离。

上传者只确认自己提供的资料，扫描结果由扫描服务记录。下载、流程中的文件引用、集团会员资金凭据、文件下拉选择、合同／交付签回源文件都检查扫描状态；前端隐藏按钮不构成权限边界。签回件自身和它关联的生成文档都须可使用，且继续检查原模板批准状态、快照与当前业务指纹。后续重扫发现生成源文件有风险时，旧签回件不能继续确认该来源。

门店、业务阅读和文件类别权限沿用现有规则；审计人员只能查看扫描记录。重扫还要求原上传岗位的权限：财务类附件由财务／主管／管理员办理，合同签回由销售／主管／管理员办理，普通业务凭据由能够访问本单和该类文件的非审计员工办理。跨店 ID、身份缓存或集团只读汇总不能用来重扫其他门店文件。

## 事务、历史与接口

- 上传或生成附件时，文件、初始隔离状态、扫描结果和业务事件在同一事务中提交。扫描失败返回已保存且隔离的文件状态，不会先公开文件下载地址再异步补判断。格式在入口即不合法的文件直接拒绝，不创建业务附件。
- `file_security` 保存版本化当前状态；`file_scan_events` 追加扫描人、时间、文件摘要、大小、扫描引擎及版本、结果代码。重扫不修改文件字节，不覆盖旧扫描事件。扫描响应不向员工暴露服务地址或原始扫描器错误文本。
- `g107_file_security` 是 `f006_group_refunds` 之后的追加迁移，使用冻结字段定义。它不改写 `flow_files`，不把历史文件自动标记为安全。没有扫描状态行的旧文件显示为历史未扫描，初始扫描版本为 `0`。
- 文件信息增加 `security`，包含中文 `label`、`state`、`version`、`can_use`、`antivirus_scanned`、结果代码及时间。下载和办理仍在后端重新判断当前策略，不能依赖客户端保存的旧 `can_use`。
- `GET /api/flow/files/{file_id}/security` 返回当前状态及最近 100 条扫描历史；原始历史完整保留。`POST /api/flow/files/{file_id}/scan` 接收 `{version, request_id}`。请求编号需 16–80 位；重复相同请求不重复扫描或追加审计，过期版本拒绝，状态冲突后刷新核对并保留原请求编号确认结果。
- 源文件先前通过的扫描结果在一次新的重扫事务完成前仍是已提交事实；新上传尚无扫描结果的文件从未获得可下载的中间状态。重扫完成发现风险或服务失败后，当前状态立即阻断后续使用。

## 验证记录与后续工作

`tests/test_file_security.py` 使用合成附件验证隔离后的下载、下拉选择和收款拒绝；本地结构模式清晰标注未查毒；扫描异常与发现风险的审计；重复和竞争重扫；版本冲突；门店／岗位／身份缓存范围；历史未扫描文件；签回和生成源文件联动；扫描审计不可覆盖；文件摘要损坏；生产配置拒绝弱化扫描。

协议测试启动临时的回环 TCP 测试端点，实际检查 `VERSION`、`INSTREAM` 分块与原始字节，覆盖未发现威胁、风险提示、服务超限、未知结果、截断、超时及不可用连接。这个端点只验证协议实现，**不是实际的杀毒软件运行结果**。正式环境仍需使用已部署且病毒库有效的 ClamAV 服务执行部署验收，并验证备份恢复后的附件摘要、扫描审计和使用门槛。

合成数据库备份测试保留不同状态的附件及多次扫描历史，逐项核对原始字节、摘要和状态关联，并证明把当前状态改指旧扫描或其他附件的扫描会被恢复校验拒绝。`validate_file_security_sqlite(connection)` 是离线备份上的只读检查，核对扫描与原文件的门店、摘要、大小及最新状态指针；旧文件缺少状态仍可保留，但恢复后继续隔离。该检查不主动连接扫描服务，也不把备份一致性当作查毒结果。

当前仍采用有限容量的数据库 BLOB 试用方案。私有对象存储、对象清单、对象／数据库两阶段写入、独立扫描队列、对象隔离库、定期重扫、完整分页审计导出与跨介质联合恢复仍是后续建设内容；不能把本次交付表述为已经实现对象存储或完成全部生产附件治理。
