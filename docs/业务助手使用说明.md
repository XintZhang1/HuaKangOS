# 业务助手使用说明

更新：2026-09-24。入口在左侧“业务助手”，与“我的工作”“数据可视化”同级。按用户最新选择，当前试用模型为 DeepSeek Flash；MiMo 试验已停止。本轮实测结果见《业务助手模拟问题清单》和《验收与限制》。

## 开始办理

1. 登录，选择当前门店，打开“业务助手”。
2. 直接说要办的事，例如：“帮我登记一次售前接待”。
3. 按它的问题补充资料；没有电话就说“暂时没有电话”，不用先去补齐整套客户档案。
4. 出现“待确认”卡片后，核对客户、门店、金额、数量和办理内容，再点“确认办理”。聊天里回复“确认”不会直接提交。
5. 看到“已完成”后，可点“查看单据”或“打开原页面”检查。下一步继续在同一对话里说即可。

建立接待时不强制填写电话。安排回访时需要电话、回访日期和沟通结果；未分派的接待还需要先由相应岗位分派。助手会读取当前单据告诉你下一步。

## 可以直接这样说

| 要办的事 | 示例 |
|---|---|
| 建车型目录 | 帮我建立本店的品牌、车系和车型，缺什么逐项问我。 |
| 接待客户 | 登记一次接待，客户叫试用张先生，展厅到店，暂时没留电话。 |
| 安排回访 | 给刚才的客户安排明天回访。缺电话、时间或沟通结果请问我。 |
| 查客户 | 找一下我负责的试用张先生。 |
| 查任务 | 我今天有哪些待办？ |
| 办理业务 | 帮我开一张维修工单／物资采购单／车辆报价单。 |
| 记录问题 | 刚才这一步做不下去，帮我记录问题。 |

这些是入口示例。不同业务需要的资料、岗位及前一步不同；有入口不代表所有分支都已经由模型实测通过。试用请用虚构姓名、电话和材料。

## 从文件填写

打开“资料整理”或对话框旁“从文件填表”，选择本地文件或文件夹。先查看解析结果，勾选要用的行或文字，填写目标，核对发送内容后点“发送资料并填表”。缺少信息继续回答，出现卡片后逐项核对再确认。完整步骤和限制见[文件试用手册](本地资料与业务助手试用_20260924.md)。

上传只在当前huakangos服务内解析，不调用模型、不保存原件。你明确发送后，所选资料作为对话交给DeepSeek；未选行不发送。文件夹只是本次选择的文件集合，不授予模型扫描磁盘或修改文件的能力。当前支持CSV、TSV、XLSX、DOCX、TXT；PDF/OCR、宏和公式运算尚不支持。支持导出预览表和卡片填写内容，原文件不会被覆盖。

## 卡住时怎么办

- **缺资料**：直接补充；不知道的说“不知道”，不要猜金额、账户或凭据。
- **需要其他岗位办理**：让相应同事登录自己的账号继续。管理员账号能看到较多内容，不能用它替代每个岗位的试用。
- **待核对结果**：先打开原单查有没有保存。不要让助手再建一份；系统会阻止同一对话里重复提交同一项不确定的操作。
- **等待过久**：“停止等待”只停止页面等候。之后点“刷新对话”看结果；它不会撤回已经确认的业务。
- **发现不合理要求或报错**：打开“问题清单”，填写“想办什么、卡在哪一步、看到什么提示”。也可以让助手记录，再点“导出问题”，把文件交给维护人员。

问题清单区分资料不足、业务规则、模型填错、服务错误和未支持事项。模型的判断只是排查线索，需要对照真实请求和原单；不能因为模型说做不了就认定前端有故障。

## 本轮保留的操作方式

原有表单和业务页面继续可用。上传凭据、下载文件、维护账号密码、正式合同模板、正式期初导入、部署及外部连接配置仍从原入口办理。助手不执行代码，不直接改数据库，不代替实际收款、收货或审批。

需要实际业务写入的操作均有确认卡。业务完成依据是原接口返回和原单记录；对话里说“准备好了”还不等于办完。已完成单据的撤销、退款或冲正仍走原业务流程，取消确认卡只取消尚未提交的那一步。

## 管理员更换模型或密钥

配置文件在运行系统的 Windows 账号下：`%LOCALAPPDATA%\huakangos\business-assistant.json`，不在源码中；也可通过环境变量 `BUSINESS_ASSISTANT_CONFIG` 指定另一个源码外的绝对路径。配置按请求读取，更换密钥后刷新助手即可，不需要重装页面。

当前 DeepSeek 配置结构如下；示例中的占位文字必须替换成管理员持有的密钥，不要把密钥粘贴到员工对话中：

```json
{
  "enabled": true,
  "provider": "deepseek",
  "api_kind": "pay_as_you_go",
  "model": "deepseek-flash",
  "api_key": "在本机私有配置填写",
  "timeout_seconds": 75,
  "synthetic": true
}
```

`synthetic: true` 标记当前模拟试用产生的问题记录，不会自动创建或清理数据。正式启用前需完成实际业务和部署验收，重新配置正式环境。关闭助手把 `enabled` 改为 `false`；日常 AI 摘要的开关与此独立，仍默认关闭。

更换同一供应商密钥，只修改 `api_key`。如以后明确切换 MiMo，可配置 `provider: "mimo"`、`model: "mimo-v2.6-flash"` 及对应密钥；Token Plan 使用 `token_plan`，按量付费使用 `pay_as_you_go`。接口由程序按官方地址选择，不能在对话里更改。连接失败时系统不会自行切到另一供应商。参考 [DeepSeek 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)和 [MiMo 官方接入文档](https://mimo.mi.com/docs/zh-CN/quick-start/summary/first-api-call)。保留连接适配不代表 MiMo 的复杂业务试验通过。

助手会把对话和当前员工有权读取、为办理所需的业务资料发送给所选模型供应商。系统查询工具不会发送密码、密钥、登录凭据或原附件内容；员工明确选中并发送的文件文字/表格作为本次对话资料传给模型，发送前需核对预览。密钥列和常见凭据会隐藏，不应主动导入或发送登录资料。试用配置只放在本机私有目录，不随交付打包；完整数据库备份包含对话和问题记录，按业务备份保护。

每段对话按本人、门店、岗位和账号权限版本隔离。岗位或账号权限改变后，旧权限会话隐藏，保留审计记录。客户重新分派、单独撤销跨店档案授权不会自动抹去此前合法读取并写入个人对话的内容；后续查询仍受原接口当前权限控制。这项历史副本保留限制需要在正式使用前确认。

## 维护人员排查顺序

先看问题清单和原单，再复现表单。必要时运行仓库中的独立模拟脚本，使用新临时库、新账号、独立端口，绝不把试验指向正在试用的门店库。测试脚本设置模型调用上限并核对实际保存结果；达到测试上限不是供应商故障。

合成浏览器试验、模拟模型的界面测试、真实模型接口试验和公司验收分开记录。当前全量统计、迁移、恢复及未完成项以《验收与限制》为准。
