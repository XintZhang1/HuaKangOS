# huakangos · 仓储作业与真实库位

本批把物资的实际位置纳入库存事实，覆盖其他入退库、耗材领退、礼品领退、其他处置、店内移库和库位盘点。门店 `Item` 继续提供总数量和总价值；库位及店内在途分桶必须与它一致。物资档案中的默认库位只用于主数据配置，不代表历史库存已在那里。

本文件中的门店、人物和凭据测试数据均为虚构。自动测试通过不代替公司业务验收、正式启用或真实部署验证。

## 员工入口与岗位

从“库位与仓储作业”进入。库管提出作业、选择物资和实际位置；主管批准后，库管根据实际交接凭据办理。主管可明确交接待办和期限，原员工失去该任务的办理资格。超期继续显示在任务列表；系统不自动确认实物、不自动处理差异、不发外部消息。

| 岗位 | 能力 |
|---|---|
| 库管 inventory | 本店库位数量、作业、原始数量流水；提出申请、实际收发、现场实盘、准备原业务库位。金额和财务凭据在 API 层隐藏。 |
| 主管 manager | 审批、拒绝、取消未执行作业、核对差异、有据作废错误观察和交接待办；读取成本。实际收发仍交给库管。 |
| 财务 finance / 审计 auditor | 本店数量、价值和原单只读；不能实际仓储过账。 |
| 管理员 admin | 配置与试验时可办理全部职责。正式员工演练使用实际岗位账号。 |

上述权限始终取当前门店的有效岗位。集团汇总不能读取专用仓储明细或写入；跨店 ID 被拒绝。销售、客服等岗位不通过新 API 读取仓储成本或领取人信息。

## 首次启用真实库位

1. 先配置有效的物资仓／混合仓及库位，建立物资目录。零库存也须由员工明确至少一个接收库位。
2. 对单个物资申请“真实库位启用”，按现场实物填写各库位数量。系统核对 `OpeningStockEntry + StockMove = Item` 的数量与价值；缺历史来源或不一致时拒绝，不自动猜测。
3. 主管查看实际定位凭据并批准。申请后库存变过，旧申请必须撤销并重新核对。
4. 系统保存启用的库存数量、价值和历史流水截止号，并追加初始库位分配事实。这不是新的采购入库，不重复增加 `StockMove`、现金或门店库存。

逐项启用允许现有未定位物资继续按原门店总账运行；只有完成启用的物资要求每次真实库位分配。历史记录保持门店级来源，不回填猜测的位置。已启用位置的变化必须办理移库，不能编辑物资档案替代。

有真实库存或未完成仓储作业的库位不能停用、改父仓；所属物资仓不能改成整车仓。

## 作业闭环

每单办理一种物资。数量允许三位小数，后端存整数千分位；金额存整数分。每个命令包括版本及幂等请求编号，单据、任务、库存、库位、预占、事件与请求回执一次事务提交。冲突时刷新核对，不以新编号盲目重复提交。

| 作业 | 必要事实和入口 | 审批、实际动作和异常出口 |
|---|---|---|
| 其他物资入库 | 本店有效物资、接收库位、数量、来源说明；主管以受限来源凭据明确总价值，可为有据零价 | 库管申请 → 主管核价批准 → 库管上传实际收货凭据并入库。批准不增加库存。未实收可取消。 |
| 原其他入库退回 | 精确关联 `wh_other_in` 原始流水和本次退回数量、发出位置 | 主管批准形成实物预占 → 库管实际发出，追加负数量和原成本冲回。可分次退，最后一次冲回全部剩余分值；不允许超退。 |
| 耗材领用／礼品发出 | 发出库位、数量、领取人或班组、作业用途 | 主管批准预占 → 库管实际发出。只是分派或批准不代表已领取。未发出可取消并释放预占。 |
| 原耗材／原礼品退回 | 对应原始发出流水、接收位置、实际退回数量 | 主管批准 → 库管实际接回，按原发出剩余数量和价值恢复。可分次退，不使用当前价格改写原成本。 |
| 其他处置出库 | 发出位置、数量、具体处置依据 | 主管批准预占 → 库管根据实物处置凭据发出。误登记需新建有来源的纠正入库并说明原单，不能删除原出库。 |
| 店内移库 | 同店不同实际出发和接收位置、数量和原因 | 主管批准预占 → 库管实际移出 → 店内在途 → 逐次实际接收；可部分接收后拒收余量，再分次实际返回原位。发出后不能直接取消。 |
| 库位盘点 | 同店单物资、单实际库位；申请数量为零，现场结果稍后填写 | 主管批准建立短围栏 → 库管现场清点并提交观察 → 释放围栏、允许正常期间收发 → 主管核对观察及衔接流水，只追加原观察差额。 |

审批产生的出库预占与精品销售预占一起参与可用量校验；移库在途也不作为可用量。重复批准、超量接收、过期版本、串店库位、原单超退均拒绝。原始预占和释放各追加一条记录。

移库始终在同一门店内，不改业务行的 `store_id`，也不制造门店级入出库流水。跨店业务继续使用已存在的调拨流程及双方 `StockMove`。

## 盘点期间变动及错误观察

实盘围栏只覆盖选定的物资和库位，不锁整店。该位置存在已批准的仓储出库／移库时，先办理或取消。现场实盘期间禁止该位置收发；提交观察后解除围栏，保留开始账面数量、实际数量、凭据和库位流水截止号。

例如开始账面 8 件，实盘 7 件；待主管复核时另有 2 件实际入库。差额仍为 -1 件，审批后是 9 件，不覆盖为旧的 7 件。页面显示开始账面、实盘、差额、期间净收发、当前账面和处理后应有量，并可下钻期间原单。

已观察的未处理盘亏会保留相应数量，防止在差异处理前继续发出短缺库存。若处理差异会占用精品销售或其他已批准业务的预占，系统拒绝差异过账并保留观察；须在原业务中有据取消、调整或核对。系统不会自行解除客户预占。

现场录错的观察不能直接改数字或普通取消。主管通过“按凭据作废错误实盘观察”填写原因并关联实际复核凭据；原观察、审批和事件保留，库存不变。需要再次实盘时另建新作业。零库存盘盈没有可靠成本时拒绝猜价，保留观察供有来源的处理。

## 与既有采购、维修、精品和跨店调拨联动

未定位物资保留原业务语义。完成库位启用后，原单详情提供“准备物资库位”：

1. 选择该原单相关物资、实际收发动作、本次精确数量和一至多个实际位置。
2. 保存仅表示已准备位置，不增加或减少库存，不取得原业务办理权限，也不占用数量。
3. 回原采购、维修、精品或调拨页面，按原业务批准、凭据、岗位与任务要求确认实际收发。
4. 原 `StockMove` 生成时，在同一事务消费匹配原单、物资、动作、方向和精确数量的一份库位准备，并再次校验当前位置及预占。缺准备、位置失效或数量变化时整笔拒绝，不部分过账。

覆盖公共入口：`flow_engine.stock_move`、`procurement_service._stock`、`transfer_service.posting`、`repair_service._post_stock`、`retail_service._stock`。旧领料／退料、采购收退、跨店发收退、维修领退及精品售退均通过共同适配器。

多次收发的本次准备可重新提交；尚未消费的同动作旧准备显式作废。已经消费的准备和其原始库位明细不覆盖。

## 价值和统计口径

- 门店的移动加权成本及原单退回成本由既有 `Item`／`StockMove` 事实决定；新库位账不改为批次先进先出，也不引入独立库位均价采购成本。
- 外部实际入出库后，以门店当前总价值按各库位及店内在途数量分配；最大余数法稳定分配最后几分钱。数量为零的分桶不保留价值。
- 价值变化也追加不可变库位流水。没有数量变化而发生的价值重新分配标为“门店均价价值分配”，不伪装实物收发。
- `sum(库位 + 店内在途数量／价值) = Item数量／价值`；各桶原始流水和等于当前余额。启用以后每个原始 `StockMove` 的数量与价值都与对应库位流水之和一致。
- 门店入出存继续取 `OpeningStockEntry + StockMove`。初始定位、店内移库和库位价值分配不能再加到门店收发合计，不能重复计经营收入。
- 列表分页；单项明细上限五万条，超限明确拒绝而不返回截断合计。手机表格支持横向滚动，关键盘点数值直接纵向显示。

## 模型、接口与恢复

冻结迁移 `r218_warehouse` 依赖 `q117_reconciliation`。新增 `warehouse_documents/approvals/enrollments/balances/entries/holds/allocations/allocation_lines/count_observations`。原单、批准、启用、观察、库位流水、预占及分配明细不允许覆盖或删除。

主要接口：

| 接口 | 用途 |
|---|---|
| `GET /api/warehouse/catalog` | 当前门店岗位能力和可用作业类型 |
| `GET /api/warehouse/items`、`/items/{id}/stock` | 分页库存及原始库位数量／获权价值明细 |
| `GET/POST /api/warehouse/cases` | 原始作业列表、按固定类型提出申请 |
| `GET /api/warehouse/cases/{id}` | 明确状态、可办动作、原流水及盘点期间衔接 |
| `POST /api/warehouse/cases/{id}/commands/{action}` | 明确审批、实际确认、拒绝、取消或有据错误处理 |
| `GET/POST /api/warehouse/allocations/{原case_id}` | 原业务相关物资与允许动作；保存一次准确库位准备 |

`warehouse_backup_integrity.validate_warehouse_integrity(connection)` 接受离线 SQLite 来源连接，验证启用来源、门店范围、每桶流水与余额、启用后的原始收发和分配、审批凭据、移库在途、预占进度与盘点观察差额。总恢复校验已注册此函数。校验无法抵御有权限的数据库管理员同步篡改全部相关原始事实，不声称密码学防篡改。
