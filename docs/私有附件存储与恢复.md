# 可选私有本地附件存储

本模块提供同一服务器上的私有目录存储。它复用现有附件、岗位权限、隔离扫描、模板版本及签回关联；不提供公开静态目录、匿名下载或对象路径链接。历史数据库 BLOB 保留原样，新附件可显式选用私有目录。实现不包含 S3、对象云服务、自动删除或既有附件的无损迁移工具。

## 配置与职责

`FILE_STORAGE_MODE=blob` 保留原默认行为；`private_local` 只影响之后新增附件。`PRIVATE_FILE_ROOT` 必须是本机绝对路径、位于代码和公开静态目录之外，也不能是代码目录的父目录。Windows 符号链接、junction 和其他重解析点会被拒绝。更换存储模式不会修改已保存记录；只要数据库还有私有对象引用，旧对象根就必须继续可读。

例如可以为独立试用实例设置 `PRIVATE_FILE_ROOT=E:\huakangos-private\trial-files`。运维人员必须在部署机器上配置目录 ACL，限制为应用与备份账号可读写；禁止把该路径作为 Web 服务器静态目录共享。Python 的权限位不能代替 Windows ACL 验收。本地测试使用临时目录、合成文件和显式结构校验策略；正式环境仍要求现有 ClamAV 策略。

单文件 10 MiB、单业务 100 个附件以及门店容量限制继续由原附件入口校验。目录存储不会自动放宽上传大小，也不会使扫描通过变成真实性、电子签名或绝对安全的证明。

## 保存、隔离和读取

| 环节 | 责任与入口 | 必要事实及原子结果 | 异常出口 |
|---|---|---|---|
| 上传或生成 | 原有获权岗位，在本店可读业务内提交 | 先校验原文件格式和业务用途；私有 staging 完整写入、刷新文件、以随机键原子且不可覆盖地发布，重新核对字节后再建立数据库引用 | 发布或验证失败不提交附件和业务；原文件不会被覆盖 |
| 建立引用 | 后端，同一数据库事务 | 新 `FileAsset` 保存空 BLOB，唯一 `PrivateFileObject` 保存同店文件 ID、大小、摘要和随机对象键；扫描记录、事件随原事务提交 | 事务回滚可能留下未引用对象，不能出现提交成功后再异步上传的窗口 |
| 扫描和业务使用 | 原扫描服务及实际经办岗位 | 扫描读取同一原字节；业务使用同时验证原权限、当前扫描策略和原对象字节 | 未扫描、风险、超时、对象丢失或摘要不符均阻断业务使用；通过明确重扫追加扫描记录 |
| 下载 | 原文件下载 API | 查询限定门店，检查原业务与文件类别权限，检查扫描及原字节，再返回现有安全响应头 | 没有可猜测的公开文件地址；跨店、无权或受损对象不能下载 |
| 签回 | 原销售/主管入口 | 签回仍关联生成文档 ID、模板版本、生成时快照和摘要；生成源自身也必须扫描可用且原字节完整 | 当前快照变化、源对象缺失或受损均拒绝，不能以一张新照片替代原生成版本 |

对象路径不使用员工上传文件名，随机键按门店分目录。不同附件不做物理去重；原入口相同内容、用途、来源的重复上传仍复用原附件记录。附加对象映射为不可变历史，不能借修改映射替换原文件。

发布使用同一文件系统的临时文件与原子硬链接；不支持该能力的文件系统直接拒绝保存。进程在数据库提交前崩溃可能留有孤儿文件；它不影响已提交业务的一致性。文件同步与目录同步遵循操作系统能力，Windows 不等同于已完成断电和存储硬件持久性验证。

## 成套备份与恢复

单独复制数据库只能备份 BLOB。只要数据库中有私有对象引用，不提供对应对象根的离线验证必须失败，不允许把空 BLOB 当成已备份原件。

`app.private_file_backup.create_bundle(database_path, object_root, output)` 提供 SQLite 在线一致快照。它在目标的同级临时目录建立下列内容，然后才发布新备份目录：

- `database.sqlite`：同一时点的数据库快照。
- `object_store/objects/store-…/…blob`：仅该快照实际引用的对象。
- `manifest.json`：版本化文件 ID、门店、原大小、原摘要、存储模式和签回源 ID，另含数据库文件摘要。
- `COMPLETE`：所有对象与完整业务恢复校验通过后才写入的清单摘要。

先核对快照引用与源对象，再复制每个对象，最后使用备份目录重新执行完整数据库、账本、扫描关联及原附件校验。失败保留 `.incomplete-…` 目录供人工核对，不能报告为已验证备份。清单和摘要用于发现缺失与损坏，不是对数据库管理员或能重写整套备份人员的防篡改签名。

`validate_bundle(bundle)` 从成套备份本身验证，不依赖仍在线的原对象根。`restore_bundle(bundle, output)` 在全新目标目录恢复数据库和对象，重复验证后发布；已有目标一律拒绝覆盖，程序不修改线上连接配置。实际切换时先停止原实例，再指向返回的新数据库与对象根；登录原测试岗位，核对原业务、下载附件、签回来源及账本。不能只以“能登录”判定恢复完成。

在已配置本实例数据库和对象根的终端，管理 CLI 可执行下列步骤。示例目录须预先建立其父目录，备份与恢复目标本身必须尚不存在：

```powershell
python -m app.cli backup --output E:\huakangos-backups\trial-20260921
python -m app.cli verify-backup E:\huakangos-backups\trial-20260921
python -m app.cli restore-backup E:\huakangos-backups\trial-20260921 --output E:\huakangos-restores\trial-20260921
python -m app.cli files-audit
```

`backup` 检测到任何私有引用或私有存储配置时自动要求成套目录，不会默默输出一个缺附件的 `.sqlite`。只有 BLOB 的既有数据库仍使用原单文件备份路径。`files-audit` 只是当前 SQLite 数据库对应目录的只读清单。

备份源可以继续新增业务，因为快照只引用已发布不可变对象；备份时不能让外部程序删除或覆盖对象。运维保留期、加密、异地副本以及恢复演练属于同一备份制度，不能只保留数据库或只保留目录。

## 孤儿对象与数据库转移

`app.private_files.audit_orphans(sqlite_connection, root)` 只列出数据库未引用的对象及 staging 文件。未引用可能表示失败事务，也可能表示正在提交的上传；因此没有在线自动清理、递归删除或按年龄删除功能。必须停写、保留可靠备份并由运维独立核对后才能另行清理。恢复只搬运快照的真实引用，孤儿不会混入恢复后的业务。

`validate_connection_files(connection, object_root)` 接受 SQLite DBAPI 或 SQLAlchemy 数据库连接，可供 PostgreSQL 转库前后核对同一对象清单。转库的表指纹只证明数据库映射和 BLOB 一致，不能证明外部对象已到目的地。必须显式复制私有对象到目的地并以目的地根校验；缺根或缺对象时拒绝宣称转移完成。`pg_dump` 仍需数据库自身恢复校验；本模块不是 PostgreSQL、网络对象存储或多机文件系统的完整备份方案。
