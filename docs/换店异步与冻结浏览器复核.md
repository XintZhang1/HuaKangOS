# 换店异步与冻结浏览器复核（2026-09-23）

本记录只证明本轮换店页面修复与相关合成浏览器场景。不是原193项全部完成、公司业务验收或正式部署验收；全树 pytest 结果另以最终冻结记录为准。公司及生产状态仍待验收。

## 问题与修复范围

首次冻结复跑 `tests/browser_master_completion.py` 时，管理员创建第二门店、切换门店后立即打开维修字典，5秒内页面最终变为“我的工作”。原 `#store.onchange` 在异步身份和目录请求完成后无条件覆盖 hash；外部诊断也记录了暂时显示字典后又回工作页。诊断请求成功且无 JavaScript 错误，不是门店权限拒绝。

仅修改 `web/app.js`，增加 `tests/js/store_switch.test.cjs`、`tests/browser_store_switch.py`。原 `browser_master_completion.py` 保留换店后立即导航的原路径，没有加等待来掩盖故障。未改后端权限、账本或数据库结构。

- 换店立即撤下旧业务页面、关闭弹窗、清理缓存并使旧渲染失效；待切换门店单独显示，已确认的门店、岗位和目录保持成组一致。
- 以指定门店请求新身份和五类目录，全部成功后一次切换；期间只保存最新页面意图，不按旧身份渲染目标业务。
- 连续换店仅最后一次可提交。旧读取、旧 JSON 解析结果和旧附件内容迟到时均不回填、不开始下载。
- 原门店已发出的办理请求不会自动重发；迟到的提交响应提示回原门店核对原办理结果，勿重复提交。
- 目标失败时重新读取原门店身份和完整目录，返回原店工作页；恢复也失败时保持阻断页面，提供重试原门店和退出，不显示残留业务。
- 多店汇总中的“切换到此门店办理”也使用同一入口；实际授权仍由 API 复核。
