# huakangos · 库位期间入出存（HK-152）

本版将“库位期间入出存”建立在已经实际启用的库位原始账上。它与门店入出存、当前库存、店内移库作业分别使用明确口径；不是把当前 `Item` 数量按默认库位回填到过去。测试资料全部虚构，自动验证通过不等于公司业务验收或正式启用。

## 员工查询

进入“库位期间入出存”，选择开始及结束日期，可按物资名称／编码查找、选择物资和仓库。页面沿用当前报表期间；接口未指定期间时查询本月。最长跨度一年，结束日期不能晚于今天。日期填反时保留原条件，显示中文说明供原页改正。

库管可查看本店数量和获权原业务，API、图表及 CSV 均不返回成本。主管、财务、审计可查看账面价值；其他岗位无该报表读取权限。集团视图仅使用已经授权的门店集合，不显示门店原单跳转，不由共享身份开放业务或附件。报表不改变库存、不代替仓库审批或现场确认。

物资／仓库选项包括停用历史资料，搜索最多返回 100 条并提示细化关键词；单类原始来源上限 25,000 条，超限明确拒绝，不输出截断合计。物资和仓库筛选会缩小相关账本范围。查看没有位置的历史物资须使用全店视图，不能根据默认库位或名称猜测仓库归属。

## 两种完整性

页面分别显示“全期间来源”和“期末来源”。例如某物资 9 月 21 日经主管实际核验完成库位启用，9 月 21 日午夜之前的库位分布并不知道。查询 9 月 21 日或更早开始的期间时：

- 期初数量／价值和完整期间入出库显示“—”，不填零。
- “真实启用桥接基准”列明实际批准时刻及分配数量／价值；这不是新采购或当期进货。
- “所选期间已记录库位流水”仍显示真实存在的逐行事实，不能把这部分记录称为完整期间收发。
- 若结束日已覆盖启用日，且基准、全部后续收发、库位账及门店账能对平，可以单独显示有据期末和期末图。图标题及页面明确这不表示全期间完整。

开始日在真实启用日之后，且全部来源一致时，才有完整的午夜期初与期间收发。结束日在启用日之前时，期末也未知，不画完整期末图。即使未启用物资当前数量为零，也不会凭此推断过去每个库位均为零。

实际批准时间采用保存的 UTC 事件并转系统配置时区取日期；CSV 的基准时刻明确标注 UTC。库存业务日期取原不可变流水，不取当前单据状态或报表打开时间。

## 逐笔来源和守恒

启用基准来自 `WarehouseEnrollment`、唯一实际批准 `FlowEvent`、已经消费的初始库位分配，以及 `WarehouseEntry` 的启用记录。系统核对启用截止号前的 `OpeningStockEntry + StockMove` 与基准数量／价值一致。

启用后的每笔 `StockMove` 须与对应全部库位流水数量、价值、原业务、门店和业务日期一致。每个库位及店内在途按原日期和记录顺序重建，其原始流水合计须等于当前 `WarehouseBalance`；全部库位及店内在途合计须等于 `Item`。来源缺失、次序无法重建、关联错误或差额时明确列出原因，保留真实记录供核对，不生成完整合计。

店内移库的实际发出、部分接收及拒收原退均按 `WarehouseEntry` 列出。店内在途归发出仓并独立列行；即使目的库位属于另一仓，也不会同时算进目的仓。店内全部位置合并时移库数量／价值净变化为零；它不是第二笔门店采购或销售。

退料仍遵守原单成本与门店移动平均分配：某库位发生负数量时，其账面价值可能因为分配变化而增加。本报表保留原有符号，不把负数量行的价值一律取负或绝对值。完整期间的核对公式为：

```text
期末数量 = 期初数量 + 入库数量 - 出库数量
期末价值 = 期初价值 + 入库有符号价值变动
         + 出库有符号价值变动 + 零数量均价分摊调整
```

零数量价值调整独立列示，不能当成实物进货、领用数量或维修实际成本。期末图的每个仓库柱值严格来自“库位期间入出存及覆盖范围”相同记录，包含该仓的店内在途一次。CSV 使用同一构建器和筛选，不另跑一套公式。

## 历史库位归属

库位一旦形成启用／收发历史，即使已经清空，也不能改所属仓库；相应仓库不能改类型。未有物资历史的新仓库、新库位仍可按主数据规则调整。

旧版本若曾允许清空后换仓，系统通过保留的主数据审计记录识别启用之后的变更，显示历史归属待核对。查询旧仓或新仓时明确拒绝含糊筛选，不让原流水从旧仓结果中悄然消失。报表不修改历史、不自动推断当年的仓库关系；无审计事实的数据库人工篡改仍需运维完整性核验。

## 接口和实现

| 位置 | 职责 |
|---|---|
| `app/warehouse_period_analytics.py` | 真实桥接、逐库位期间重建、来源差异、图表与表格同源集合 |
| `app/inventory_reports_api.py` | `GET /api/inventory-reports/warehouses`、`/warehouses/export/{table_key}`；参数 `date_from`、`date_to`、`item_id`、`warehouse_id`；只读筛选项 `/warehouses/options/items`、`/warehouses/options/warehouses` |
| `app/warehouse_stock.py:has_location_history` | 清空后仍保护曾承载物资历史的库位身份 |
| `web/inventoryreports.js:warehousePeriodPage` | 期间／期末分别提示、中文筛选、手机卡片、相同筛选导出 |
| `app/flow_analytics.py` | 经营汇总组合复用相同表格、图表与定义 |

本版没有新迁移，也没有改写原库存事实。查询在同一数据库快照内读取；并发实物过账不会把过账前的余额与过账后的流水混合统计。历史报告反映查询时可见的原始事实和覆盖情况，并不是不可变会计关账快照。

## 验证

专项 `tests/test_warehouse_period_analytics.py` 覆盖零／非零启用、启用前历史未知、次日期初、实际部分移库、跨仓在途归属、原单退回有符号价值、零数量均价调整、来源损坏、未定位零物资、仓库筛选、集团只读、成本隐藏、跨店 ID、主数据历史守卫、历史换仓审计、图表／CSV／组合报表一致和并发查询快照。

`tests/browser_warehouse_period.py` 使用全新隔离数据库和随机密码，通过真实 Chrome HTTP、Cookie 和 CSP，以库管／主管账号在 390 像素网页核对启用、实际收发及部分移库后的统计，验证未知期初／已知期末、成本权限、真实 CSV 下载、物资查找和保留筛选的中文日期拒绝。截图和无密码结果 JSON 存放临时目录，不进入仓库。

已验证的来源覆盖不能补齐启用前从未记载的库位历史。盘点观察本身也不改账；只有实际差异过账形成的 `StockMove` 和库位流水才进入相应日期统计。
