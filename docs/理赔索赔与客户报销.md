# 理赔索赔与客户报销

本模块对应 HK-035、HK-036、HK-039、HK-040、HK-041、HK-042 的有界内部协同闭环。新建 `claim/v2`，只关联本店可读的维修明细 v3／v4；旧维修不自动升级。外部单据由员工确认实际提交、实际结果和实际款项，无保险或厂家直连。上传原件只建立来源关系，不证明文件真实性。

## 办理责任与原始事实

| 动作 | 经办与入口 | 必要事实及权威来源 | 同事务结果／下一人 | 文件与异常出口 |
|---|---|---|---|---|
| 申请与核损核价 | 服务顾问，从原维修或理赔菜单进入 | 同店原维修、客户、当前报价版本、启用的保险公司／厂家／明确内部主体；逐项引用原报价行 | 不可变核价版本，数量及金额不得超过原行；交另一位主管复核 | 报价变更后旧核价不得继续提交，追加核价版本；未发生成本或现金 |
| 核价复核 | 另一位主管，管理员也不能自批 | 当前版本、实际依据 | 保留批准人和授权原件；外部交顾问提交，内部待承担绑定 | 无接手主管即拒绝；未实际生效可取消并保留历史 |
| 外部提交、补件、结果 | 服务顾问 | 实际受理单号、提交日、结果日、逐行核准金额和原件 | 结果为全额／部分／拒赔／补件；补件明确关联原要求，所有旧记录保留 | 未来日期、错版本、错原行、重复结果拒绝；无自动超时通过 |
| 原维修承担 | 主管在维修质检后冻结；顾问可事后绑定相同已冻结承担 | 获准核价与同一原保险／厂家／内部主体 | 原分配必须与核赔结果一致；原维修财务收款待办继续核对实际到账 | 核准不产生收款；拒赔部分需明确由客户或内部承担 |
| 已冻结第三方调减 | 顾问提方案、另一主管批准、财务退款并生效 | 真实外部结果、原承担、原第三方实收及待退余额、差额实际内部主体 | 逐笔原账户退款后，追加负第三方责任及等额正内部责任；原报价和原分配不改 | 未实际退款可取消释放占额；已有退款必须完成责任生效。不能以此增加客户债务或更换债务人 |
| 第三方直接报销客户 | 独立主管批准后由财务核对 | 原客户现金净实付，扣其他案件已报销及有效占额；实际第三方→客户凭据 | 追加客户报销事实，完全不生成公司 CashEntry／RepairPayment | 集团本金、赠金、券和套餐不能当作可折現现金报销；剩余未用批准额度可凭撤回依据结案 |
| 第三方经门店转付 | 独立主管批准、财务分笔到款和转付 | 原核准额、实际第三方到账；转付须选本单原到账及原账户 | 每次真实收付各一笔 CashEntry／PaymentLink；不重复增加原维修收入或已付金额 | 到账未转付可独立批准后原路退第三方，不能编造客户付款；待转付和待退资金不能互占 |
| 原报销返还 | 顾问选原实际款，另一主管批准，财务分笔实际办理 | 原直接报销／原经店付款／原未转付到账，扣已退与其他批准占额 | 直接路径只核对客户已退原第三方；经店路径客户退回原账户后再实际退原第三方；未转付直接退原到账第三方 | 批准前后都核限额；未有实际返还可取消。已实退不能撤销抹账；未退至第三方不释放客户已报销额度 |

## 资金、期间与权限

金额用整数分，数量用整数千分位。每个命令同时带理赔版本和原维修版本，并在同一事务触碰原维修，保证不同案件竞争相同客户实付款时最多一笔有效占额。相同请求编号和内容返回原结果；换内容或换员工不能复用编号。银行账户同样进行版本保护，实际流水号跨所有现金来源查重。

第三方批准金额与实际到账分开。已完工维修的原外部承担保持历史；责任调减按实际生效日追加减少外部经营收入，不静默重写原交车月。内部吸收不产生公司现金、不计外部维修收入。第三方经店报销属于代收转付，只进入实际现金及对应明细，不二次计维修收入。

原客户退款、误记更正与已批准理赔占额互相校验。有效报销尚未返还或待生效第三方调减时，不可绕过理赔回写原款；取消、撤回未用额度及原路径返还保留出口。未完成责任调减时阻止新蓝票申请，实际已开票结果和红票纠正仍需如实办理。

服务顾问、主管、财务、审计可按本店原业务权限查询。库管、技师、销售不获取本模块核价和财务文件。财务事实使用本理赔单新上传的收款类别原件；其他核价与审批使用授权类别。所有证据经过门店、类别、岗位和隔离扫描检查，旧维修文件或重复原件不能冒充本次实际结果。来源维修退款仅通过 `ClaimCash → ClaimResolution → 原 RepairAllocation／PaymentLink` 明确证明跨单凭据关系。

## 超时与恢复

任务默认当日本地日期到期，超期列入当前岗位待办；外部等待无自动批准、自动付款或自动改价。人员离岗使用现有任务明确交接，关联同步不会悄悄重派仍开放的任务。

迁移 `b228_claims → a127_recharge_bundle` 冻结 18 张不可变事实表。恢复校验重建原报价行、核价批准、外部结果、内外责任守恒、每笔原款路径、直接报销与公司现金区别，以及跨案件客户现金上限。数据库管理员仍具有技术写权限，此处不是密码学防篡改存储。

## 当前边界与验收

不做保险／厂家外部接口、真实电子签名认证、完整会计总账。当前固定一种保险公司和一种厂家承担，与维修 v3／v4 原分配一致；变更承担单位、提高第三方或客户责任、复杂多家共保及外部历史单导入尚不支持。仅原已承担外部金额调减、等额内部吸收；不能把外部拒赔自动追给客户。维修 v3 只冻结其已有客户与车牌；经过实际到店核验的 VIN 仍由 v4 接待原始事实提供。

专项覆盖申请、补件、拒赔、核准无现金、承担绑定及后到账、两个客户报销路径、部分原路返还、未转付退回、上限拒绝、取消、重复请求、旧版本、跨店和不同案件竞争。实际浏览器、恢复及统计验证结果以本批最终验收输出为准；本文件不把已写代码当作公司验收或正式启用。

本批专用自动用例 18 项通过；保险、厂家、内部均有实际独立用例，含错误厂家／内部主体拒绝。维修、售后、发票、业务财务、恢复及核赔统计组合回归 102 项通过，之后新增厂家拒赔用例单独通过。非空责任调整及原款退款快照通过总恢复校验，金额、原款路径篡改被拒绝。实际 HTTP Chrome 在 390px 使用服务顾问、主管、财务、技师、库管五个独立员工账号完成四条办理／拒绝链，零 JavaScript 错误；截图经本人和另一位开发者检查。生成凭据内容均为合成数据，`structure_only` 扫描仅用于该隔离验收，不冒充真实杀毒或生产环境验收。
