# 文件、单据和签回

## 当前数字化闭环

新订单建立时自动生成“车辆订购确认书”；配车后再次生成包含车辆信息的版本。详情可生成“车辆交付确认单”；维修可生成“维修项目确认单”；任何流程业务可生成“业务处理记录”。全部为DOCX，可下载、打印、由公司完善条款，签署后把扫描或照片上传原单。

这不是仅放一个上传按钮：系统保存模板版本、生成时字段快照、生成文件字节、摘要哈希、来源业务和操作者。签回件关联到具体生成版本。生成日期不是客户签署日期。签回动作核对本单/文件类型/公司启用模板/当前快照，不验证签名真假，不提供CA证书、电子印章或外部签约服务。

文档可重复生成，同样模板版本和快照会复用已有文件；模板或业务改变产生新文件。已生成文件、已上传原件不会被新版本覆盖。没有删除原件的员工按钮。

## 模板维护

管理员/店长在“基础数据→单据模板”修改标题和条款，修改会递增版本。默认是未启用的占位模板，正文明确显示样式草稿，不能作为已签正式模板通过流程。公司确认并启用后，只对新生成的版本生效。

支持替换已提供字段：`{{单据编号}}`、`{{门店}}`、`{{客户}}`、`{{联系电话}}`、`{{车型}}`、`{{车架号}}`、`{{车牌号}}`、`{{约定金额（元）}}`、`{{预计办理日期}}`、`{{办理内容}}`；订购确认书还提供 `{{选购服务}}`。不支持上传复杂Word模板自动解析、自由版式设计器、模板脚本或任意表达式执行。

模板条款的完整性、价格/税费约定、定金/订金区别、违约/退订条款、签约主体和公司盖章安排由公司正式审核。本版示例只展示数字化填表能力，不作适用于真实交易的法律文本保证。

## 上传和权限

支持PDF、JPEG、PNG、DOCX、UTF-8 TXT。默认单文件10MiB、单业务100个文件、每店1GiB附件空间；参数见 `.env.example`。不同文件用途由相应岗位选择，签回件关联本单生成版本；财务、合同类文件对非相关岗位限制下载。

校验文件大小、扩展名/内容特征、图片结构；拒绝程序/网页/压缩包、明显异常文档、宏、嵌入对象和DOCX外部链接。不自动打开、不OCR、不发模型。原件经鉴权后以附件下载，不挂公开静态目录。

**结构校验不是杀毒服务。** 0.4已增加独立隔离状态、ClamAV扫描适配和不可变扫描审计：默认`quarantine`不放行文件，扫描失败/风险/历史未扫描均不能下载或作为业务凭据；获权员工可在文件的“扫描记录”中重扫。生产必须配置`FILE_SCAN_MODE=clamav`，实际查毒服务仍需部署联调。`structure_only`只能明确用于本地合成试用，会在页面显示“未查毒”。员工上传或扫描通过不代表凭据内容真实，也不验证电子签名。详见《附件安全》。

## 存储与备份

当前附件以数据库二进制字段保存，适合有容量边界的小规模试用。`app.cli backup`包含全部业务和文件，避免只备份数据库却漏原件。没有自动压缩、大文件分片、对象存储或云端防篡改。

应用层不可覆盖并不意味着数据库管理员无法修改文件。若需要强审计和独立保全，需要外部不可变存储、访问管理和保留政策，不能把摘要哈希等同于第三方存证。
