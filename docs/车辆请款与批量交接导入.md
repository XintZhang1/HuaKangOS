# 车辆请款与批量交接导入

本模块覆盖 HK-019 车辆请款导入、HK-027 请款导入车辆发货、HK-028 请款导入车辆到货的受控 CSV 办理。原始需求只列功能名称，没有确认厂家格式；本版明确采用固定 UTF-8 CSV。每批只属于一家门店的一张已批准整车采购单，车型、数量与价格仍由原采购单确定。这里不创建另一套采购、库存或现金账。

## 员工办理

1. 从“整车采购办理”原单打开“车辆请款与交接清单”。主管选择请款导入；库管选择发运或到货导入。下载的示例全部虚构，必须对照真实资料改正。
2. 填写来源清单编号并选择原始 `.csv`。文件与批次一次保存，保留原字节、SHA-256、编制人、门店、原单版本、逐行数据和行号。文件结构不合规时整批拒绝；业务行错误则保留错误清单供核对，不生成请款或库存。
3. 经办人试执行。系统调用原采购动作，完整检查后回滚，包括临时生成的请款、发运、车辆身份、车辆保管与库位；试执行只留下核验进度及审计记录。
4. 另一名本店主管复核。编制人不能复核自己的批次，管理员也没有同人豁免。复核后由原编制人明确确认本人实际办理。
5. 一次事务执行全部行。任一行失败则全部回滚。请款仅建立原生请款；财务到原采购单另行登记分笔实际付款。发运仅登记供应方已实际发出的 VIN，在途车辆不算可售库存。到货由库管逐车核对 VIN、实际库位后按冻结成本入库。

上传文件仍适用现有私有存储、附件扫描与隔离规则。隔离中的 CSV 可以留档，但不能试执行、复核、确认或下载；文件检查通过后才能继续。文件结构校验不等于病毒扫描，更不代替员工核对原始业务事实。

## CSV 固定格式

文件上限 128 KiB（131072 字节）、200 个数据行，支持 UTF-8 BOM。表头及顺序必须一致，不自动猜列名或修正 VIN。数值不能带单位、千分号、小数或首尾空格；金额为整数分。VIN 是 17 位大写字母或数字，不含 I、O、Q。来源行编号为字母、数字、下划线或短横线，最多 80 位。

| 类别 | 表头 | 核对内容 |
| --- | --- | --- |
| 请款 | `source_row,line_id,vin,amount_cents` | 采购车型行属于本单；每 VIN 请款不超过冻结单车成本，台数不超过原有效数量；所有原生请款、付款和取消约束仍生效。 |
| 发运 | `source_row,manifest_row_id,vin,shipped_date,expected_date` | 关联已正式确认请款清单的行编号及同一 VIN；发运日期不早于原单且不晚于今天，预计到货不早于发运且在一年内。 |
| 到货 | `source_row,manifest_row_id,vin,received_date,location_id` | 同一请款清单 VIN 已通过导入正式发运、仍在途；到货日期为本次实际确认日且不早于原发运；库位是本店启用的整车仓或混合仓库位。 |

`manifest_row_id` 是页面“已确认请款车辆清单”的行编号，不是原采购车型行号，也不是发运编号。到货不能直接引用请款意向而跳过发运。库管取得的清单仅有必要的 VIN 和关联编号，没有请款金额、成本、付款或财务附件。

现有采购支持预付或先货后付，本模块保留这一语义。导入不添加未定义的付款前置条件，也不跳过原采购校验。实际到货仅支持当天确认，不批量回填历史到货。原采购单的后续付款、供应商退车及原款退款仍分别办理。

同一原采购单的同一 VIN 只执行一次导入请款，可按不超过单车成本的金额请款；后续资金安排或分笔付款使用原采购单，不重复导入该 VIN 创建资金事实。

## 取消、纠正、超时与竞争

批次状态为“逐行预检未通过、待试执行、待主管复核、待本人确认办理、已执行原单动作、已取消”。每一步检查批次版本；试执行、复核和正式确认还检查冻结的原采购单版本。期间原单被付款、取消、验收等动作改变时，不自动重试旧清单；取消未执行批次后按最新原单准备有明确替代关联的新批次。

来源行与本单同类别 VIN 均有防重复占用，历史已完成批次也参加检查。未执行批次取消时释放占用，但保留原文件和错误；再次使用相同来源行或 VIN 必须关联最近对应的已取消批次。已执行批次不能取消或覆盖。其请款余量取消、供应商退回、原款退款均追加原采购事实；需要新的采购来源时按新采购单办理，不把旧 VIN 历史删除。

内部待办期限为七天，逾期显示给主管，不自动推断实际动作，不发送外部消息。主管可将复核待办交接给另一名本店主管；实际经办人更换须取消未执行批次，由新经办人核对替代资料。同一原单内相同字节的供应方文件可以共用原附件，保留最初上传人；新批次另记本次编制人和本人的实际确认，不覆盖附件归属，也不把原上传人记作本次实物经办人。

VIN 仍由集团车辆保管事实协调。其他门店已有可售、销售、在途或待调拨占用时返回统一冲突，不披露对方客户、车辆位置或成本。重复请求只返回原批次；过期版本及相互竞争的操作不能重复生成原单结果。

## 技术与验收

`vehicle_imports_*` 保存冻结批次、不可覆盖的行、临时防重复占用、唯一原单结果及幂等回执。请款、发运、到货通过 `vehicle_procurement_service.command_in_transaction` 执行原守卫，外层一次提交。原单普通 API 保持同一事务和原有幂等接口。迁移 `c329_vehicle_imports` 依赖 `b228_claims`，静态定义五张新表。

恢复检查验证门店及原采购单、源文件摘要及编制人、冻结行摘要、独立主管、替代关系、占用键、逐行请款/发运/到货结果和日期库位。原采购恢复检查继续核对库存、保管代次、原成本和唯一现金事实。批次统计是导入进度，不能把请款金额作为现金支出或再计一次库存价值。

自动专项涵盖三阶段闭环、回滚、逐行错误、价格权限、源附件隔离、同人复核拒绝、重复和替代、串店、过期版本、并发确认、确认时第二行失败整批回滚、非空备份与故意篡改拒绝、全链冻结迁移。实际 Chrome 员工验收由 `tests/browser_vehicle_imports.py` 在独立合成库执行；实际结果记录由根验收文档统一更新。

本版不支持厂家 API、任意 Excel/厂家私有格式、多采购单混合批次、批量实际付款、历史到货回填，亦不推断未知未结旧单。系统确认仅表示员工对来源的核对与实际动作留痕，不验证厂家签章真伪。
