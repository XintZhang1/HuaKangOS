# huakangos 整车跨店调拨

2026-09-21，建设版。实现位置：`vehicle_transfer_models.py`、`vehicle_transfer_service.py`、`vehicle_transfer_api.py`、`vehicle_transfer_analytics.py`；迁移 `n814_vehicle_transfer`。这是实物调拨流程，尚不是整车采购、客户退车或内部划款模块。

## 身份与库存

车辆 VIN 对应统一身份。原有 `Vehicle` 继续作为具有固定门店归属的库存入库记录；同一 VIN 在接收门店重新入库时生成下一批次的记录，不修改原记录的 `store_id`，也不移动销售、检查、合同或附件。

`VehicleCustody` 按 VIN 唯一，记录当前库存及本次调拨占用。申请时锁定原库存版本并占用车辆，原销售配车接口与保留的旧销售接口都核验该占用。双方确认前不能发车；发出后原库存不可用，接收方未实际验收时也没有可用库存。实际验收生成新库存批次并关联同一共享身份。旧库存、原成本和原单仍保留。

迁移只给旧库存增加批次0，不推断旧销售/维修的未结流程。首次调拨由员工明确选择并核对本店可用库存后登记共享占用。旧创建路径的批次0仍受 VIN 唯一约束；后续批次只能由授权接收服务产生。

## 员工办理

入口：整车仓库 → 整车跨店调拨。每单一辆车，双方各有本店业务单、待办和凭据。

| 分支 | 经办与前置事实 | 原子影响与下一责任人 | 凭据、超时与撤销 |
|---|---|---|---|
| 申请 | 调出库管或主管；本店已确认可用车辆，无旧销售或新订单占用 | 锁定车辆、创建双方业务与主管待办 | 原申请原因及计划日期；尚未发出可由调出申请人/主管取消 |
| 本店批准/拒绝 | 双方各自主管；非本人申请，管理员例外 | 分别留存批准人，双方批准后建立调出库管待办 | 超期留在待办并可转交；一方拒绝结束申请、释放占用 |
| 发出 | 当前调出库管；双方批准、资料未变、未被销售占用 | 原库存不可配车，追加数量−1与原成本负值；车辆进入在途，交调入库管验收 | 本店实际交接文件和现场输入VIN，错VIN拒绝；发出后不允许取消账目 |
| 验收入库 | 当前调入库管；在途，核对VIN与本店启用的整车库位 | 新建本店库存批次，数量+1、完整原成本；生成双方等额内部往来，结束任务 | 本店验收凭据；不使用对方附件代为见证；重复或过期版本不会重复入库 |
| 拒收 | 当前调入库管；尚未验收入库 | 保存拒收事实，保留在途，不形成可用库存或店间应付 | 本店拒收文件和原因；转为退回发运待办 |
| 退回发运 | 当前调入库管；已有拒收事实 | 保留在途，建立原店退回验收待办 | 本店发运凭据和现场VIN，不能代替原店确认到货 |
| 原店退回验收 | 当前调出库管；已经实际退回发运 | 原店生成新入库批次，恢复原成本和可用库存，结束双方待办 | 原店验收文件、库位、现场VIN；不把旧记录改回新收货单 |

已分派的待办保持接手人；主管通过统一任务转交功能交班。超期不会自动发货、验收或冲销。运输遗失、损坏赔付尚无核销分支，必须保留未解决的在途记录，不能伪造收货清账。已接受后再次调回，要以接收店当前库存发起新的反向调拨。

所有动作同时校验调拨版本、本店业务版本、经办角色和任务责任人；请求编号与内容一起保存，业务、库存、两店任务、往来及幂等回执在一个事务提交。跨店协调只操作共同调拨所需的双方任务与往来，实物变动只在实际经办人的当前门店落账。

## 数量、价值与报表

成本使用整数分，整车数量使用整数台。发出价值完整进入在途；接受或原店实际退回后才减少。单车在途按调出门店统计一次，和可用库存分开。调拨接受按原成本形成调出方应收、调入方应付；集团包含双方时等额抵销，没有内部销售收入，也没有实际收付款。

数据可视化的 `vehicle_transit` 与 `vehicle_clearing` 图、明细和CSV来自同一集合。恢复校验检查每个状态所需的实物事实、库存归属、原成本、两方往来、VIN唯一当前库存与批次。
