# huakangos 集团会员与共享身份：本金基础闭环

本交付实现独立于旧门店会员余额的集团本金账本，以及客户、车辆 VIN、供应商／保险公司身份关联。它是建设计划阶段二和阶段五的部分基础能力，**不等于集团会员全部功能或公司业务验收完成**。

## 身份与访问边界

- 本店先建立客户、车辆或往来单位资料，再明确关联集团身份。客户电话只做精确查询提示；相同电话允许多个人，关联必须人工核对姓名及电话，系统不会自动合并。前台、销售只能关联和开通自己负责的客户。
- 未关联本店的客户搜索结果只显示遮盖姓名和候选编号，不返回电话、来源门店、订单、费用或附件。已有本店关联后可查看中央可用本金；历史流水仅返回当前门店的记录。未关联本店的会员 ID 不能读取或扣款。
- 车辆通过完整 17 位 VIN，供应商和保险公司通过人工确认的 18 位统一社会信用代码精确关联；本版关联车辆仍指向原本地库存档案，**尚未实现整车跨店在途、验收与库存调拨**。物资调拨是另一独立流程，不能据此认定整车调拨已完成。
- 集团中央模型通过显式集团业务服务授权访问；服务校验有效门店、员工门店岗位及客户关联。普通查询和业务写入仍受原单店范围约束。集团汇总模式不能办理会员动作，也不能列举集团客户历史。
- 身份关联不可通过修改关联行重新归属；误合并、解除关联、主档资料更正须后续建立有审计的专门流程。本版无自动客户合并接口。

## 本金动作契约

所有本金单位为整数分。请求携带固定请求编号和当前会员版本；涉及业务单、占额记录时还需相应版本。每个动作一次提交会员、业务版本、现金、占额、账本、内部往来、事件及幂等回执。冲突返回中文提示，刷新核对，保留原请求编号查询／确认已执行结果，禁止盲目换编号重试。

| 动作 | 经办岗位、进入条件 | 必要事实与权威来源 | 原子结果、后续办理及撤销 |
|---|---|---|---|
| 关联身份 | 获权员工；库管仅车辆／往来单位 | 当前门店原始主档、精确标识、人工确认 | 追加本店关联与事件；不复制历史业务；关联不可覆盖 |
| 开通会员 | 获权员工；必须已有本店客户关联 | 集团客户身份唯一；不收取开卡资金 | 新建余额为零的集团会员及事件；重复开户拒绝 |
| 到账充值 | 本店财务或管理员；尚未结束的本客户接待／订单／维修单 | 正额本金、本店有效账户、唯一流水号、该单上传的实际凭据 | 真实 CashEntry 收入一次；本金增加；中心／门店往来成对追加；不抵付来源业务费用、不完成其收款任务 |
| 额度占用 | 本店财务或管理员；客户承担的维修单，已质检进入待结算或赊账状态 | 本客户已关联集团会员、未结金额、可用本金、该单授权凭据 | 仅占额，不扣本金、不记现金；等待同店财务核销或明确释放 |
| 核销 | 本店财务或管理员；本店有效占额与当前业务版本 | 占额原额、当前未结金额、实际办理凭据 | 本金和占额同时减少，追加维修结算关联、中心／门店往来；全额结清关闭收款任务，赊账单按原引擎完成；不新增现金 |
| 释放占额 | 本店财务或管理员；尚未核销的占额 | 原占额、原因、业务与占额版本 | 释放可用额、追加事件；业务收款责任不变；已核销占额不可直接释放 |
| 原核销冲正 | 本店财务或管理员；原核销所在维修单仍待结算且客户尚未接车 | 原核销编号、未冲正原额、原因、凭据 | 追加反向本金、业务结算及内部往来记录；重新开启财务收款任务；支持部分冲正，累计不超过原扣款 |
| 本金退款申请 | 原收款门店财务、售后、客户服务或管理员 | 原充值记录、申请金额、客户申请凭据与原因；申请事实保存后不可覆盖 | 建立待复核申请和主管待办，不扣本金、不占额；申请人或主管可撤销 |
| 批准退款 | 当前门店主管或管理员；申请尚待复核 | 原充值未退且未获其他退款批准的金额、集团未占用本金 | 原子占用本金、保留审批人和时间；结束复核任务、生成财务退款待办；申请人与审批人必须不同，明确管理员例外 |
| 拒绝／撤销退款 | 主管可拒绝或撤销；申请人可撤销自己的申请；尚未实际退款 | 原申请版本与处理原因 | 已批准则只释放本申请占额，保留其他消费／退款占额；结束对应复核和退款任务，保留原审批与处理事件 |
| 本金退款执行 | 原收款门店已接手退款任务的财务或管理员；申请已批准 | 已批准申请及其版本、原收款账户、实际退款流水与凭据 | 金额与原充值从批准申请推导，调用方不能改额或换原单；本金与本申请占额同步扣减，现金一次，反向内部往来；结束退款任务 |

上述凭据仅证明经办人上传并确认了事实，不代表银行到账核验或电子签名验证。文件还须通过[附件扫描策略](附件安全.md)的独立使用检查；上传动作本身不能解除隔离，本地结构校验模式也不表示完成查毒。生成的系统文件不能代替实际办理凭据。所有实际现金只能出现在 `CashEntry`，旧入口不能修改／作废集团本金产生的现金记录。

占额**没有自动过期扣款或自动释放**；客户改变支付方式时由本店财务释放消费占额，退款申请撤销／拒绝则释放批准退款占额。现有维修取消、收款及接车关口识别集团消费占额；消费占额未处理时阻断接车，防止赊账放行后留下无出口的占额。退款占额针对原充值，本身不抵付来源维修单；来源业务完成或取消后，其独立的集团退款待办仍保留，由集团退款动作明确结束。未支持的流程版本拒绝执行集团资金动作。

退款复核与付款待办分别使用 `group_refund_review_{申请ID}` 和 `group_refund_pay_{申请ID}`，进入“我的待办”；默认计划日为今天，逾期沿用现有任务提醒。没有后台超时自动审批、付款或解冻。新建多份待复核申请不重复占额；批准时重新校验原单剩余和全集团可用本金，竞争批准只允许可覆盖的金额成功。退款申请以独立记录保存，当前仍关联原业务作为凭据载体，尚未创建专门的集团退款业务单类型。

## 对账与指标定义

- `balance_cents` 为集团未消费、未退款本金；`reserved_cents` 为有效消费占额加已批准未执行的退款占额；`available_cents = balance_cents - reserved_cents`。数据库约束保证三者非负且占额不超过本金。退款申请本身不占额，批准才占额。
- 每条本金变动对应一对内部往来：正数表示该方应收、负数表示该方应付。充值时中心应收代收门店，核销时履约门店应收中心；退款和冲正按原单反向。每对相加为零。这些记录**不是新增收入，也不是已完成银行结算**。
- 维修累计已收包含集团核销减冲正。报表与业务引擎读取相同的集团结算关联，避免会员核销后维修单仍显示全部欠款。预约／开单／占额本身不产生收入。
- 实际收支报表读取 CashEntry：A 店充值、B 店核销时只有 A 店真实收款；B 店核销不重复计现金。旧 `member_balance_cents`、旧“会员储值”表仍只表示原门店会员；不能将其误标为集团合并余额。新页面独立展示集团本金。
- `/api/group/reconciliation` 返回当前店全部本金分类合计、原始行及中心／门店往来净额；超过 25,000 行时明确拒绝，避免截断后冒充完整财务统计。会员详情默认最近 100 条本店流水和占额；本版不是完整分页财务明细系统。

## 接口及迁移

- 身份：`GET /api/group/identities?kind=customer&q=完整电话`；`POST /api/group/identities/link`。车辆查询使用 `kind=vehicle` 和 VIN；往来单位使用 `kind=counterparty` 和信用代码。
- 会员：`POST /api/group/members` 开通；`GET /api/group/members?customer_id=本地客户ID` 查询本客户的共享身份与会员；`GET /api/group/members/{id}` 返回本金与本店流水。
- 办理：`POST /api/group/members/{id}/actions/{topup|reserve|capture|release|reverse|refund_request|refund_approve|refund_reject|refund_cancel|refund}`。外层为 `request_id/version/values`，额外字段拒绝，金额必须为严格整数分，不能提交浮点数或把字符串静默转为整数。
- 退款执行 `refund` 必须提交 `refund_request_id/refund_request_version/case_version/account_id/reference/evidence_id`；直接提交 `original_id/amount_cents` 的旧调用被拒绝。原单和金额从已批准申请读取，不能仅凭财务身份绕过批准。
- 基础表由迁移 `e905_group` 建立；退款审批追加 `f006_group_refunds`，不改写 `e905_group`。迁移使用冻结字段定义，不引用当前 ORM metadata，不自动迁移旧会员余额，也不为旧试验阶段已发生的退款伪造审批记录。既有现金和原单退款上限继续有效；升级后的新退款必须走申请和批准。涉及不可丢失的账本，禁止删除表降级，应使用经验证的一致备份恢复。
