# 非维修实际进出厂与原维修交接

建设检查点 q79d，迁移 `q79d_gate_visits`。本页定义默认业务范围和可核验的来源，不是公司签收或生产启用证明。

## 员工办理

客户管理 → 非维修实际进出厂。先选本店已核验的客户车辆，登记咨询、非维修检查、精品办理、客户车辆交接或其他有据来访；安排本身不计实际进厂。服务顾问、接待、客服、主管及管理员可按本单权限办理，财务/审计只读。原单、文件、任务和跨店查询继续受原授权控制，集团页面只提供隐藏身份的同源统计。

| 当前阶段 | 本人最小动作 | 必须核对 | 原子影响与后续责任 |
|---|---|---|---|
| 待进厂安排 | 确认实际进厂，或取消未发生的安排 | 逐位 VIN、带时区的实际时间、可用的本单上传凭据、本人明确确认 | 新增不可变进厂事实；产生实际离场/转接任务。不增加库存、车辆所有权、现金或施工 |
| 已进厂 | 确认实际离场 | 同 VIN、实际时间、凭据及明确确认 | 新增原离场事实，结束本次到访；不以取消、收款或完工代替 |
| 已进厂且需要维修 | 服务顾问沿原进厂转接 | 再次核验 VIN、本次里程、工位、计划时段和诉求、转接凭据 | 同一接待原单建立维修接待别名，锁定原进厂时间/人员/凭据；继续原报价授权与维修，不重复到店 |
| 尚未转维修的有效原记录 | 申请时间纠正或撤销错误登记 | 原事实、纠正依据及本单凭据 | 冻结原事实摘要、独立主管任务。未批准时原数据继续有效，但本次新进出或转接暂停 |
| 待纠正复核 | 另一主管批准/不通过，或申请人撤回 | 原事实仍未变、本次独立复核凭据 | 管理员也不能自批。批准只改变当前有效投影，原始事实、申请和复核分别保留 |
| 已取消的原维修仍无实际离场 | 服务顾问/主管确认实际离场 | 原接待、冻结 VIN、实际时间和独立上传凭据 | 只追加取消后的实际离场事实；不恢复维修、不假装完工、不修改原现金/库存 |

普通预约、洗车、原单返修和非维修进出厂共用本店同 VIN 的并发锁。该锁不依赖客户关系 ID 或工位：同 VIN 多客户关系、跨入口同时点击不能制造两次重叠实际进厂。邻接区间可共用精确边界；无离场来源保持未知，不按业务状态猜测。

## 原事实、纠正与报表

`gate_facts` 保存原方向、时间、人员、凭据；`gate_corrections` 保存申请时的原事实摘要；`gate_reviews` 保存另一人的不可变处理。不能修改或删除这些原事实。申请期间保持唯一占用，批准时重新检查先后关系及同 VIN 的其他在厂区间。

恢复校验按**记录及批准的先后顺序**重放，而不是直接比较全部原始时间。例如：误记进厂 10:30，批准纠正为 10:00，后来记录实际离场 10:20，这是有效历史；原始 10:30 不覆盖。若当时并没有原进厂，或纠正试图凭空创建离场，则拒绝。

`gate_handoffs` 绑定原进厂与维修接待的唯一别名；别名不构成第二次实际进厂。转维修后原进厂冻结，不允许在非维修入口绕过原维修链改时或撤销。转接后尚未开单的真实离场沿原维修接待办理。已取消维修的实际离场由 `gate_repair_exits` 单列，取消本身仍不是离场。

`/api/visit-activity-reports` 与各表 CSV 继续使用相同行集合。新增 `gate_corrections` 表，按申请日期定位原纠正；实际进出仍按当前已批准投影的实际日期计算。跨月离场可关联前期进厂，本期到店批次只观察至期间末。当前查询会反映后来批准的原事实纠正，但不修改任何已经封存的财务月结来源。进出次数之差不是当前在厂人数/车辆数，经过时间不是员工工时。

集团汇总隐藏 VIN、沟通内容和原单办理地址；文件不会因报表可见而获得下载授权。当前源不足、篡改或关系损坏会提示不完整，不补造历史进出。

## 接口与开发位置

入口：`app/gate_visit_api.py`，命令：`gate_visit_service.py`，同 VIN 事实/并发：`gate_attendance.py`；模型：`gate_visit_models.py`，独立恢复：`gate_visit_integrity.py`，同源报表：`gate_visit_reporting.py`。前端：`web/gatevisits.js`。原维修接待与接车入口已接入公共锁，未删除旧版本规则。

- `GET/POST /api/gate-visits`，`GET /api/gate-visits/catalog`，`GET /api/gate-visits/{id}`。
- `POST /api/gate-visits/{id}/actions/{arrive|leave|cancel|handoff}`。
- `POST /api/gate-visits/{id}/corrections`，`POST /api/gate-visits/corrections/{id}/actions/{approve|reject|cancel}`。
- `POST /api/gate-visits/repair-orders/{case_id}/departure`。

命令均使用 `request_id`、当前 `version` 和严格 `values`；未知状态/现金/库存字段拒绝。`confirmed` 必须是布尔真，不能用字符串、数字或默认勾选代替。实际时间必须明确时区、不早于 2000 年且不晚于登记时刻；更早历史不通过日常入口补造。

## 升级与验证

新迁移只增加六张空表，不按旧工单创建进出厂、不修改旧迁移、不回填未知离场。已有库必须先备份数据库与私有附件，停写并在副本 `python -m app.cli migrate`。不可向已有库执行演示初始化。

`tests/test_gate_visits.py` 包含注册接口、原接待/维修接车、同 VIN 不同客户关系与不同入口并发、独立复核、跨期、原件篡改、同源 CSV、非空 p68c 升级、二进制凭据和全部原表指纹保持、旧请求重放及升级后继续办理。完整关联回归还应包括 `test_service_intake.py`、`test_visit_activity.py`、`test_questionnaire_versions.py`、`test_backup_integrity.py`。

按项目负责人的安排，真实浏览器与 PostgreSQL 在本机后验；本轮不执行。`tests/browser_gate_visits.py` 保留真实 HTTP/浏览器、多员工独立复核、390px 页面和 CSV 下载的可运行脚本；只编译该脚本不等于浏览器通过。运行前必须使用独立合成库，不传公司库或真实凭据。其它本机验收要求沿《验收与限制》执行。
