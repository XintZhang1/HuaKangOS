# huakangos 集团权益：赠送金额、积分、消费券与作业次数套餐

本交付为集团本金之外建立四种独立单位账，提供固定规则发行、跨店使用、核销撤销和未用券包原款退款。它是需求表会员、积分、消费券、套餐及相关统计的实际业务闭环，仍不代表所有促销、会员卡生命周期或公司业务验收完成。本金沿用《集团会员与共享身份》，不复制或修改旧门店会员余额。

## 冻结规则与范围

| 权益 | 账本单位 | 当前可办理 |
|---|---|---|
| 赠送金额 | 整数分 | 店长有据赠送、财务占额与核销、原核销撤销；每分抵一分，无现金退款 |
| 积分 | 整数积分 | 店长有据赠送或调减、按发行冻结的每分抵扣额消费、按目标规则兑换券包；无现金退款 |
| 消费券 | 整数张 | 固定额券购买或赠送、占额、跨店核销、原核销撤销、未用张数原款部分退款 |
| 作业次数套餐 | 整数次 | 单个作业编码的次数包购买或赠送、按已授权作业使用、原核销撤销、未用次数原款部分退款 |

规则由店长在本店发布；含其他适用门店的规则只能由集团管理员发布。每个版本冻结名称、种类、适用门店、有效天数、每单位抵扣额、购买价、内部结算价、优惠承担方、退款规则、兑换积分数及套餐作业编码。发布后不能覆盖，新发行只能选同发行门店和编码的最新版本；已发行批次继续执行原规则。有效期在发行时固定，不随新版本延长。

购买与赠送使用不同的明确规则：购买券包的单价必须为正，赠送及积分兑换目标规则的购买价必须为零。积分兑换按目标规则冻结的整份兑换率扣除积分并发行新批次；不产生现金，不默默舍弃零头。积分增加通过新赠送批次表达，调减只减少可用积分，保留理由和凭据。

套餐只适用于维修 v3 当前客户已授权、已完成质检并冻结承担的 `work` 作业行，单位须为 `job`、作业编码一致、金额为正。所有同作业编码的套餐版本和批次合并检查已核销及占额：份数不得超过已授权作业次数，抵扣不得超过对应作业金额；同时不得超过客户承担的未付金额。券、积分、赠金、本金和本地现金共享客户未付额度，不能抵保险、厂家或内部承担。

## 经办与责任交接

每次动作携带固定 `request_id`、集团会员版本，以及涉及的钱包、来源业务、占额或退款版本。在同一事务内写入版本、数量、凭据引用、现金、权益账、业务抵扣、配对往来、待办、事件及回执。数据库检查约束、会员与业务行锁、版本及唯一键共同阻断并发重复使用；过期版本返回中文冲突，员工刷新核对后再决定后续处理。

| 动作 | 岗位及入口条件 | 必要事实、结果、下一责任人及异常出口 |
|---|---|---|
| 发布规则 | 店长／管理员；本店；跨店仅管理员 | 核对售价、优惠承担、适用范围及退款规则；生成不可变新版本，无资金变化 |
| 购买 | 财务／管理员；本客户仍在办理的接待、订单或维修来源单 | 本店有效账户、唯一收款流水号、已通过扫描的本单凭据、整份数量；现金收入一次并发行权益，来源业务收款金额不因此减少 |
| 赠送／积分调减 | 店长／管理员；本客户仍在办理来源单 | 核对政策依据及凭据；新赠送批次或负向调减记录；没有现金事实，不改原发行记录 |
| 积分兑换 | 财务／管理员；本店可发行目标规则 | 可用未过期积分、整数份兑换率、来源凭据；积分扣除与新券包发行一次提交；不能原路现金退款 |
| 占额 | 财务／管理员；当前门店适用、未过期权益；已具备客户结算条件的维修单 | 本单凭据、客户剩余承担、批次可用单位、套餐对应作业；只占额，不记现金、不完成收款；创建本店经办财务的“核对并核销或释放集团权益”待办 |
| 核销 | 分派财务／管理员；原占额仍有效、原单版本一致 | 再次校验额度、有效期和实际凭据；扣减权益并追加业务抵扣及内部往来，完成核销待办，更新维修客户未收款；不自动交车 |
| 释放 | 分派财务／管理员；原占额未核销 | 释放原占额并记录理由；过期后仍可释放，不产生负现金或新权益 |
| 原核销撤销 | 本店财务／管理员；原客户尚未提车、原单仍在结算 | 指向原核销的部分整数单位及凭据；累计撤销不超原核销；恢复原批次，冲回抵扣和内部往来，重新打开应收任务；原有效期不延长 |
| 原款退款申请 | 原发行店财务、服务顾问、客服或管理员 | 仅现金购买批次、原来源单、本单退款依据、未用整数份；退款规则允许时创建店长复核待办，申请本身不扣权益 |
| 批准／退回 | 本店店长／管理员；禁止申请人自批，管理员例外 | 批准时原子占用未用份数，避免跨店消费；转本店财务付款待办。退回记录理由，无资金事实 |
| 撤销退款申请 | 原申请人或店长／管理员；尚未实际退款 | 释放该申请已批准占额，关闭自身待办，保留申请及审批历史；不会影响其他消费占额 |
| 实际退款 | 分派财务／管理员；原批准记录与版本 | 原购买账户、真实退款流水号及已通过扫描的原单凭据；金额由已批准份数×原购买价计算，前端不能改金额／份数；一次扣权益、记原款现金支出及配对往来，关闭待办 |

待办沿用系统约定到期提醒与可审计交接，不自动批准、不自动核销、不自动退款。到期权益不再允许新消费，已有占额由财务释放或在未过期时完成核销；退款审批后已锁定的原款可继续登记实际支付。退款复核／付款待办不因来源业务完成或取消而静默消失。系统记录外部银行的实际办理凭据，不实际操作银行。

## 现金、抵扣与统计口径

对每一单位，`C` 是客户抵扣额，`P` 是冻结购买价（赠送及兑换批次为零），`S` 是内部结算价。本版仅允许两种明确承担关系：集团承担时 `S=C`，履约门店承担时 `S=P`；并要求 `0≤P≤C`。

- A 店购买收款为 `P`，追加唯一 `CashEntry`，作为券包预收；不再通过本金或原业务收款路径重复记现金。
- B 店实际履约核销时抵客户应付 `C`，对外履约对价为 `P`，集团承担优惠为 `S−P`，履约门店承担优惠为 `C−S`。B 店与会员中心按 `S` 生成等额反向往来，没有第二笔现金。
- 原维修“对外结算金额”为原对外承担金额减去全部已核销权益的 `C−P`。履约对价已包含其中，不能再把权益报表的 `P` 加一次。集团汇总抵销内部配对往来。
- 原核销撤销追加上述值的反向记录；原款退款按未用份数的原 `P` 退回，不重新计算历史优惠，不退款已消费份数。

例如 A 店以 8 元售出一张抵 10 元的券，约定履约店承担优惠：A 店只有 8 元预收现金，B 店客户应付减少 10 元、对外履约对价为 8 元、门店优惠为 2 元、中心与 B 店往来为 ±8 元；集团不会显示 16 元收入。若约定集团承担，往来改为 ±10 元，集团承担 2 元，对外履约对价仍为 8 元。

报表 `benefit_bonus/points/coupon/package` 分别按分、积分、张、次显示发生期单位变动；不同单位不相加。`benefit_redemptions` 按核销／撤销发生日显示抵扣、对价及两类优惠；`benefit_clearing` 显示当前内部往来，不伪称历史余额。表格、图表、CSV 取相同数据集合；本金报表仍独立。

## 接口、隔离与恢复

入口为业务单的集团会员页面→集团权益。`GET /api/group/benefits/members?customer_id=…` 验证本店客户与集团身份关联，提供可用权益；只显示当前门店最近 100 条流水、占额和退款，隐藏外店原业务及账户。集团汇总视图不能办理。文件引用必须属于当前原单、当前门店，并通过附件安全策略；隔离文件不可用于任何权益动作。

规则接口为 `GET/POST /api/group/benefits/rules`。动作接口为 `POST /api/group/benefits/members/{member_id}/actions/{action}`，动作名与严格字段定义见 `app/group_benefits_api.py`。所有请求之外来字段拒绝，整数单位拒绝浮点、字符串和布尔值。没有钱包余额或状态任意修改接口。

`app/benefit_backup_integrity.py::validate_benefits_sqlite(connection)` 只读核对每个批次余额等于单位账总和、消费与批准退款占额、原单关系、现金金额方向账户、业务抵扣、积分兑换及内部往来配对。备份恢复仍须核对附件 SHA、扫描状态和其他业务账，不能以能登录代替恢复验收。

## 本次验证与明确限制

2026-09-21，`tests/test_group_benefits.py` 的 21 项测试覆盖独立单位、跨店现金一次、冻结版本、原款部分退款审批与撤销、过期权益、岗位拒绝、跨店来源／文件拒绝、幂等与过期版本、并发争用、同一客户本金＋权益额度、真实维修 v3 对应套餐数量与金额限制、备份恢复守恒，以及对价／优惠／往来和 CSV 一致性。真实 PostgreSQL 17.11 的 `n814_vehicle_transfer` 空库迁移和转入／备份恢复样本包含非空四种权益账、核销与批准退款占额，详见《PostgreSQL验证》。

`tests/browser_benefits.py` 使用真实 Chromium HTTP、390 像素手机页面和独立财务／店长账号，通过 5 个场景：冻结券规则、A 店实际购券、B 店超额中文拒绝并正常占额核销、原店退款申请与独立审批、原账户实际部分退款；无 JavaScript 错误。截图已逐页检查，保存在仓库外临时证据目录。本测试是合成数据本地 HTTP，生产 HTTPS、实际手机拍照及公司周期验收仍需按上线关卡执行。

尚未实现自动按消费赚取积分、积分到期批量处置、券转赠给另一会员、组合商品包、不同项目混用的自由套餐、满减／折扣叠加等促销数学、实物会员卡补换续会、等级自动升降与权益联动、提车后的权益核销撤销。套餐当前是单作业编码次数包；不把这个交付称为所有套餐需求完成。未用券包退款已经有独立审批和待办，但来源仍绑定实际业务单，尚无独立券包销售业务类型。公司应在正式启用前确认实际规则与凭据口径。
