# HK-038 原责任返修与新增自费项目

本专项采用显式 `rework_extension.definition_version=1`；没有该记录的原 v4 返修继续全额内部承担、不得收客户现金。2026-09-23 已完成以下实现与限定范围验收；这不是整树回归或生产可用声明。

## 已核实的原边界

- `service_intake_service._source/rework_create` 要求原维修已实际交车、冻结结算、同客户身份和 VIN、选定最终报价原行；原 v3 须另有主管核验车辆事实。
- `before_repair_command` 原返修只能全内部承担；`service_intake_backup_integrity.validate` 同时拒绝跨店来源及返修现金。这是旧契约而非应删掉的保护。
- 服务历史授权只给服务摘要；dossier 授权只给明确范围的只读快照。均不授权返修办理，不借它们开放原财务或附件。

## 最小办理链

1. 原店服务人员选择已交车维修、同身份/VIN 的接收店车辆、具体原责任项目、指定接收员工及到期时间，提出本次责任额度；原店另一名主管根据原店凭据独立批准。管理员也不能自批。批准冻结最小来源和责任主体，不移动库存或资金。
2. 指定接收店员工在期限内领用一次授权。服务端校验门店/岗位/账号访问版本、原事实和接收车辆，建立本店返修申请，并用原 `ReworkRequest.active_source_id` 唯一约束与新旧返修共同争用原单。授权未领用不占原单；领用后不能二次使用。
3. 接收店另一名主管确认承接；现场核对 VIN 和实际到店后，创建一张原生 v4 明细工单及不可变扩展契约。普通工单不能追加标签变成返修。
4. 报价每行明确为“原责任”或“新增自费”。原责任行必须引用获批原行，客户额仅来自新增自费行；行分类、原行链接及金额进入当前报价摘要。系统按行计算双方金额，不接受员工自行分摊汇总。每版仍须价格审批、当前客户授权、真实开工/领退料/质检。已授权行不得改换责任类别；停工版本继承类别并按原报价规则确定保留费用。
5. 结算仅允许“获批原店内部责任主体”及“本次客户新增项目”两类，金额严格等于当前冻结行合计。新增客户实际到账沿用本单 `RepairPayment -> PaymentLink -> CashEntry`；原现金、应收、领料绝不复制。内部责任既不形成对外收入，也不自动制造原店付款/接收店到账。店间关系准入与实际清算不在本专项。
6. 未开工取消、申请拒绝/取消释放原单占额；已开工走真实停工和原领料退回，不能取消抹账。取消工单不代表车辆实际离场，沿用原出厂核对。已消费的授权保留历史，重办需重新授权。

## 权限、过期、撤销

原店批准前核对源版本与凭据可用性；领用再核对授权、人员及源范围。未消费授权可拒绝/撤销，过期禁止领用；消费后不能以撤销授权抹除已承接责任。后续办理使用已冻结的本次来源，不继续授予原档案读取权。B 店只见原单号、VIN、选定项目、责任主体和额度，不见 A 店原金额、成本、付款、联系方式、附件 ID 或下载地址。未获授权、错误 VIN/身份、第三店、非指定员工、普通工单均失败关闭。

已合法消费后，本地工单的冻结分类、实际施工和收付款属于 B 店自己的事实。原店员工访问版本变化、原指定接收人离岗不抹除这些事实，也不重新开放 A 店来源：未开工由 B 店现任主管安全取消；已开工必须保留施工，沿原任务显式交接给本店当前合法岗位，继续质检、结算及交车。新接手人无权查询中央原授权或原店附件。已授权报价即使尚未开工，也不能更换行号绕过原责任分类冻结；停工按真实原领料退回及本版保留费用处理。

## 文件归属与公共钩子

本专项拥有 `rework_extension_*`、`service_intake_*`、`repair_service` 的必要报价/投影钩子、`web/reworkextensions.js`、必要 `web/repair.js/serviceintake.js` 钩子、专项测试及本文件。新迁移 `z68m_rework_extensions` 下接已落盘的 `y57l_vehicle_income`，只建新表；旧迁移不改。

新表：中央原责任授权、不可变授权决定、本店幂等回执、请求扩展契约、报价分区、报价行责任。公共接线由主代理完成：模型/路由注册，网页加载与路由，备份校验，新报表和新月结版本来源。旧月结定义不静默扩大。

公共接口：`GET/POST /api/rework-extensions/grants`、`GET /grants/{id}`、`POST /grants/{id}/actions/{approve|reject|cancel|revoke}`、`POST /requests`、`POST /orders/{id}/quote`。承接后继续原接待及维修动作；旧报价接口不添加可选字段，避免改变旧幂等摘要。
